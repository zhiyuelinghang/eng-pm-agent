# 记忆配置页产品化精简方案

日期：2026-09-10。状态：代码、实际配置迁移及服务重启已完成，前后端回归、生产构建和真实管理接口验证通过。浏览器控制服务连接失败，尚未完成截图及键盘目视验收。本文保留改造前的问题作为决策依据。

## 1. 依据与范围

本轮实施对象是智能体管理中心的 `/memory-settings`、对应六字段接口及内部运行策略。依据改造前的页面源码、接口契约、实际保存的全局配置以及记忆、学习、群聊、压缩执行链路。

前期浏览器工具返回 `nodeRepl.fetch request failed`，未取得有效页面截图。前端实施阶段只完成本地代码测试与构建，未操作浏览器；本文件不宣称已经完成视觉、键盘或窄屏实测，实际浏览器验收仍需补齐。

改造前页面有 **37 项配置**：11 个开关、20 个数字输入、2 个模型选择器、1 个压缩方式下拉框、3 个提示词文本框；后台保存 **60 个字段**。现在页面只有 **4 个开关、2 个模型选择器**。逐项历史盘点见 [控件盘点](../../artifacts/memory-settings-ui-inventory.md)，该盘点中的建议以本方案最终六项决策为准。

改造前读取的配置：后台学习及业务交互、正式业务事件、群聊三个来源均开启；学习模型是 DeepSeek V4 Flash，对话压缩模型是 DeepSeek V4 Pro。实际一次性转换已准确保留这些模型和来源选择；配置版本由 3 升至 4。

改造前接口审查确认：更新会全量替换 60 个字段，空设置可通过校验，未知字段被忽略，版本号可省略，存储缺少按版本的条件更新；两个同时保存的请求可能互相覆盖。“恢复默认”会重新打开全部来源并清空两个模型。现已移除重置入口，更新契约要求完整六字段和版本号，保存采用版本比较。历史问题见 [契约审查](../../artifacts/memory-settings-contract-review.md)。

本轮不重新设计记忆归属或智能体分工。用户、用户＋项目、项目三个范围，以及入口、调用链、知识来源、群聊受众、本次不记忆／不学习的限制继续生效。

## 2. 页面最终只保留六项选择

| 页面区域 | 用户可以配置 | 保留理由 |
| --- | --- | --- |
| 后台学习 | 启用后台学习 | 决定是否允许后台产生新学习成果 |
| 后台学习 | 后台学习模型 | 决定提炼能力、费用与所用模型服务 |
| 学习来源 | 业务交互 | 决定用户纠正及实际执行过程是否参与学习 |
| 学习来源 | 已确认业务事件 | 决定初始化确认、任务发布、验收等正式来源是否参与学习 |
| 学习来源 | 群聊消息 | 决定群聊消息是否参与后台学习；可见范围仍由权限决定 |
| 长对话处理 | 对话摘要模型 | 决定长对话整理使用哪个模型，和后台学习独立 |

普通页面从 37 项减至 **6 项**，移除 31 项调参控件。不增加新的“高级配置”折叠区，不将这些控件转移到智能体编辑窗口。

保留两个模型选择器，是因为它们对应不同职责，也会影响模型服务与费用。当前“模型与连接”主要管理可选模型和凭证，本轮不为迁出一个选择器再扩展另一个配置页面。对话摘要模型保留为当前页第二个短区域；空值明确表示“使用当前对话模型”，不是学习模型的备用配置。

已实施的公共接口只包含：

| 字段 | 处理 |
| --- | --- |
| `learning_enabled` | 保留 |
| `learning_model_config` | 保留；不自动改用总控模型 |
| `learning_interactions_enabled` | 保留 |
| `learning_business_events_enabled` | 保留 |
| `group_learning_enabled` | 保留 |
| `compression_model_config` | 由当前 `memory_model_config` 明确更名；一次性转换已有数据，不接受旧名别名 |

新请求严格拒绝未知字段，版本号必填，不能将空对象解析为一套全开的默认配置。学习模型和摘要模型分别验证自己的用途，不再借旧 Mem0／GraphRAG 适配验证；摘要空值只表示明确跟随当前对话模型，不能再静默进入未说明的环境模型回退。

## 3. 被移除的控件由谁接管

| 当前配置族 | 目标归属与行为 |
| --- | --- |
| 常用个人资料加载 | 记忆运行规则：按真实用户、入口、受众和本次要求自动加载。原开关只停止自动注入，不能作为禁止访问个人信息的承诺 |
| 语义检索 | 检索服务：可用时辅助文本检索，未就绪、忙或超时时自动回退。就绪状态可观察，用户无须选择检索算法 |
| 后台索引开关 | 索引服务：持续处理新增与更新，失败自动重试，重启继续；运行诊断显示异常和积压，不搬过去再放一个常驻开关 |
| 查询返回条数、每轮经验数量 | 检索与上下文策略：先做来源过滤，再按相关性、去重结果及上下文容量截取。保留内部防护上限，不代表用户的总记忆容量受该数字限制 |
| 纠正、失败修复、重复模式、周期合并 | 学习服务：在总开关和来源允许时按统一规则处理，保留证据和正确性检查，不需要逐种勾选 |
| 冷却、触发次数、扫描间隔、空闲、最长等待、批次大小 | 任务调度：根据真实材料就绪、去重和积压安排；保证低流量群不会永远等待，高流量不会阻塞业务交互 |
| 超时、输入字符数、复核周期 | 服务内部策略：结合模型容量、来源有效期和运行保护统一维护，来源撤权仍即时处理 |
| 学习任务／群聊批次数量上限 | 内部资源控制：暂时移出日常配置，不包装成金额或 API 次数预算；诊断能够解释等待、限流和重试原因 |
| 压缩比例、保留消息、间隔、次数、质量阈值、压缩方式 | 对话引擎：根据实际模型上下文容量自动整理，保留未完成工具交互和当前任务约束，避免反复压缩；不增加用户任务轮数限制 |
| 压缩提示词 | 随代码版本维护的系统模板，走评审和回归，不作为普通管理员文本框 |
| 其余未显示的旧全局字段 | 逐一确认当前读取点：仍需要的计算参数归入内部运行策略，废弃链路字段删除，不因为旧表单曾保存就继续对外接受 |

“系统自动管理”不能只靠把现有值改成默认值。需要明确运行策略、失败回退、状态反馈与回归测试；无法根据模型容量可靠计算的部分，采用经过验证的内部默认值，不声称已实现自适应。

语义检索需要覆盖服务刚重启、已有有效索引但没有新索引任务的场景。当前模型初始化依赖索引任务，实施时应核对就绪恢复机制，避免长期只走文本回退却显示语义能力正常。

## 4. 暂不增加“费用预算”配置

当前两个每日数字不是费用预算：

- `learning_daily_job_limit` 统计租户、入口智能体、来源类型下当天新建的学习任务。普通交互按入口智能体分别计算；正式业务事件使用另一组计数。
- `group_learning_daily_limit` 统计租户全部群当天新建的批次，独立于上项。
- 前日积压、失败重试会产生模型调用，部分批次又完全不调用模型；管理员重试也不等同于自动新建任务。

所以本次页面不新增“每日花费”“每日模型调用次数”或含糊的“省钱／标准／高效”档位。内部继续保留资源保护，并让诊断说明真实限制。以后若确需金额预算，先实现覆盖重试、积压及各来源的调用计量、额度预留和实际用量结算，再提供用户控制。

## 5. 页面结构与文案

沿用现有管理端颜色、字体、间距和表单组件。页面标题为“记忆与学习”，导航仍沿用现有“记忆配置”入口；页头只说明后台学习来源、模型与系统自动管理的职责。

### 区域一：后台学习

按顺序展示总开关、后台学习模型、三个学习来源。每个来源独占一行，左边标题及专属说明，右边开关位置固定。取消每个技术参数各占一个边框方格的排列方式。

| 项目 | 说明职责 |
| --- | --- |
| 启用后台学习 | 从允许的来源整理可复用经验。暂停后仍可保存明确记忆、读取已有记忆 |
| 后台学习模型 | 用于提炼长期记忆与经验，与业务智能体和对话摘要模型独立 |
| 业务交互 | 从用户纠正和有证据的执行过程中学习，遵守本次不记忆／不学习要求 |
| 已确认业务事件 | 从正式确认、发布、验收等记录中学习；未确认草稿不作为正式事实 |
| 群聊消息 | 在后台处理消息，不向群内发送学习通知，成果按原消息可见范围使用 |

暂停时仍可编辑模型和来源，便于提前配置；保持显示“后台学习已暂停，保存这些设置不会自动恢复学习”。不因暂停而清空来源选择或模型。

后台学习开启但未选择可用模型时，字段下显示原因并阻止提交无效的启用状态。暂停状态允许模型为空，仍可保存来源偏好。开启时至少选择一个来源，否则提示选择来源或暂停学习。

### 区域二：长对话处理

只保留“对话压缩模型”。说明长对话时自动整理上下文以继续当前任务，留空时使用当前对话模型。关闭后台学习不关闭对话压缩。

两个区域始终展开，无额外标签页、折叠区、技术提示词或长篇原理卡片。正文与控件沿用 14px，辅助说明不小于 12px。窄屏自然纵排，标题和说明不挤走右侧控件，键盘焦点顺序与视觉顺序一致。

### 页头与操作栏

区域内显示当前学习选择与暂停说明，字段校验区显示模型未配置或不可用的原因。配置已启用不等同于“后台运行正常”；本次没有增加缺少真实运行信号的健康状态。

页底固定操作栏，主按钮“保存更改”，次按钮“放弃更改”，左侧显示未保存状态。去掉当前会立即重设全量配置的“恢复默认”。放弃只恢复上次成功读取或保存的值，不发后台写请求。

## 6. 保存及异常流程

| 场景 | 目标行为 |
| --- | --- |
| 读取配置 | 显示与最终两区域结构匹配的骨架；读取失败保留导航并给出重试 |
| 编辑 | 在本地形成草稿，明确有未保存更改，不出现开关已生效的假象 |
| 保存中 | 暂时锁定整个表单和重复提交，防止响应覆盖保存期间的新编辑 |
| 保存成功 | 更新服务器版本及本地基线，清除未保存状态 |
| 字段校验失败 | 在对应模型或来源处说明问题，聚焦第一项错误，保留草稿 |
| 网络或服务错误 | 保留草稿，持续显示失败原因和重试入口，不只闪一下 toast |
| 并发修改 | `expected_revision` 必填，存储在同一事务内按版本比较、写入和递增；冲突时显示当前版本与草稿差异，用户处理后再提交，不静默覆盖 |
| 页面内离开或添加模型凭证 | 有更改时提供继续编辑、放弃并离开、保存并离开；保存失败保持当前页 |
| 关闭或刷新标签 | 有更改时触发浏览器原生未保存提醒 |

“保存并离开”只在本地表单有效时执行。新增凭证等跨页操作不能绕开未保存保护，也不在入口层另加多重确认。

## 7. 暂停与恢复需要统一语义

改造前普通学习、业务学习和群聊学习均在模型前后做授权检查，但已发出的模型请求不能撤回，末次授权到成果提交之间存在竞争窗口；普通任务和群聊任务的停用处理也不一致。当前实现增加成果事务中的配置锁定与开关核对，并用可恢复的暂停状态保留材料，完整运行回归仍由主任务汇总。

实施语义及验收要求：

1. 暂停总开关后不启动新的学习任务；关闭单一来源只约束该来源。
2. 已发出的模型请求可以收尾，但成果提交事务必须原子核对当前策略版本和来源开关，停用期间不发布新成果。
3. 暂停作为可恢复状态处理，保留待处理材料及进度；不把管理员暂停伪装成来源失效或普通处理失败。
4. 恢复后按当前权限、来源版本和模型重新检查，再继续处理，不能直接提交暂停前未经重新验证的结果。
5. 现有有效记忆、明确事实的保存和读取、来源撤权检查、对话压缩继续独立运行。

优先复用现有配置版本机制，实现设置更新和学习成果提交的一致性约束，不再建立第二套人工策略来源。模型服务已经接收到的请求无法通过页面开关追回，这一点在运行状态中准确表达。

## 8. 运行诊断的边界

检索就绪、索引积压、学习暂停、模型不可用、等待材料、资源限制、失败重试及最后成功时间归入现有“记忆管理 → 运行诊断／学习记录”。配置页不重复任务列表、内部错误码、向量维数和模型实现信息。

按实际状态给出动作：查看失败任务、重试失败项、前往修复模型配置。只有确有运维必要时才设计针对具体任务的临时控制，不能把删除的 31 个配置在诊断页重新堆一遍。

状态不应只用颜色表示；同时提供文字。索引未就绪与明确记忆保存失败分别表达，避免用户误以为索引等待意味着内容丢失。

## 9. 实施步骤与交付边界

1. **冻结公开契约**：确定上述六项；让前后端请求和响应都不再携带内部调参字段，拒绝已删除字段。移除全量默认重置入口，版本号改为必填。
2. **建立内部运行策略**：逐个改造读取点，保持查询、索引、学习和压缩的有效保护；模板、调度与容量计算随代码维护。对当前活动链已覆盖的旧融合召回、Mem0、Historian、Dreamer 参数，在解除依赖后删除，不继续作为高级设置。
3. **统一保存、暂停和状态**：设置更新必须在存储层进行原子版本比较，不能仅在路由提前读版本；记忆设置更新不能覆盖并发修改的主智能体绑定等其他平台设置。补齐学习成果提交的策略原子校验、可恢复暂停及真实状态；摘要模型等无关修改不能被当成停止学习。
4. **显式转换开发数据**：预览当前所有全局配置，保留学习开关、来源和两个有效模型，仅清理退役设置并明确更名。保留记忆、来源证据、运行快照和历史审计。不写旧字段别名、自动吞字段或多版本回退分支。
5. **重构页面**：落实两区域、六项配置、固定操作栏及异常交互，同步更新操作文档。
6. **联调验收**：必要回归、实际 API 和浏览器验证后交付。

## 10. 验收标准

- 页面只有六项可编辑配置；没有技术数字输入、压缩提示词、折叠区或逐智能体记忆选项。
- 当前 DeepSeek V4 Flash 学习模型、DeepSeek V4 Pro 摘要模型及三个来源选择被准确保留。
- 保存、放弃、失败重试、并发冲突、带更改离开以及模型凭证跳转均不会静默丢失草稿。
- 两个客户端携带同一版本同时保存时恰好一个成功、另一个返回冲突；缺版本的请求失败，并发更新其他平台设置不会被覆盖。
- 学习关闭、模型缺失、凭证失效、来源全关等状态都有确定行为；总开关与模型状态不互相冒充。
- 读取、显式保存、删除、索引回退、服务重启后的索引恢复均正常。
- 总控、直接业务智能体、多级协同、知识查询、初始化、任务草稿及群聊继续遵守原来的范围和来源限制。
- 本次不记忆／不学习在多级调用、重试和派生业务中继续生效。
- 暂停发生在模型执行中或提交边界时，不产生越过新策略的成果；恢复可继续有效材料。
- 调整摘要模型不改变学习模型；暂停学习不停止长对话压缩。
- 新接口和保存数据都不再包含退役字段；旧请求被明确拒绝，转换可审计且不改已有记忆。
- 桌面和窄屏完成真实截图及键盘操作验收；浏览器工具未恢复前不宣称视觉验证通过。
