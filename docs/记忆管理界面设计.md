# 记忆管理界面优化

本轮先确定信息结构，再在现有 React / Tailwind 页面中实现并验证交互。不改变三个抽屉及后台权限。

## 页面结构

- 记忆库：默认展示有效记录，三个抽屉用紧凑导航切换；按用户、项目和类型筛选，搜索正文。结果为摘要列表，点击后在右侧查看完整正文。
- 待确认：复用相同的抽屉与列表，把状态固定为候选，提供证据与审核入口。审核后从当前列表移除。
- 学习记录：群聊持续学习和对话／经验整理作为二级切换，一次只展示一种记录；保留暂停、恢复、重试、取消、查看成果及证据。
- 运行诊断：索引任务、失败重试和遗留归属处理，仅进入此页时加载。

## 浏览与详情

列表显示内容标题／摘要、普通记忆或经验类型、归属、使用状态和更新时间。技术字段名、版本、消息 ID、索引状态不占用主列表。

右侧详情以完整正文为主，明确说明谁能使用。来源、条件与限制按需展示；历史版本独立切换。正文可在面板内编辑。学习成果的审核、反馈和回滚保留现有验证规则。跨抽屉移动继续使用原有授权及确认流程，群聊来源的归属限制保留。

窄屏以详情替换列表并提供返回入口；宽屏并排浏览。正文 14px、辅助信息最低 12px；保留可见焦点、加载骨架、空状态和局部错误提示。

## 数据与功能保留

切换记忆筛选时只请求记忆列表。后台任务不随列表筛选重复请求；仅当前学习分区挂载和轮询。选中记录采用稳定 ID，刷新后更新详情；过滤条件、分页变化时避免显示已失配的旧记录。

保留三个抽屉、姓名／项目筛选、状态与类型筛选、正文编辑、候选确认、审核拒绝、反馈、历史与回滚、导出、合并经验、生成技能、索引重试、遗留归属分配以及所有学习任务操作。

## 验证路径

1. 找到某用户的记忆，连续切换记录、查看详情、修改正文并确认刷新后的版本。
2. 找到项目经验，查看条件与来源，并进入审核／反馈流程。
3. 在待确认中处理候选，确认结果离开候选列表。
4. 从学习记录跳转到对应抽屉；检查诊断信息与日常列表隔离。
5. 检查窄屏返回、空结果、错误提示及不小于 12px 的字体。

## 本轮验证结果（2026-09-08）

- 前端 TypeScript 检查及生产构建通过。
- 在本地独立测试 schema 中完成三个抽屉切换、正文修改、历史版本核对、删除及已删除记录查询。
- 候选经验审核通过后，在有效记忆库显示“正在使用”；群聊产出可跳转到对应的项目抽屉。
- 检查学习任务、运行诊断、搜索空结果和清除筛选；记忆页面未发现运行错误。构建及初始应用加载仍有既有的 mime-types/path 浏览器兼容警告与大包体提示。
- 390 × 844 窄屏检查：四个功能入口及三个抽屉完整显示，详情有返回列表入口，页面无横向溢出。正文 14px、辅助文字不低于 12px。
- 本轮未调用真实学习模型、未重启正式服务；真实记忆未参与界面测试。复杂反馈、回滚、导出及后台重试沿用既有实现，本轮未逐项重复执行。

临时测试服务已正常退出，并通过生命周期清理独立测试 schema。
