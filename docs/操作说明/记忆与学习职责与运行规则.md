# 记忆与学习职责与运行规则

本文是长期记忆、后台学习和记忆管理界面的现行规则。智能体调用关系见[智能体分工与协作规则](智能体分工与协作规则.md)，模型参数与图片能力见[统一模型与原生图片输入](统一模型与原生图片输入.md)。

## 职责与配置

| 组件 | 职责 |
| --- | --- |
| 主智能体、业务智能体 | 完成业务，按本次授权读取记忆、提交明确记忆变更或学习材料 |
| 后端记忆服务 | 验证身份、来源、调用链、范围和版本，事务保存正文与索引任务；明确保存与删除不调用额外分类模型 |
| 后台学习服务 | 使用独立配置的学习模型，从有效证据中提炼并校验成果；允许没有值得保留的结果 |
| 对话压缩 | 整理长对话的当前上下文；使用独立压缩模型，未指定时使用当前对话模型 |
| 索引服务 | 建立可重建的向量索引；未就绪或超时时使用文字检索，不影响正文保存 |

全局「记忆配置」只保留六项：启用后台学习、后台学习模型、业务交互来源、已确认业务事件来源、群聊消息来源、对话压缩模型。启用学习必须选择可用模型和至少一个来源；暂停时可以保留模型与来源偏好，也可以清空学习模型。学习模型不隐式跟随总控或压缩模型。

保存配置必须携带当前版本；发生并发冲突时保留草稿，处理差异后再保存。「放弃更改」恢复上次读取或保存的值，不写入后台；没有「恢复默认」操作。索引、检索、常用资料加载、调度与压缩策略由代码维护，内部数量限制不代表总记忆容量或金额预算。

主智能体和业务智能体均没有逐个配置记忆读写、学习参与或经验使用的入口。规则由后端按固定职责、真实业务入口、来源、受众及调用链计算；公开／内部只控制平台可见性。

## 三个记忆范围

| 范围 | 内容与归属 |
| --- | --- |
| 用户 | 本人跨项目的称呼、表达偏好等个人信息 |
| 用户＋项目 | 本人在当前项目中的私人信息和有权使用的经验 |
| 项目 | 当前项目获授权成员可用的共享事实和经验 |

记忆归属于用户或项目，不按智能体复制。姓名、称呼偏好与账号显示名分别处理；称呼不证明实名、岗位或权限。同一偏好优先使用当前项目设置，否则使用跨项目用户设置。实时业务状态以业务数据库为准，资料内容以当前获授权的原资料为准。

下表是系统能力上限，实际权限还须与真实用户、项目、来源和全部输出受众取交集。

| 运行场景 | 可读范围 | 可提交写入范围 |
| --- | --- | --- |
| 首页总控、直接进入业务智能体 | 三个范围 | 三个范围；项目写入仍需当前业务权限 |
| 普通受邀协作节点 | 用户＋项目、项目 | 继承入口及所有上级的职责、来源和用户本次限制 |
| 任务助手及其下级 | 直接入口可读三个范围；受邀时排除用户级 | 用户、用户＋项目；草稿不能成为正式项目事实 |
| 知识库助手及其下级 | 直接入口可读三个范围；受邀时排除用户级 | 仅用户＋项目，持续校验资料权限 |
| 项目初始化及整条协作链 | 仅项目 | 不写入，不从初始化草稿交互学习 |
| 群聊输出及其协作链 | 仅项目，且全部受众可访问 | 仅项目，再与任务、知识库等职责限制取交集；无法满足则拒绝 |
| 首页派生的任务草稿 | 继承真实入口和本次限制 | 不把复制上下文当新用户陈述，不写交互记忆、不触发交互学习 |
| 管理端调试 | 按职责和来源计算，使用隔离测试身份 | 不进入生产用户记忆或生产学习 |

## 保存、协作与学习

入口身份来自后端保存的业务会话，直接上级与根会话来自真实团队关系。各节点直接向后端提交结构化候选及原始来源，不依赖总控逐层转述。结果返回上级或调整团队关系不能扩大权限、移除已参与节点的来源限制。

用户明确确认的独立事实可以即时保存；涉及协作或知识资料的候选，要等回复可靠保存、业务协作完成且来源权限仍有效后提交。工具返回 `pending` 只表示已提交候选，不能答复「已经记住」。失败、取消、来源变动或迟到请求不得继续落库；协作前已即时保存的明确事实不追溯回滚。

相同来源、操作和内容共享幂等结果。修改已有事实检查版本，不静默覆盖冲突内容。删除停止召回，版本历史保留；索引失败、服务重启或旧任务重试不能复活已删除记录。

后台学习按有效业务阶段归集原始用户消息、真实工具结果或确认事件。邀请成功、消息发送成功、草稿生成及助手自称完成，不证明业务完成；发布只证明发布，验收才证明通过。单独失败不构成成功经验，经验须有适用条件和限制，操作技能还须有实际步骤。学习不会自动安装工具、执行生成代码或提升权限。

提炼和系统校验通过后成果自动生效，不要求人工逐条审核。模型调用前、成果保存前及读取时均检查来源、范围和版本；参与去重或冲突判断的已有记忆也须即时复核。来源校验不保证内容绝对正确，因此保留原始证据、版本与删除能力。普通用户明确保存的事实不会仅因删除原聊天而丢失。

## 用户排除与学习暂停

「不要学习，记住我的偏好」允许保存明确偏好，但不把本次交互用于提炼经验；「本次不要记忆」同时停止本次记忆使用、写入和学习。限制沿同一协作运行及可验证的草稿生成来源传递。正式业务事件必须有真实生成与确认关系，不能靠最近一次会话猜测；来源尚未归集完成时，后台等待重查，不阻塞正常发布和确认。

全局暂停或关闭单一来源后，停止领取对应新学习任务。已发出的模型请求允许收尾，但停用期间不能提交新成果；任务保留为可恢复状态，不按普通失败消耗重试次数。恢复后重新核验来源再处理。暂停不关闭明确保存、已有有效记忆读取、对话压缩或来源失效检查，也不恢复已撤销的来源权限。

学习设置更新与成果提交使用同一 PostgreSQL 事务边界；启用后台学习要求平台配置和记忆存储支持这一机制，不对 Redis 配置存储或跨数据库部署作隐式降级。

## 群聊持续学习

后台独立增量收集群聊消息，无需 `@`、等待智能体回复或主动总结。扫描不调用模型；达到内部积累、空闲或最长等待条件才生成批次。每个有效批次以一次模型调用判断价值并提炼，允许空结果，完成后推进游标。群内不发送学习开始、完成或失败通知。

| 证据来源 | 成果归属 |
| --- | --- |
| 明确自动同步全项目成员的群，且全部证据在产生时全体可见 | 项目 |
| 子群共同结论，或引用原子群历史证据 | 能访问全部证据的成员各自的用户＋项目 |
| 特定成员的项目上下文 | 该成员的用户＋项目，须能访问全部证据 |
| 本人明确的跨项目称呼、回答详略偏好 | 本人用户级，不推断身份或权限 |

全体群由实际成员同步策略判定，不能靠群名称或当前恰好全员在群推断。历史证据保留产生时的受众，扩群不扩大旧材料权限。群聊来源不改抽屉、用户或项目；合并及技能提炼继续保留同群、同归属约束。群聊交互只走群聊学习来源，关闭后不会转入普通交互学习。

消息变更序号与业务事务一起提交；记忆成果、版本、索引任务、批次结果和游标在同一事务保存。同群只处理一个未完成批次，幂等重试不重复产生正文版本。失败按冷却策略自动重试，管理端可查看原因。

撤回、编辑、成员变化有独立失效进度，不受学习预算、暂停或失败批次阻塞；查询也会重新检查当前来源权限。退群、群转为子群、项目或资料撤权后，旧成果不得继续被无权者召回。

## 管理端使用

「记忆管理」提供记忆库、学习记录和运行诊断。管理员可按用户、项目、范围、类型和状态搜索，查看完整正文、来源、历史与处理结果，并删除不需要的记忆。

管理端不提供待确认、正文编辑、审核、反馈、合并、回滚或手动任务重试；旧 POST／PATCH 写入口统一拒绝。对话中的自然纠正与明确偏好由智能体按上述规则处理。候选和到期成果由后台复查，来源永久无效时停用，临时故障延后处理；索引及学习失败自动冷却重试。
