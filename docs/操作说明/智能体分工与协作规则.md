# 智能体分工与协作规则

主智能体有四个固定职责，始终启用，不能停用、删除或清空。业务智能体是可新增的专业能力执行者，以「公开／内部」区分可见范围。

## 固定职责

| 类型 | 业务入口与职责 | 向外调用 |
| --- | --- | --- |
| Dobby 总控 | 首页理解需求、下发工作、汇总结果 | 固定任务助手、知识库助手，以及已启用且允许总控调用的业务智能体 |
| 项目初始化 | 仅在初始化页面生成、核对草稿 | 已保存协作名单中的获授权专业智能体 |
| 知识库助手 | 工程资料问答，直接查询外部项目知识库 | 按已保存协作名单调用 |
| 任务助手 | 任务生成入口和群聊任务草稿，调用任务引擎编排流程 | 按已保存协作名单调用 |
| 业务智能体 | 专业业务处理；公开且发布后可直接进入 | 对方须允许其他邀请，且在调用方已保存名单中 |

总控与项目初始化不接受任何智能体调用。向直接上级返回结果不属于新调用；旧名单和已有子会话也不能绕过此边界。初始化的业务入口只接受初始化会话，管理端调试仍可验证其配置。

只有固定知识库助手直接获得外部知识库查询工具，职责由平台绑定决定。其他智能体需要资料时，在协作授权范围内调用它；调用不会获得它的直接工具权限，实际查询仍受用户、项目和文档范围约束。

任务助手先生成可编辑草稿，正式保存和发布由用户确认；停止生成会中断对应运行。草稿不等于正式任务，相关来源边界见[记忆与学习职责与运行规则](记忆与学习职责与运行规则.md)。

## 公开、内部与发布

- 「公开」对应 `business`，「内部」对应 `system_internal`。内部智能体不进入用户业务列表或普通 `@` 候选，也不能发布。
- 「允许平台运行」决定业务智能体能否被平台使用或协作调用，关闭后保留配置。
- 「发布到平台」仅控制公开入口；公开、已启用且已发布才进入业务列表及 `@` 候选，实际运行还需可用模型。
- 未发布不等于内部，发布也不授予协作权限。记忆与学习由系统按职责、入口和来源计算，不按公开／内部或旧层级分配。

## 协作授权与配置

管理员决定允许调用谁，智能体在授权范围内决定是否需要协作。固定任务助手、知识库助手始终允许总控调用；业务智能体的以下两项接收许可相互独立，默认关闭，保存时保留已有值。

| 允许总控调用 | 允许其他智能体邀请 | 总控名单 | 其他调用方候选 |
| --- | --- | --- | --- |
| 关闭 | 关闭 | 不纳入 | 不出现 |
| 开启 | 关闭 | 自动纳入 | 不出现 |
| 关闭 | 开启 | 不纳入 | 出现，仍须勾选保存 |
| 开启 | 开启 | 自动纳入 | 出现，仍须勾选保存 |

「编辑智能体 → 协作设置」维护接收许可和协作说明；说明写明适合承接的任务、所需信息与预期结果。「协同智能体」页签只管理向外调用名单，两处保存不互相覆盖。调用范围只接受 `selected` 和 `none`，未配置时独立工作。

每次查找、首次调用、重试和继续派发都校验双方启用状态与当前许可。总控对业务智能体检查总控调用许可；其他调用方检查目标邀请许可及自己的明确名单。关闭许可后，旧名单或团队成员身份不能继续授权派发。

被调用方使用自己的工具和固定模型策略；继承模型的规则见[统一模型与原生图片输入](统一模型与原生图片输入.md)。用户、项目、来源和受众限制沿整条协作链传递，返回上级不能扩大权限；禁止调用本次运行的上级形成循环，禁止跨阶段接管其他调用者负责的成员。

固定职责只读平台职责绑定，不按名称、角色标签或发布状态猜测；启动时不隐式迁移旧职责和授权配置。

## 系统权限审核

「权限审核配置」是独立系统服务入口，集中维护审核凭证、模型、最低置信度、最高自动放行风险、超时，以及模型测试和审核记录。

审核服务固定使用独立模型，不提供启用开关或备用模型，也不加入主智能体列表、聊天、发布或协作邀请。Auto 模式按需调用；模型未配置、不可用或判断不满足规则时转人工确认。明确权限拒绝和必须人工确认的业务操作继续由权限引擎控制。
