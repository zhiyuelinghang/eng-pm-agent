# 三抽屉记忆系统重构

> 后续学习闭环已接入，完整功能对应、触发条件、迁移及验收见 [记忆与学习闭环重构](记忆与学习闭环重构.md)。普通记忆保持直接保存；学习成果另有证据、候选审核和生命周期。

目标：用户级、用户＋项目级、项目级记忆统一管理；主模型一次决定内容和作用域，后端校验并可靠保存，不以分类模型或向量模型可用为保存前提。

## 约束与决定

1. PostgreSQL 正文为权威记录；向量索引为可重建投影。正文与索引任务同事务提交。
2. 租户和身份类型参与所有权限过滤。业务用户与管理测试身份不得因数字 ID 相同而合并。
3. 项目共享记录不归某个用户所有；创建人只用于审计。来源不明的旧项目池不自动发布。
4. 明确字段在同一归属下只有一个有效值；版本更新需要预期版本，内容完全相同返回未变化。
5. 文字事实按来源请求幂等，不用相似度自动覆盖正式决定。删除记录不进入检索；历史版本供管理审计。
6. 后台索引按记录版本更新；删除／改抽屉／编辑后清除旧向量。先校验权限再检索，无跨用户结果缓存。
7. 身份、当前项目、公开会话边界由服务端确定。模型只建议抽屉、字段和内容。
8. 长对话压缩保留独立职责；旧 Dreamer 不再维护新的权威正文。后台工作不得令正常聊天变成失败。
9. 字体不小于 12px。使用项目内嵌 Python。未经明确需要不操作浏览器；需要联动界面验证时先告知。

## 验收场景

保存姓名无需加载向量模型；同请求重试仅一条；显式纠正保留版本；私人记忆不跨用户／项目；项目共享可被授权成员读取；权限撤销立即拒绝；管理端编辑后聊天读新值，删除后不可召回；索引失败可重试且不丢正文；进程重启可恢复索引任务；旧数据迁移可重复运行。

## 实现入口

| 职责 | 文件 |
| --- | --- |
| 权威正文、版本、幂等与索引任务 | `utils/memory_schema.py`、`utils/memory_repository.py` |
| 独立向量模型与后台处理 | `utils/memory_service.py` |
| 三个模型工具与轻量资料读取 | `AgentScope/agentscope/app/memory/_direct.py` |
| 当前用户／项目实时授权 | `backend/app/agent_context_gateway.py` |
| 实际运行入口及后台工作生命周期 | `scripts/agentscope_dev_app.py` |
| 管理 API | `AgentScope/agentscope/app/_router/_memory_management.py` |
| 记忆管理、设置、智能体读写配置 | 管理前端 `pages/memory-management`、`pages/memory-settings`、`components/form/AgentPlatformConfigFields.tsx` |
| 旧数据导入 | `scripts/migrate_memory_v3.py`、`utils/memory_migration.py` |

保存链路为：主模型调用 `add_memory(items)` → 实时权限校验 → 正文、历史和索引任务同事务提交 → 返回保存结果。向量模型在后台处理任务，不参与保存成功判定。`search_memory` 按字段或内容检索；`forget_memory` 携带 ID 和预期版本停止召回。

后台租约为 5 分钟；失败退避重试，连续 5 次失败后由管理页手动重试。记录修改会替换任务版本；旧租约或旧版本的处理结果不会写回。模型未预热、正忙或查询向量生成超过 1 秒时使用文本检索。

项目级写入沿用当前平台管理员权限，普通项目成员可以读取授权项目的共享事实。每个管理级智能体可进一步缩小三个抽屉的读写范围。执行级智能体不挂载长期记忆工具。管理端登录身份只用于审计和管理；管理端试聊的个人记忆通过独立身份类型隔离。
