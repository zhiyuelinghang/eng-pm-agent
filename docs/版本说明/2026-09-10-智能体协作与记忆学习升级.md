# 2026-09-10 版本说明：智能体协作、记忆学习与模型管理升级

本版整理了平台智能体的职责、入口和协作权限，重做长期记忆与后台学习的分工，并集中精简智能体、模型、凭证和权限审核界面。同时接通任务助手的真实任务生成链路、统一当前聊天模型配置，修复图片没有以原图进入模型的问题。

主体功能提交：[`f0dd2021`](https://github.com/zhiyuelinghang/eng-pm-agent/commit/f0dd2021df22925e7cd13b39cd4c4087e71161b5)。比较基线：`c726928a`。主体功能提交涉及 276 个源码、测试和文档文件；本说明另记录复核时随说明补交的任务日历字段修复。

以下按这个版本的最终行为说明。开发过程中出现过的逐智能体记忆开关、层级方案和中间界面，以本说明中的最终规则为准。

## 一、明确四个主智能体的职责与使用入口

| 主智能体 | 使用入口与职责 | 协作规则 |
| --- | --- | --- |
| Dobby 总控 | 首页主体，承接需求、分配工作并汇总结果 | 可调用任务助手、知识库助手，以及开启总控调用许可的业务智能体；自身不接受其他智能体调用 |
| 项目初始化 | 在初始化页面分析资料、组织专业智能体、生成和核对初始化草稿 | 不接受总控或其他智能体调用；按已配置专家名单完成初始化 |
| 知识库助手 | 知识库页面问答，负责查询外部项目知识库并依据资料回答 | 总控可调用；其他智能体需满足邀请许可和明确协作名单 |
| 任务助手 | 整理任务需求，调用任务引擎生成可编辑任务草稿 | 总控可调用；其他协作仍受邀请许可和明确名单约束 |

- 四个主智能体是平台固定组成，不能停用、删除或清空职责。界面移除对应启停选项，服务端也检查这些限制。
- “资料助手”统一命名为“知识库助手”。直接查询项目知识库的能力由这一固定职责决定，取消其他智能体通过勾选开关取得该能力的方式。
- 需要资料的总控或业务智能体，在允许协作的范围内交给知识库助手处理；资料访问继续服从实际用户、项目和文档权限。
- 项目初始化限定于初始化业务入口，管理中心仍保留配置调试能力。
- 主智能体与业务智能体使用清晰的独立管理入口，主智能体以固定职责呈现，业务智能体用于维护可扩展的专业能力。

## 二、重新梳理协同调用的双向权限

协作配置分成“谁可以调用我”和“我可以调用谁”。管理员确定许可范围，智能体在范围内决定是否需要协作。

### 接收协作请求

编辑智能体增加独立的“协作设置”区域。业务智能体的两个开关分别生效，并采用上下排列和独立说明：

| 设置 | 开启后的行为 | 关闭后的行为 |
| --- | --- | --- |
| 允许总控调用 | 智能体已启用时自动进入总控可协调名单 | 总控不能继续派发给它 |
| 允许其他智能体邀请 | 智能体已启用时出现在其他智能体的候选列表；对方还需加入协作名单 | 从候选中移除，旧名单或已有团队成员身份不能绕过限制 |

总控与初始化不提供接收协作开关。任务助手、知识库助手固定允许总控调用，其他邀请仍单独控制。

### 向外分配协作

- “协同智能体”调整为能力页第一个 Tab，管理向外调用的明确名单。
- 总控的名单根据固定助手职责和业务智能体的总控调用许可自动展示，不再让管理员逐个分配。
- 其他主智能体和业务智能体按保存的名单调用；没有配置名单时独立工作。
- 接收许可和协作说明放在编辑窗口，向外名单放在能力页，保存一处配置不会覆盖另一处。
- 查找、首次邀请、重试和再次派发时重新检查权限。禁用目标或撤销邀请许可后，旧会话不能继续授权调用。
- 子任务结果返回直接调用者；禁止向本次运行的上级发起循环调用，也不能跨阶段接管其他调用者的成员。
- 协作节点继续使用自己的技能、MCP、数据库等能力，调用方不会因为委派而自动获得对方权限。

## 三、统一业务智能体的公开、内部与发布状态

- “业务工具”统一按“业务智能体”呈现。
- 编辑中的“平台角色”改为“使用范围”，提供“公开”和“内部”。
- 公开智能体同时开启“允许平台运行”和“发布到平台”后，才进入用户业务列表及相应助手、`@` 候选；实际使用还需可用模型。
- 内部智能体只用于系统流程或授权协作，不在用户业务列表、`@` 候选中出现，也不能发布。
- “允许平台运行”和“发布到平台”各占一行，分别说明运行权限和平台可见性的含义。发布不会自动授予协作调用权限。
- 管理列表显示“公开／内部”和“已发布／未发布”两组标签：公开为蓝色、内部为紫色、已发布为绿色、未发布为琥珀色；停用状态另外标示，避免把“未发布”误解成“内部”。
- 移除旧智能体层级配置及相关运行门槛，主智能体职责、业务智能体使用范围和协作权限各自承担明确作用。

## 四、改善智能体配置与管理页面

- 管理端首页默认进入主智能体工作台，显示四项固定职责及实际绑定；配置缺失、暂不可用和正常配置分别展示对应状态。业务智能体可搜索并查看独立详情。
- 统一详情页标题、图标和操作按钮的布局，长说明不再把编辑、调试和删除按钮挤到不一致的位置。
- 编辑窗口使用与表单结构对应的骨架加载状态，替换大块空白上的简单“加载中”文本。
- 整理基本信息、模型配置、平台接入和协作设置的分区，主智能体按固定职责展示可编辑项。
- 技能空状态删除不必要的格式词说明，减少重复提示。
- 能力配置页保留协同智能体、技能、MCP、数据库交互；移除与系统统一规则重复的“记忆与学习”Tab。
- 系统工具使用独立目录维护；MCP、技能和数据库交互继续按智能体所需分配。
- 能力页切换 Tab、切换智能体、离开或刷新时处理未保存更改；MCP 目录暂时缺少已分配服务时保留分配并提示，不因读取异常丢失配置。
- 数据库交互列表补充搜索、选中数量、只读／写入与停用标识，统一保存、放弃、删除确认和错误反馈。
- 编辑窗口同步移除逐智能体的记忆配置，避免同一设置在外部 Tab 与编辑窗口重复出现。
- 独立调试入口使用智能体已保存的模型策略和执行权限模式。固定模型不在调试会话中任意切换，执行权限跟随配置。
- 调试窗口集中提供调试会话的新建、切换、重命名和删除。
- 记忆配置与记忆管理调整导航顺序，移除“基础配置”分组标题以及多余的规则说明卡片。

## 五、让任务助手真正参与任务生成

- 沿用原任务智能体并完成任务助手职责配置，接入现有任务引擎 MCP、固定模型和协作说明，避免创建重复助手。
- 任务管理中的任务流生成走管理中心已保存的任务助手配置，使用真实模型调用任务引擎。
- 识别任务引擎 MCP 的真实工具名称，修正成功调用被误判为“没有调用任务引擎”的问题。
- 将任务引擎返回的触发时间、责任人、工点和交付物等结构转换为编辑器可用的草稿字段；缺失信息保持待补充状态。
- 任务管理编辑器补齐日历方式、执行星期、每月日期、截止日期和最大执行次数等回填字段，保留任务引擎已有的日历执行模式。
- 补充修复首页、群聊原生任务流转草稿时的字段映射：正确读取 `calendar_weekdays` 和 `calendar_day`，保留每周执行星期与每月日期。复核时实际复现的 `[2, 4]` 被清空、每月 `15` 日变为空值的问题已修正，并补上从真实任务引擎序列化结果到表单校验的回归。
- 生成结果先进入可编辑草稿，保存、发布和执行计划仍由业务确认流程处理。生成草稿不代表已经发布或完成任务。
- 停止生成会中断对应任务助手运行。
- 任务引擎包、MCP 清单和服务端版本统一为 `0.1.1`。重新构建并替换仍含旧规则模板回退行为的运行包，使实际部署与当前源码一致。
- 任务引擎 PostgreSQL 存储支持参加平台当前业务事务，任务与对应业务记录可以统一提交或回滚。周期、日历、转办等既有能力继续保留。
- 首页派生草稿、群内私有草稿和正式确认事件保留真实生成来源，支持后续权限与学习规则核验。
- 生成、创建和状态流转检查实际项目访问范围，拒绝项目之外的责任人或工点，以及跨用户、跨项目的生成来源引用。
- 停止请求与会话创建、提交交错时，也会对实际提交的运行执行中断；临时生成会话不混入用户普通会话列表。

## 六、重新分配长期记忆、学习和压缩的职责

| 部分 | 本版职责 |
| --- | --- |
| 业务智能体与主智能体 | 完成业务，按本次授权读取记忆、提出明确记忆变更或提供学习材料 |
| 后端记忆服务 | 校验身份、来源、范围、版本和调用链，合并候选并事务保存；明确事实的保存与删除不额外调用分类模型 |
| 后台学习服务 | 使用明确配置的学习模型，从有效业务材料中提炼经验，通过校验后保存 |
| 对话压缩 | 整理当前长对话上下文；可独立选择模型，留空时使用当前对话模型 |
| 索引服务 | 建立向量索引、辅助检索，与经验提炼和对话压缩分开 |

系统学习有明确的后台服务和模型配置。总控无需在每次回答后再充当一个额外的“记忆管理智能体”，本地向量模型也不承担学习提炼职责。

### 按入口和职责自动决定范围

取消逐智能体分配三个抽屉读写权限、学习参与开关，以及“跟随系统／排除交互学习／禁止长期留存”三选项。公开和内部只影响可见性，记忆规则由实际运行场景确定。

| 场景 | 本版关键规则 |
| --- | --- |
| 首页总控、用户直接使用业务智能体 | 在用户、用户＋项目、项目三个范围中，按真实身份与业务权限工作 |
| 普通受邀协作 | 不读取跨项目的个人档案；继承入口、上级、来源及用户本次限制 |
| 任务助手及其下级 | 草稿不能直接变成项目共享事实；可写范围限制在用户及用户＋项目，并叠加调用场景约束 |
| 知识库助手及其下级 | 写入候选仅允许用户＋项目范围；涉及资料来源时持续校验原资料权限 |
| 项目初始化及其协作链 | 只读项目记忆，不从初始化草稿交互写入长期记忆或自动学习 |
| 群聊回答及其协作链 | 按全部输出受众共同可见的项目范围工作，不能把个人私密记忆带进群里 |
| 管理端调试 | 使用隔离的测试身份与范围，不进入生产用户记忆和生产学习 |

这些是系统能力上限，实际访问还要与文档来源、成员身份、项目权限和调用链限制取交集。

### 多级调用共享来源约束

- 后端根据真实业务会话和团队关系识别入口、直接调用者及根会话，不靠提示词猜测是否被邀请。
- 每个节点直接提交结构化候选和原始来源，避免只凭总控逐层转述落库。
- 用户明确确认的独立事实可以即时保存；依赖协作或资料来源的候选，要等回复可靠保存、协作完成且权限仍有效后提交。
- 候选回执为待处理时，不当作“已经记住”。失败、取消、迟到请求及失效来源不能继续写入。
- 保存使用幂等和版本校验，冲突内容不静默覆盖；删除停止后续召回并保留版本审计。
- 用户明确要求“本次不要学习”时，允许保留明确要求记住的事实，但不把交互用于提炼经验；“本次不要记忆”同时限制本次读取、写入和学习。这是对明确语句的识别，不代表可以准确推断所有隐私意图。
- 这些限制沿协作和可验证的草稿生成来源继续生效，不能通过转交下级、复制上下文或调整团队上级移除。

## 七、把全局记忆配置收敛到六项

配置契约从 60 个字段缩减为 6 项产品选择，页面从 37 个控件缩减为 4 个开关和 2 个模型选择器：

1. 启用后台学习。
2. 后台学习模型。
3. 智能体业务交互来源。
4. 已确认业务事件来源。
5. 群聊消息来源。
6. 对话压缩模型。

- 常用个人资料加载、语义检索、索引任务、默认返回数量、学习调度和压缩策略改由系统维护。
- 语义服务不可用或超时时可回退文字检索；索引失败可重试，服务重启后继续处理。
- 启用学习必须选择可用模型和至少一种来源；暂停时保留配置偏好。
- 暂停学习不关闭明确记忆保存、已有记忆读取或对话压缩，也不停止来源失效检查。
- 已发出的学习模型请求可以收尾，但停用期间不能提交新成果；恢复后重新验证来源再继续处理。
- 配置保存使用版本校验。其他管理员先保存时，保留当前草稿并展示差异，避免覆盖彼此修改。
- 移除“恢复默认”操作以及多余说明卡片，避免误清模型或重新开启原本关闭的来源。
- 页面以后台学习和长对话压缩两个区域直接展开，底栏统一显示保存状态、保存和放弃操作。
- 学习活动把暂停、配置未就绪和模型缺失显示为“等待恢复／等待配置／等待模型”，补充来源、验证状态、分页和错误展示，便于判断待处理原因。

### 分开处理不同学习来源

- 业务交互按一次有效业务阶段归集原始消息和真实工具结果，助手自称完成不能替代业务证据。
- 正式发布、初始化确认、验收等由业务事务提供来源；发布证明发布，验收证明验收通过。
- 群聊使用独立后台来源。关闭群聊学习后，不改走普通交互学习。
- 全体群可在权限允许时产生项目共享成果；子群成果限定在有权成员的个人项目范围，个人偏好只归对应发言者。
- 学习调用前、保存前和成果读取时检查来源；撤销资料权限或改变受众后，旧学习成果不能继续扩大可见范围。
- 已有经验参与去重或冲突判断时也要重新校验，不能仅依赖定期扫描。

## 八、精简模型凭证和参数编辑

### 凭证直接编辑

- 删除详情页重复的“编辑”弹窗，名称、API Key、API Base URL 可直接修改并保存。
- 三项使用真正的单行输入框，长内容保持单行滚动，不把密钥或地址换成多行展示。
- API Key 支持隐藏与显示；保存只提交改变的字段，未提交的密钥等配置继续保留。
- 切换凭证、离开页面或删除前处理未保存草稿；保存过程中阻止相互冲突的操作。
- 凭证编辑与模型发现、测试、目录修改互相协调，避免接口操作期间继续修改凭证。保存失败保留输入，字段结构加载失败可重试。
- 保存后立即更新凭证名称并刷新模型目录，清除旧连接测试结果；后续刷新失败不再让列表倒退为旧名称。
- 凭证基本信息更新不覆盖模型目录，模型目录与默认参数使用各自的配置接口。

### 模型默认参数集中管理

- 常用配置收敛到思考模式、思考强度；服务商特殊参数放在“接口扩展”中。
- 移除输出上限、随机性、累计采样、并行工具请求、思考预算等普通用户无需逐项设置的控件，整理中文标签及说明。
- 界面精简保留已有的显式参数和接口扩展，避免打开后保存就丢失原配置。
- 校验并定位错误字段，保留布尔 `false`、数值 `0` 和嵌套 JSON 的实际含义。
- 手动模型编辑只保留用途、模型 ID 和显示名称；修改名称时保留既有能力和默认参数，去掉重复的 JSON 编辑入口。
- 不同服务商展示对应的思考请求语义，模型选择去掉不帮助判断的凭证技术类型后缀。
- 智能体和会话的参数覆盖不再控制正式运行，保存的模型默认参数由使用该模型的运行入口统一继承。

### 模型测试使用已保存配置

- 模型测试从服务端读取已保存凭证、模型默认参数和接口扩展，包括保存的思考配置。
- 未保存的页面草稿不会进入模型请求，需要先保存再测试。
- 保存模型参数后清除旧测试结果，避免把上一份配置的测试成功当作当前配置已通过。
- 连接测试使用简单请求验证模型可用性，不把它当作完整智能体任务、工具或全部图片场景的验收。

## 九、统一当前模型，并修复输出与继承规则

### 当前开发环境的模型核对

- 智能体管理平台唯一启用的聊天模型为 `deepseek-flash`。
- 清理 9 个智能体、16 个会话中的旧 `deepseek-v4-flash` 绑定及局部参数覆盖。
- 学习、压缩和权限审核已核对为当前模型；保持职责上的独立配置入口。
- 未固定模型的智能体继续继承入口，不强制改成固定策略；禁用的 `deepseek-v4-pro` 目录条目不参与选择和运行。
- 新协作、再次派发、创建下级智能体和计划任务读取当前有效模型，修正照抄旧会话模型副本的问题；目标自身固定策略仍优先。
- 可切换会话的失效模型选择按实际可用目录处理，搜索所有凭证中的可用项；目录加载失败保留原选择，切换保存完成前暂不发送消息。
- 保存或运行时校验模型存在、已启用且与凭证类型匹配；错误的固定模型明确报错。
- 旧业务资料补全接口改为调用平台共享模型服务，移除独立的 `AI_MODEL`、`AI_BASE_URL`、`AI_API_KEY` 配置链。
- 共享文本接口仅供受信的平台后端调用，不创建会话、执行工具或写入记忆。

### 取消假定的 8192 输出上限

- 动态模型未提供输出能力时记录为未知，不再自动填入 8192，也不在表单校验中制造这个上限。
- 接口允许省略输出长度、且没有明确配置或已知能力时，不发送长度参数，由服务商处理。
- 已登记的能力和用户明确的限制继续生效。必须提供长度的接口在缺少依据时明确报错。
- 模型目录、模型测试和正式运行使用一致的输出能力解析规则；未知不代表无限输出。

## 十、打通原生图片输入

- 为当前模型登记 PNG、JPEG、WEBP、GIF 图片能力，刷新发现目录时保留已确认能力。
- 管理端支持的图片保留原始数据并进入模型图片请求，不再统一先做 OCR 后丢掉原图。
- 工程平台首页、助手及业务智能体会话发送本轮选择的原图，原有资料上传引用继续保留。
- 项目初始化只读取当前项目、当前初始化会话中所选的原文件；成功的解析结果仍可附带，OCR 失败不会阻断有效原图。
- 工程平台每次最多 8 张、总计 30 MB；验证真实格式、损坏或截断文件、大小及初始化文件目录范围。
- 普通文档继续走解析流程；群聊保留专用上传与资料授权链路。
- 实际使用保存的模型能力和思考参数发送合成图，模型正确识别“紫色圆形、橙色三角形、青色正方形”。测试未发送业务图片。

## 十一、把权限审核整理为独立配置页

- 将系统权限审核从“模型与连接”迁出，新增“权限审核配置”独立菜单。
- 审核员作为系统服务按需运行，不加入主智能体列表，不提供聊天、发布或协作邀请入口。
- 删除独立模型启用开关、备用凭证和备用模型；保留审核凭证、模型、最低置信度、最高自动放行风险和超时。
- 配置区使用紧凑响应式网格，操作区靠右下；审核记录自适应占满剩余高度，并设置最小高度支持小屏滚动。
- 清理重复标题和非必要说明，保留审核模型测试及最近审核记录。
- 测试结果显示耗时、模型、审核动作、风险、置信度和原因；记录支持刷新、分页及明确空状态，读取失败可重试。
- Auto 模式按独立审核配置处理需要确认的操作；模型不可用、判断不清或未满足规则时转人工，明确拒绝和业务确认要求仍生效。

## 十二、统一长任务运行、截断处理和阶段保存

- 主智能体、业务智能体、调试和确认后恢复共用运行管理策略，不再依赖逐智能体填写轮次、上下文和重试细项。
- 有新结果时继续运行；通过工具、参数和结果识别重复查询、交替重复及连续失败，不额外调用模型判断进展。
- 连续异常达到阈值时先提示调整，再结束当前阶段并总结已完成内容和阻碍，不把异常结束显示为正常完成。
- 保留运行资源保护：每次回复最多 200 轮、100 万输出词元、1 小时累计活跃时间；等待用户确认不按活跃运行计时。
- 已接入的模型适配器识别正文截断并有限续接，最多连续追加 4 次；工具参数截断时不执行不完整调用。
- 完成轮次在后续模型调用前按至少 30 秒间隔保存阶段状态，结束或中断时保存完整状态。
- 阶段保存沿用服务端运行、订阅和取消机制，不承诺服务器崩溃后自动重做有副作用的工具操作。

### 数据结构

本版本新增三项业务数据库修订，最终开发环境版本为 `fd73b916a204`：

缺少完整运行证据的历史交互成果保留原文和审计，按迁移规则停止作为有效成果使用；不会把历史聊天补造为已经验证的业务运行。相关修订不提供自动删除证据的降级路径。

### 显式配置清理

| 工具 | 用途 |
| --- | --- |
| `scripts/remove_agent_memory_policy.py` | 清理中间阶段的逐智能体记忆策略字段 |
| `scripts/simplify_memory_settings.py` | 将全局记忆配置转换为六项公开配置，并更新配置版本 |
| `scripts/simplify_permission_reviewer.py` | 清理审核员启用与备用模型字段，并检查旧停用配置的激活风险 |
| `scripts/remove_assumed_model_output_limits.py` | 清理旧动态模型被假定的 8192 输出能力 |
| `scripts/align_platform_chat_model.py` | 按明确的凭证与目标模型统一当前聊天绑定及已确认图片能力 |

这些工具默认预览，应用需显式执行。模型统一工具只适用于已核验的唯一目标场景，不能把当前开发环境的模型名、凭证 ID 或能力未经核实照搬到其他环境。

当前开发库已分阶段完成转换。直接从更早旧库升级时，要先盘点旧字段并审阅对应数据处理；保留的单项清理脚本不能覆盖所有历史阶段。启动程序不承担旧职责、旧层级和旧配置的隐式兼容转换。

后台学习的暂停与成果提交使用同一 PostgreSQL 事务边界，启用时要求平台配置与记忆存储位于支持该机制的同一 PostgreSQL 数据库；Redis 配置存储或跨数据库部署不提供隐式降级。

服务器更新需要按项目部署规范完成数据库升级、两套前端构建、任务引擎运行包安装和服务重启。Git 推送不包含真实 `.env`、数据库、运行日志或本地模型绑定数据，也不代表其他服务器已自动升级。本次已重启并验证本地 AgentScope 与工程后端，并检查了实际在线接口。

## 十五、尚待核验与适用边界
