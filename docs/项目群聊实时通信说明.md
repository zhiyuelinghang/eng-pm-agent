# 项目群聊实时通信说明

## 当前范围

当前版本已打通项目默认群和项目内私密会话：

- 同一项目成员进入同一个项目群；
- 消息、成员关系和已读位置由平台 PostgreSQL 保存；
- 平台后端负责登录鉴权、项目权限和消息写入；
- Centrifugo 只负责把已提交的消息实时广播给在线页面；
- 实时服务断开时，页面自动改为定时刷新，消息仍可发送和保存；
- 用户可从当前项目成员中选择一人或多人创建私密会话；
- 私密会话只有创建者和所选成员可以查看、订阅和发送消息；
- 输入 `@` 会显示紧凑候选浮层，可选择全体成员、当前频道成员、平台已发布业务智能体或平台保留的任务助手；
- `@全体成员` 不设次数和人数配额，以独立消息语义持久化，并提醒当前频道除发送者外的所有成员；
- 人员提及写入结构化 mention 记录，并通过个人实时频道定向提醒；
- 每位被提及成员拥有独立的首次查看回执；消息进入该成员的可视区域时原子领取回执并短暂闪烁，其他成员不受影响；
- 未领取的艾特提醒显示在聊天发送框上方；点击提醒可切换到来源会话并定位原消息，原消息进入可视区域后提醒自动消失；
- 每条消息最多明确提及一个智能体，前端阻止第二个选择，后端再次拒绝伪造请求；
- 智能体仅在被明确选择提及时运行，首次路由直接进入目标智能体，不经过 Dobby；平台只传递当前用户、项目、频道成员和有界的近期消息；
- 普通业务智能体先落库一个连续运行占位，再依次更新“请求已受理、授权校验、会话建立、智能体执行、结果保存”及各阶段耗时，最终答复复用同一消息；
- 每次显式智能体请求建立独立的 AgentScope 会话和工作区，绑定原请求的平台用户、项目与内部 `group_chat` 会话；运行状态和回复通过 outbox 写回原频道；
- 资料工具在每次检索前后重新计算当前用户的文档白名单，撤销权限后不继续使用旧白名单返回资料；
- 原请求发起人可以停止本次执行或确认待执行操作，后端再次校验频道权限与原会话身份；后续用户的请求不会替换旧请求的确认目标；
- 下级智能体的人工确认请求同时通过 SSE 和轮询消息接口展示；确认内容带版本号，修改参数后必须重新审阅；停止后的迟到回包不能覆盖停止状态；
- `@任务助手` 走管理中心指定的任务助手与任务引擎，只生成私有待确认草稿，用户确认前不发布任务或群消息；
- 普通群消息不调用主智能体、不进行任务识别，也不触发任务引擎。

专题群、附件、成员变更和完整的已读回执不在本次试验范围内。

## 技术边界

平台是群聊业务数据的唯一权威来源。Centrifugo 不保存账号、项目权限或聊天业务表，也不能绕过平台 API 发送消息。

消息写入和实时投递记录在同一 PostgreSQL 事务中完成：

1. 平台校验登录用户是否属于目标项目；
2. 平台写入 `chat_messages`；
3. 平台校验并写入 `chat_message_mentions`；
4. 同一事务写入每位接收人的 `chat_message_mention_receipts`，以及频道广播和人员提及提醒的 `chat_realtime_outbox`；
5. Centrifugo 消费 outbox 并广播；
6. 若消息明确提及普通业务智能体，同一事务先写入运行占位；提交后后台直接调用目标智能体，并以同一消息 ID 持续发布阶段更新和最终答复；
7. 若目标是任务助手，同一事务只创建待生成草稿占位，后台调用管理中心指定的任务助手，草稿确认前不调用发布接口；
8. 接收人的页面在消息首次进入可视区域时领取个人回执，只有领取成功的页面播放一次提醒动画；
9. 消费完成后删除对应 outbox 记录。

客户端只能取得当前用户有权访问频道的短期连接令牌。发送人身份由后端登录态确定，前端不能指定或伪造。

## Windows 安装和启动

`dobby-server-first-install.zip` 已经携带 Centrifugo 运行程序，首次部署无需联网安装。
解压并配置 `.env` 后，直接运行服务器首次部署检查和统一启动脚本即可。

如果运行程序损坏，或者从源码目录手动部署时缺少程序，可运行：

```text
安装群聊实时服务.bat
```

安装脚本会优先使用 PowerShell 7，下载固定版本的 Centrifugo Windows 单文件程序，并使用官方 SHA256 文件校验。程序安装到被 Git 忽略的 `runtime/centrifugo/`，不需要 Docker；它不是首次部署包的必执行步骤。

安装完成后，现有启动脚本会自动执行以下操作：

1. 生成本机运行配置；
2. 启动 `38431` 实时通信端口；
3. 启动平台后端和前端。

启动脚本不会创建表或执行 PostgreSQL 迁移。版本涉及数据库变更时，必须先备份，
再由管理员审阅并人工执行 `数据库更新` 目录中的对应 SQL。

可单独运行 `start-centrifugo.bat` 验证实时服务。`一键停止全部服务.bat` 会同时停止 `38431`。

### Nginx HTTPS 转发

生产站点使用 HTTPS 时，浏览器必须通过同域 `wss://` 连接，不能直接访问本机明文
WebSocket 端口。当前服务器 Nginx 配置应建立以下转发：

```text
wss://dobby.ibeyondnav.com/realtime/connection/websocket
    -> http://127.0.0.1:38431/connection/websocket
```

服务器 `.env` 对应设置为：

```env
CORS_ORIGINS=https://dobby.ibeyondnav.com
CENTRIFUGO_WS_URL=wss://dobby.ibeyondnav.com/realtime/connection/websocket
CENTRIFUGO_BIND_ADDRESS=127.0.0.1
```

公网只需开放 443，38431 不对公网开放。修改 Nginx 和 `.env` 后，应先执行
`nginx -t`，配置检查成功后重载 Nginx，并重启 Dobby 服务以重新生成 Centrifugo 配置。

## 配置项

配置示例见根目录 `.env.example`：

- `CENTRIFUGO_ENABLED`：后端是否签发实时连接令牌；
- `CENTRIFUGO_WS_URL`：浏览器连接地址；
- `CENTRIFUGO_TOKEN_SECRET`：生产环境独立签名密钥；
- `CENTRIFUGO_BIND_ADDRESS`：服务监听地址；
- `CENTRIFUGO_PORT`：服务端口。

本地未设置独立签名密钥时，会从平台 `JWT_SECRET` 派生隔离密钥；生产环境仍应配置独立的高强度随机密钥。

## 验证

后端权限与消息测试：

```text
python-3.13.14\python.exe scripts\pytest_entry.py --prepend . -- backend/tests/test_project_chat.py -q
```

启动平台后端与 Centrifugo 后，可验证 PostgreSQL outbox 到 WebSocket 的完整链路：

```text
python-3.13.14\python.exe backend\scripts\verify_project_chat_realtime.py
```

联调脚本只创建临时项目，验证完成后会清理临时项目和消息。
