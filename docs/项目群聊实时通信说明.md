# 项目群聊实时通信说明

## 当前范围

当前版本已打通项目默认群和项目内私密会话：

- 同一项目成员进入同一个项目群；
- 消息、成员关系和已读位置由平台 PostgreSQL 保存；
- 平台后端负责登录鉴权、项目权限和消息写入；
- Centrifugo 只负责把已提交的消息实时广播给在线页面；
- 实时服务断开时，页面自动改为定时刷新，消息仍可发送和保存；
- 用户可从当前项目成员中选择一人或多人创建私密会话；
- 私密会话只有创建者和所选成员可以查看、订阅和发送消息；
- 输入 `@` 会显示紧凑候选浮层，可选择全体成员、当前频道成员或平台已发布业务智能体；
- `@全体成员` 不设次数和人数配额，以独立消息语义持久化，并提醒当前频道除发送者外的所有成员；
- 人员提及写入结构化 mention 记录，并通过个人实时频道定向提醒；
- 每位被提及成员拥有独立的首次查看回执；消息进入该成员的可视区域时原子领取回执并短暂闪烁，其他成员不受影响；
- 未领取的艾特提醒显示在聊天发送框上方；点击提醒可切换到来源会话并定位原消息，原消息进入可视区域后提醒自动消失；
- 智能体仅在被明确选择提及时运行，平台会传递当前项目、频道成员和有界的近期消息；
- 同一频道与同一智能体复用一个 AgentScope 会话，智能体回复重新写回原频道；
- 普通群消息不调用主智能体、不进行任务识别，也不触发任务引擎。

专题群、附件、成员变更和完整的已读回执不在本次试验范围内。

## 技术边界

平台是群聊业务数据的唯一权威来源。Centrifugo 不保存账号、项目权限或聊天业务表，也不能绕过平台 API 发送消息。

消息写入和实时投递记录在同一 PostgreSQL 事务中完成：

1. 平台校验登录用户是否属于目标项目；
2. 平台写入 `chat_messages`；
3. 平台校验并写入 `chat_message_mentions`；
4. 同一事务写入每位接收人的 `chat_message_mention_receipts`，以及频道广播和人员提及提醒的 `chat_realtime_outbox`；
5. Centrifugo 消费 outbox 并广播；
6. 若消息明确提及已发布智能体，后端在响应发送请求后调用该智能体，并把回复作为新群消息写回；
7. 接收人的页面在消息首次进入可视区域时领取个人回执，只有领取成功的页面播放一次提醒动画；
8. 消费完成后删除对应 outbox 记录。

客户端只能取得当前用户有权访问频道的短期连接令牌。发送人身份由后端登录态确定，前端不能指定或伪造。

## Windows 安装和启动

首次使用时运行：

```text
安装群聊实时服务.bat
```

安装脚本会优先使用 PowerShell 7，下载固定版本的 Centrifugo Windows 单文件程序，并使用官方 SHA256 文件校验。程序安装到被 Git 忽略的 `runtime/centrifugo/`，不需要 Docker。

安装完成后，现有启动脚本会自动执行以下操作：

1. 将平台 PostgreSQL 迁移到最新版本；
2. 生成本机运行配置；
3. 启动 `38431` 实时通信端口；
4. 启动平台后端和前端。

可单独运行 `start-centrifugo.bat` 验证实时服务。`一键停止全部服务.bat` 会同时停止 `38431`。

## 配置项

配置示例见根目录 `.env.example`：

- `CENTRIFUGO_ENABLED`：后端是否签发实时连接令牌；
- `CENTRIFUGO_WS_URL`：浏览器连接地址；
- `CENTRIFUGO_TOKEN_SECRET`：生产环境独立签名密钥；
- `CENTRIFUGO_BIND_ADDRESS`：服务监听地址；
- `CENTRIFUGO_PORT`：服务端口。

本地未设置独立签名密钥时，会从平台 `JWT_SECRET` 派生隔离密钥；生产环境仍应配置独立的高强度随机密钥。

