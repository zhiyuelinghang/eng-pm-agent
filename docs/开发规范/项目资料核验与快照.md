# 项目资料核验与快照

## 判定归属

项目资料的必填、空值、取值范围、结构关系，以及分批提交时问题是否影响当前选择，全部由当前选中的核验 MCP 决定。前后端不补充业务规则，不按规则名称过滤 MCP 问题，不单独放宽质量字段。规则调整必须发布新的 MCP 版本。

草稿接收接口保留已知字段名、对象/数组结构、请求大小和来源记录要求；原始字段内容交给 MCP 检查。账号权限、记录标识关联、并发版本、重复提交保护与数据库存储类型转换属于接口及写入机制，不生成资料核验结论。

平台向 MCP 传递合并后的正式数据与本次选择，并通过 `validation_scope` 提供记录与变更的映射。MCP 返回本批次问题及 `details.change_keys`。平台只定位到对应记录/字段，保留 MCP 的级别、说明和结果状态。资料修正仍须人工修改原资料后重新上传。

## 快照

已完成的 MCP 结果持久化在预览存储中，专家完成核验时也生成快照。相同草稿版本、正式数据、有效资料、选择范围、匹配决定和 MCP 版本，重复打开直接复用；失败结果不缓存。切换核验版本期间取得的结果不存入旧版本的快照。

修改资料、正式数据或选择范围会按新内容核验。界面不提供“重新核验”入口；资料有问题时，用户须人工修正原资料并重新上传，由流程触发核验。接口保留 `force_validation` 供内部流程明确绕过快照。快照复用不会延长旧提交凭证：每次打开仍产生绑定当前用户的新预览凭证，提交前检查草稿及正式数据是否变化。

## WBS 展示

默认按树展示工序名称、计划区间、工期与负责人、完成进度、状态与优先级、前置与上级工序。来源、工时与成本等补充字段通过统一开关展示；有问题或现有数据有差异的字段始终显示。折叠层级不改变选择范围。

## 草稿范围与记录关联

草稿界面仅提供“全部”“新增”“更新”，不提供“待匹配”“已提交”分类或手动指定新建/覆盖的入口。记录按明确标识自动关联；人员同名、WBS 同名或来源序号相同都不能作为更新旧记录的依据。识别信息确实对应多条旧记录时，将候选事实传给 MCP，由 MCP 在相应字段提示人工核对和修正；写入流程不得任意选择一个目标。

分批提交成功后，已入库行退出草稿表格，卡片统计仅保留剩余内容；没有待提交变更或整份草稿已提交时不显示草稿卡片。后台保留来源行和提交台账用于追溯及防重复写入，已入库内容在项目配置中查看。


## 核验权限边界

初始化智能体只读取上传资料、写入草稿分区和触发平台调用 MCP，不能产生合格性结论或自行修复资料。六个智能体的系统提示与实际工作区技能必须同步维护。

通用数据库交互执行器有独立于可编辑白名单的权限边界：所有智能体均不可写核验运行、问题、快照、提交台账及草稿核验状态；初始化会话只可创建草稿及创建/更新来源分区。即使自定义交互放宽白名单、利用固定值或上下文绑定，也不能绕过此边界。正式写入只走人工确认接口。

核验前不替换姓名、不归并岗位别名、不分配或调整原始序号、不去重前置编码。`record_targets.observations` 保留原始提取值，既有账号姓名、多条上传记录指向同一旧记录等仅作为事实传给 MCP，不生成后端业务问题。WBS 关联问题的逐行字段和说明由 MCP 返回，前端原样展示。


## MCP 2.4.0 规则补齐（2026.09.4）

固定岗位规则迁入 MCP 自带的 `project_rules.json`：项目经理、项目常务副经理、项目商务副经理、项目总工、项目技术员、安全员、质量员、施工员、劳务员、材料员、机械员、测量员、资料员、标准员、取样员。范围外岗位或空白岗位返回 `personnel.unsupported_position`，直接定位 `position_name`；保留来源值，要求人工修正原资料后重新上传。

同时迁入历史模型已有的 12 个字段数值限制：合同工期大于 0 的整数、合同金额非负、人员和风险序号为正整数；WBS 排序为非负整数、层级为 1–100 的整数、进度为 0–100，工期/预计工时/预算/实际成本非负、已记录工时为非负整数。只约束已提供数值，不因此增加可选字段或质量内容的必填规则。

历史独立结构校验的规则已逐项对照：除本次补入的固定岗位外，重复、日期顺序、WBS 结构与循环、质量指标关联均有 MCP 规则。目录一致性在测试中检查，运行时 MCP 不依赖后端规则函数。初始化智能体仍只采集并形成草稿。

未提交的确认凭证在实际入库前须与当前 MCP 包标识及版本一致；升级、换包或无法读取当前版本时拒绝沿用旧凭证，用户重新打开草稿取得当前版本快照。该检查只验证凭证版本，不重新判断资料。已成功提交的幂等重试仍返回原结果。
