# 开发规范

本目录是研发规则入口。用户当前明确要求优先；其他约定与项目实际脚本、模块边界和
内嵌运行环境保持一致。发现文档与实现冲突时，先核对需求和代码，不按旧说明恢复已移除功能。

## 按变更范围阅读

- [代码结构规范](代码结构规范.md)：目录职责、依赖方向与文件规模门禁。
- [前端开发规范](前端开发规范.md)：业务 Vue 前端与 React 管理端的边界和验证。
- [后端开发规范](后端开发规范.md)：API、数据库、权限及集成规则。
- [测试规范](测试规范.md)：测试入口、实际覆盖范围及必要的补充检查。
- [Dobby 工作状态展示](Dobby对话工作状态展示.md)：用户对话过程和工具展示协议。

## 开发环境

- 本项目在 Windows 下开发，Python 必须使用 `python-3.13.14\python.exe`。目录缺失时先恢复，
  不静默换用系统 Python、`py`、Anaconda base 或其他环境。
- 需要 Visual Studio 时使用 VS2022，不尝试 VS2019。
- 没有明确浏览器操作需求时，不擅自调用内置浏览器；需要时先告知用户。
- 网页所有可见文字不得小于 12px。
- Git 提交标题和更新记录使用中文。

## 文档与临时产物

1. 根 [README](../../README.md) 是唯一总入口，一个主题只维护一份现行规则。
2. 普通修复、布局调整和测试执行不新建说明、计划、总结、审计或验收文档。过程和验证结果
   写在任务回复、提交记录中；需要长期维护的行为变化直接修改现有对应章节。
3. 修改旧规则时替换原文，不在文末不断追加“最新调整”。保留版本历史时只写正式发布变化
   和必要升级事项，不记录本机对象 ID、凭证、临时模型绑定、重复测试数字和日志路径。
4. 原始业务资料、尚未实施的设计提案、上游接口参考与运行技能按用途保留，不能混称当前规范。
   模型、字段、接口和门禁阈值优先链接源码，避免手工复制另一套清单。
5. 日志、截图、测试结果、一次性修改器放入被忽略的 `artifacts/` 或 `scratch/`；任务结束后
   清理。正式文档不得依赖这些临时目录中的文件，不为清理工作再生成清理报告。
6. 删除或移动资料前核对 Markdown/HTML 链接、测试样例、运行加载器与打包引用；不得删除
   数据库升级脚本、业务原始材料或程序读取的 `SKILL.md`、Prompt、许可证。

## 变更与交付检查

- 确认所属模块、用户/项目权限、外部副作用和失败处理；写操作保留事务、校验及必要审计。
- 前端处理加载、空态、错误、取消和过期响应；代码放到实际职责所在模块。
- 按测试规范运行与变更相称的检查，说明实际执行范围和未完成项。纯文档整理检查链接、
  删除依赖、忽略规则和差异格式；不为此启动业务服务或执行数据库验收。
- 不提高门禁阈值、跳过测试或删除断言来掩盖失败。
- 提交前检查差异，排除无关用户改动、临时产物、本机路径、密钥和真实业务数据。
- 数据库变更单独交付可审阅的迁移/SQL和适用前置版本；部署不依赖启动时自动建表或迁移。
- 发布包使用预构建前端和完整运行依赖；依据实际清单核对代码、资源、SQL及配置的交付范围。
