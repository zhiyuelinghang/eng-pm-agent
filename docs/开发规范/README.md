# 开发规范

本目录是工程管理智能体项目的研发规则入口。规范与仓库中的实际验证脚本、
模块边界和便携运行环境保持一致；发生冲突时，应先修正实现或脚本，再同步更新文档，
不得让文档长期描述一套无法执行的流程。

## 文档索引

- [代码结构规范](代码结构规范.md)：目录职责、模块拆分原则、文件规模门禁与例外收敛。
- [测试规范](测试规范.md)：统一测试入口、测试分层、选择性回归和失败处理。
- [后端开发规范](后端开发规范.md)：FastAPI、数据库、权限、AgentScope 与 MCP 集成约定。
- [前端开发规范](前端开发规范.md)：Vue/TypeScript 组件边界、状态、样式和验证约定。
- [变更与评审清单](变更与评审清单.md)：开发完成、评审、提交和发布前的检查项。

## 必须遵守的入口

在项目根目录执行完整验证：

```powershell
.\test-all.bat
```

查看或选择测试套件：

```powershell
.\test-all.bat --list
.\test-all.bat --suite structure --suite backend --suite frontend
```

项目后端和 Python 工具默认使用：

```text
<项目根目录>\python-3.13.14\python.exe
```

禁止用系统 `python`、`py` 或 Anaconda `base` 代替项目便携 Python 来判断依赖是否完整。
只有项目明确调整运行方案时，才能切换解释器，并同步修改启动、测试和部署文档。

## 规范优先级

1. 安全、权限和数据完整性要求。
2. 仓库根目录 `AGENTS.md` 及当前任务的明确要求。
3. 本目录开发规范。
4. 各子模块 README 与局部约定。

提交记录必须使用中文。规范自身的修改也必须随实现一起评审，不能用提高规模上限、
删除测试或扩大例外的方式绕过失败。
