# 代码结构规范

## 模块边界

一个模块承担一个可清楚命名的领域职责。路由、业务编排、数据契约、持久化、外部网关
和纯转换逻辑应分层；底层模块不得导入路由或页面来取回状态。

| 入口 | 职责 |
| --- | --- |
| [backend/app/main.py](../../backend/app/main.py) | 应用装配、路由注册和生命周期 |
| [backend/app/api_common.py](../../backend/app/api_common.py) | 鉴权、项目访问校验、序列化与审计 |
| [backend/app/agent_conversations_api.py](../../backend/app/agent_conversations_api.py) | 智能体会话、消息、确认和流式响应 |
| [backend/app/engineering_documents_api.py](../../backend/app/engineering_documents_api.py) | 工程资料与知识库业务入口 |
| [backend/app/chat_api.py](../../backend/app/chat_api.py) | 项目聊天；成员设置另见 `chat_management_api.py`，运行编排见 `chat_agent_runtime.py` |
| [scripts/agentscope_dev_app.py](../../scripts/agentscope_dev_app.py) | 本项目 AgentScope 存储、工具、中间件与后台服务装配 |
| [frontend/src/router/index.ts](../../frontend/src/router/index.ts) | Vue 业务前端路由 |
| [AgentScope/agentscope-web-ui/frontend/src/App.tsx](../../AgentScope/agentscope-web-ui/frontend/src/App.tsx) | React 管理前端装配 |

新路由进入对应领域模块，由应用入口注册；不得把已拆出的智能体会话和工程资料路由
重新放回 `api.py`。数据库交互输入模型放在 `database_interaction_contracts.py`，策略与
受控执行放在 `database_interactions.py`。

业务表结构以 `backend/app/models.py`、`workspace_models.py`、
`database_interaction_assignment_model.py` 和 Alembic 迁移为准。记忆、AgentScope 与任务引擎
各自的存储实现也需随对应变更检查，不另手抄一份完整字段表。

## 前端拆分

通用规则适用于 Vue 业务端和 React 管理端，框架约定见 [前端开发规范](前端开发规范.md)。

- 页面组合组件、状态与用户流程，完整交互区域拆成子组件。
- 页面专用类型与无副作用的树构建、格式化、标签和消息投影逻辑独立存放。
- Vue 流程协调使用 composable，React 使用 hook；不以拆文件为名建立反向依赖。
- Vue 大页面保持外部 scoped CSS；`ProjectSetupView.vue` 的类型、presentation 和样式，
  以及 `AiWorkPlatformView.vue` 的两份样式不得重新内联。
- React 沿用现有组件、hook 与样式组织，不套用 Vue 的 `emit`、Pinia 或 scoped CSS 写法。

## 文件规模检查

在项目根目录执行：

```powershell
.\test-all.bat --suite structure
```

检查范围、默认上限和历史大文件上限的唯一执行依据是
[scripts/check_code_structure.py](../../scripts/check_code_structure.py)，分别见
`_scan_roots`、`DEFAULT_LIMITS`、`TEST_FILE_LIMIT` 和 `FILE_RATCHETS`。

当前扫描业务后端源码与测试、Vue 业务源码、根目录脚本、MCP 源码与测试及包根 Python
文件；不扫描 AgentScope、`utils`、根目录 `tests` 和前端 `.mjs` 测试。通过检查只代表这些
范围通过，不等于全仓库都满足规模规则。

历史文件上限只降不升。新增文件不得加入例外；合理变更触及上限时，应提取领域模块、
子组件、契约或纯函数，不得提高数字使检查通过。未被脚本覆盖的代码仍须遵守模块边界。

出现多个无关领域、类型堆积、跨层取状态或小改动频繁引发无关冲突时，应评估拆分。
按领域和依赖方向拆分，不机械按行数切片，不创建 `utils2`、`common_new` 等杂物模块。

## 依赖与生成物

推荐依赖方向：路由/页面 → 业务编排 → 领域服务/网关 → 数据模型或外部服务。
纯转换与契约不可反向导入路由/页面；外部服务调用统一封装，浏览器不持有服务端密钥。

构建产物、缓存和运行数据不作为源码提交，除非发布流程明确要求。一次性开发脚本和
检查结果在任务完成后清理；数据库版本迁移属于长期运行资产，不能按临时脚本删除。
文档维护遵循 [开发规范入口](README.md)，优先更新已有职责明确的文档。
