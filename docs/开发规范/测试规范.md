# 测试规范

## 统一入口与覆盖范围

在项目根目录执行：

```powershell
.\test-all.bat --list
.\test-all.bat --suite structure --suite backend --suite frontend
.\test-all.bat --keep-going
```

不指定 `--suite` 时执行全部已登记套件；`--keep-going` 在失败后继续并汇总结果。
脚本固定使用内嵌 Python，套件的执行依据是
[scripts/run_project_tests.py](../../scripts/run_project_tests.py)。

| 套件 | 当前内容 |
| --- | --- |
| `structure` | 源码规模与拆分边界，扫描范围见 [代码结构规范](代码结构规范.md) |
| `backend` | `backend/tests` 的平台 API、数据库和集成测试 |
| `agentscope` | `AgentScope/tests` 的 Python 集成测试 |
| `task-engine` | 任务引擎源码测试 |
| `wecom-notify` | 企业微信 MCP 源码测试 |
| `interactive-data-modeling` | 数据建模 MCP 源码测试 |
| `frontend` | Vue 业务端 Node 测试、类型检查和生产构建 |
| `*-smoke` | 数据建模、附件解析、初始化核验、任务引擎、企业微信五类发布包冒烟 |

统一入口**不包含**根目录 `tests/`，也不包含 React 管理端的测试、lint 和构建。
“全部已登记套件通过”不能写成“仓库所有测试通过”。发布时执行全部已登记套件，并对
涉及的上述范围补充检查；普通开发按影响选择套件。纯文档修改检查内容、链接和差异。

## 未纳入统一入口的检查

修改 React 管理端时，在 `AgentScope/agentscope-web-ui/frontend` 执行：

```powershell
pnpm exec node --test tests/*.test.mjs
pnpm run lint
pnpm run build
```

业务 Vue 前端的 `npm run check` 已组合 Node 测试与 `npm run build`，后者包含
`vue-tsc --noEmit` 和 Vite 构建。管理端构建使用 `tsc -b` 与 Vite。两套命令分别以各自
`package.json` 为准，不相互替代。现有 Node 测试不等于完整浏览器交互或 E2E 覆盖。

根目录测试及单个 Python 用例通过显式源码根入口运行，例如在项目根目录执行：

```powershell
.\python-3.13.14\python.exe .\scripts\pytest_entry.py --prepend . -- tests -q
.\python-3.13.14\python.exe .\scripts\pytest_entry.py --prepend . -- backend\tests\test_database_interactions.py -q
```

AgentScope 用例追加 `--prepend AgentScope`；MCP 用例追加对应包的 `src` 根目录。
不要运行裸 `pytest`，便携 Python 的路径隔离可能造成与业务无关的导入错误。

## 用例与测试数据

- 单元测试覆盖纯函数、输入校验、状态转换、权限和错误映射；外部客户端通过 mock 控制。
- 路由测试覆盖成功、未认证、无权限、资源不存在和无效输入，项目资源验证跨项目拒绝。
- 写操作验证事务结果及必要审计、通知等副作用；patch 指向依赖实际使用的模块。
- 回归修复补充能复现缺陷的用例，不为低影响文字修改或实现细节重复新增测试。
- 集成测试使用独立临时目录、内存数据库或明确的测试 Schema，不使用生产数据库。
- 不读取或覆盖 `data` 下的生产/人工数据；发布包构建缓存按冒烟脚本约定使用。
- 正式包冒烟检查 ZIP/运行目录，不只检查源码导入；默认不向真实渠道发消息。
- 单独的部署探测、迁移和安装脚本可能访问配置服务或写数据库，不能当作普通单元测试随意执行。

## 失败处理与结果说明

先定位失败套件的首个根因，再缩小到单文件或用例。修复实现或环境问题，不删除断言、
扩大超时或跳过测试来掩盖失败。目标套件通过后检查受影响的相邻范围；没有新变更或
未解决疑点时，不重复运行同一批检查。

结果直接在任务交付中说明执行范围、通过情况和未完成项，不为每次测试另建报告文件。
历史测试数字不能证明当前代码通过。已知第三方警告可说明后处理，新资源泄漏、未等待
协程或未关闭连接需定位原因。
