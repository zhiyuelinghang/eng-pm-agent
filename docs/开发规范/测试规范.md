# 测试规范

## 1. 统一入口

项目根目录的唯一完整验证入口是：

```powershell
.\test-all.bat
```

它固定调用项目便携 Python 和 `scripts/run_project_tests.py`。不要直接运行裸 `pytest`：
便携 Python 的 `python313._pth` 有意隔离当前目录，直接运行可能因源码根目录未显式加入
`sys.path` 而产生与业务无关的导入失败。

常用参数：

```powershell
# 查看全部套件
.\test-all.bat --list

# 只跑一个或多个套件
.\test-all.bat --suite backend
.\test-all.bat --suite structure --suite backend --suite frontend

# 一个套件失败后继续，最后统一列出失败项
.\test-all.bat --keep-going
```

## 2. 标准套件

| 套件 | 内容 |
| --- | --- |
| `structure` | 源码规模棘轮与关键模块边界 |
| `backend` | 工程管理平台 FastAPI、数据库和集成测试 |
| `agentscope` | AgentScope 服务、编排、工具和权限测试 |
| `task-engine` | task-engine 源码测试 |
| `wecom-notify` | 企业微信通知 MCP 源码测试 |
| `interactive-data-modeling` | 交互式数据建模 MCP 源码测试 |
| `frontend` | Vue TypeScript 类型检查与生产构建 |
| `*-smoke` | 五个正式 MCP 发布包的构建/协议/降级冒烟 |

套件名称以 `--list` 输出为准。完整验证必须包含结构检查、所有源码测试、前端检查和发布包
冒烟；不能用单个目录的测试通过代替项目级结论。

## 3. 单目录 Pytest

需要诊断单个测试文件时，仍应通过显式源码根入口运行：

```powershell
.\python-3.13.14\python.exe .\scripts\pytest_entry.py `
  --prepend . `
  -- backend\tests\test_database_interactions.py -q
```

MCP 子项目还应追加自己的 `src` 根目录。日常优先使用 `--suite`，只有定位失败时才直接
调用 `pytest_entry.py`。

## 4. 测试分层

### 单元测试

- 覆盖纯函数、Schema 校验、状态转换、权限分支和错误映射。
- 不访问真实网络、生产数据库或真实企业微信 Webhook。
- 时间、随机数、外部客户端和任务引擎应通过依赖或 mock 控制。

### 路由与集成测试

- 至少覆盖成功、未认证、无权限、资源不存在和无效输入。
- 项目级资源必须验证跨项目访问被拒绝，不能只验证管理员成功路径。
- 数据库写操作应验证提交结果、关联约束、审计或通知副作用。
- patch 目标应指向“实际使用该依赖的模块”，模块拆分后同步修改 patch 路径。

### 前端检查

`frontend` 套件当前执行：

```powershell
npm run check
```

该命令包含 `vue-tsc --noEmit` 和 Vite 生产构建。它能发现类型、模板和打包错误，但不等于
交互已被自动测试。新增关键交互时，应补组件测试；登录、项目初始化、任务流和资料权限等
核心链路后续接入 E2E 时，也必须加入统一入口。

### 发布包冒烟

- 冒烟验证正式 ZIP/运行目录，而不仅验证源码导入。
- 默认不向真实第三方服务发送消息或写生产数据。
- 子进程必须使用发布包内约定的解释器和相对路径，不能依赖开发机 `PYTHONPATH`。

## 5. 失败处理

1. 记录失败套件和首个根因，不把后续连锁错误当作多个独立问题。
2. 先用对应 `--suite` 稳定复现，再缩小到单文件或单用例。
3. 修复实现或测试环境根因；禁止删除断言、扩大超时或跳过测试来获得绿色结果。
4. 目标套件通过后，执行受影响的相邻套件。
5. 交付前运行一次 `test-all.bat --keep-going`，确认没有被提前退出隐藏的失败。

已知第三方弃用警告可以记录后分期处理；新的业务警告、资源泄漏、未等待协程或未关闭连接
不得无说明进入基线。

## 6. 测试数据

- 测试使用独立临时目录、内存数据库或明确的测试 Schema。
- 不读取或覆盖 `data` 下的生产/人工数据，发布包缓存除外。
- 测试名称应描述行为和结果，不仅重复函数名。
- 回归缺陷必须先形成可失败用例，再修复实现。
