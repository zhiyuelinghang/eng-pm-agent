# Dobby 对话工作状态展示

## 用户可见行为

聊天按原顺序保留思考、每条调用记录和回答。思考生成时展开，结束后默认收起，用户
可随时查看；历史记录遵守相同规则。调用记录使用中文工作描述和真实执行状态，
隐藏函数名、参数和原始返回值。协作及下级记录保留，但不复制内部邀请参数。
工具结果通过助手答复与附件呈现，工作提示不能替代逐条记录。

项目初始化不创建执行计划，直接显示草稿分区与专家真实进度。其他场景已有执行计划时，
必须保留结构化待办列表、每项状态、完成进度，以及已有的负责人和前置任务。
任务创建与更新记录不能替代任务列表；实时更新与刷新后的历史恢复使用相同数据。
没有本轮任务操作的普通聊天，不展示无关的内部任务上下文。

运行中与历史回复底部均显示总耗时、实际模型、已输出字符数和服务端返回的 Token 用量。
协作未完成时在底部列出正在等待的专家；不能将已结束成员显示为等待。
团队成员概览放在正文之后、运行统计之前，默认展开；只有一位专家也必须显示。
实际模型名称随运行端原始消息持久化，不依赖浏览器一直连接或平台流式收尾。
刷新后同时恢复停止按钮、会话内容和服务端运行状态，持续同步至终态，不能只轮询草稿。
面向用户的正文进度、协同反馈与最终答复默认使用简体中文。

草稿核验的错误和提醒直接放在对应记录的字段单元格内，不再展示集中问题列表。
必填字段即使为空也保留字段位置和具体原因；问题资料须由用户修改原始文件后重新上传，
重新核验后才能确认入库。不提供对话修正按钮，也不自动向对话框填入修正请求。
核验失败与重新核验入口仍可见，有错误的记录继续阻止入库。
WBS 使用连续层级连线、逐级缩进、父节点强调与展开收起；补充字段不能截断左侧树路径。
人员按身份证归组，姓名和身份证显示一次，名下岗位连续展示且独立勾选、保留字段问题。
同名但身份证不同或身份证缺失的记录不自动合并。账号与初始密码只在每个人的全部岗位
下方显示一套，不另设账号列表。新人员在预览时自动生成，
确认提交后创建账号，初始密码默认明文显示；已有账号直接显示沿用信息。一人多岗按身份共用同一套凭据，
修改账号或重生成密码须同步到该人员的全部岗位；只读用户不展示初始密码。
字段缺失不能阻止 MCP 检查其余有效记录；取消勾选只影响本批提交，不隐藏原草稿问题。
业务缺失或冲突交给用户核对，不得自动删掉问题记录来获得“通过”。
草稿卡片在本轮整理和核验结束后才出现；出现或折叠时保留用户原来的跟随滚动状态。

停止直接中断主会话、团队所有成员和后台任务，不等待历史查询。全员并发取消，
中断状态保存后，成员取消收尾不再触发正常协同上报；已入队的协同唤醒也不能恢复
用户停止的会话。只有用户停止后发送的新消息可以开启下一轮，历史同步不能锁住输入框。
中断指令先同时发给全队，记录归档与临时会话清理随后在后台完成，不阻塞停止接口。
重复取消不能再次打断中断记录的保存。

邀请协同后必须能看出成员、所属团队、分配任务和真实处理状态。成员工作记录归入
对应的可折叠详情，不能平铺成看不出归属的普通工具记录；下级反馈必须保留来源。
按原调用位置显示，使用会话和任务版本隔离，不能把后一次任务结果带入前一次邀请。
结构化任务内容与成员反馈属于用户可见结果，隐藏内部参数不能成为删去这些信息的理由。

失败显示简洁原因，不展示错误堆栈。没有结果时明确说明。需要业务确认时，展示服务端
提供的对象、影响和前后变化，并保留回复标识和确认版本；缺少可读预览时不能盲目确认。
旁观者只查看，停止中或停止后不再提供可执行确认按钮。

## 展示描述的来源

工具注册信息提供 `presentation = {label, source, category}`，执行状态来自实际事件。
业务前端不维护第二套名称表，也不从函数名、SQL、参数或返回值猜测工作内容。

- 普通工具使用 `display_name`。
- MCP 使用 `Tool.title`，缺失时使用 `annotations.title`。
- 数据库交互使用目录的业务 `display_name`。
- 无有效标题时，按已知来源和只读属性显示通用提示；展示描述不参与权限判断。
- 记忆读取/查询显示“回顾相关信息”，保存显示“记下重要信息”，标题由轻量元数据共用。

Toolkit 在已有目录查询完成后建立本次调用快照；发送开始事件时只读内存，不额外调用
模型、发现 MCP 或访问数据库。模型提供的同名字段不能覆盖注册信息。

## 实时、历史与恢复

每轮智能体回复占满所属聊天布局的可用宽度上限，不能按当前文字长度收缩。
展开或收起思考、计划和协作详情只改变高度；滚动区域预留滚动条位置，避免宽度跳动。

`TOOL_CALL_START.presentation` 写入 `ToolCallBlock.presentation`，随消息 JSON 保存；
协作进度、待确认与恢复上下文保留同一快照。过去的真实快照不随工具改名或卸载重算。

旧消息缺少快照或只有通用描述时，历史接口可按当前工具注册、缓存 MCP 目录和数据库
业务目录补齐，标记为 `catalog_backfill`；不改写原始消息和执行结果。目录故障或来源
不明确时使用通用描述，不能阻断历史读取。目录按登录用户和智能体隔离缓存。

记忆历史标题不依赖记忆运行模块的加载时机；历史别名只服务展示，不能触发模型、
记忆服务或远程目录查询。新增工具在注册位置补充标题，避免前端补丁。

成员结算和团队清理前，运行端须将真实进度归档到成功分配任务的消息。归档同时校验
父会话、消息、工具调用、团队、成员会话、智能体和任务版本；多轮会话不能互借进度。
仅保存允许公开的状态、时间和最近活动，不保存原始参数、工具输出或内部正文。
历史读取需合并该归档，即使平台未收到实时事件也能恢复；已清除且没有归档的旧活动
不得编造补齐。并发保存及元数据更新须保留归档，且不得重建已删除消息或降级旧任务终态。
