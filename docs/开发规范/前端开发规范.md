# 前端开发规范

## 范围与验证

本项目有两套前端：

| 目录 | 技术栈 | 验证入口 |
| --- | --- | --- |
| `frontend` | Vue 3、TypeScript、Naive UI、Pinia、Vue Router、Vite | 根目录 `test-all.bat --suite frontend` |
| `AgentScope/agentscope-web-ui/frontend` | React、TypeScript、Tailwind CSS、Radix UI、Vite | 本目录 Node 测试、lint、build，需单独执行 |

技术版本与命令以各目录 `package.json` 为准，完整命令见 [测试规范](测试规范.md)。
根目录 `frontend` 套件包含业务端测试、类型检查和构建，不包含 React 管理端。
下列类型、权限、交互和可访问性规则适用于两套前端，框架专属要求单独注明。

## 页面与状态

- 页面负责路由级数据装配和流程协调；完整的表单、列表、弹窗或消息区域拆成子组件。
- Vue 通过 props/emit 协作，复杂流程使用 composable；React 通过 props/回调协作，
  复杂流程使用 hook。子组件不修改父组件私有状态。
- 无副作用的转换、格式化、消息投影和复杂判断提取为可测试函数。
- 禁止新增无说明的 `any`。外部响应先定义 API 类型，在边界校验或归一化。
- Vue 的跨页面共享状态使用现有 Pinia store；React 沿用现有 context/hook。弹窗和
  输入等临时状态留在组件，不重复保存可推导的数据。
- 请求区分加载、成功、空数据、失败和取消；并发请求防止旧响应覆盖新状态。

## API 与权限

- 请求通过各前端的 `src/api` 封装，认证与错误归一化不散落在组件中。
- 前端权限控制体验，后端是权限最终裁决者。
- 服务令牌、Webhook、数据库连接和服务端凭证不放入前端构建环境变量。
- 流式响应处理断线、用户取消、部分消息、工具确认与最终状态对账。
- 产品界面展示用户所需的业务信息，不把开发实现或调试说明塞进操作流程。

## 样式与可访问性

- 两套前端的文字均不得小于 **12px**，包括辅助说明、标签、表格和图表文字。
- Vue 大页面使用外部 scoped CSS；React 沿用现有 Tailwind、组件及样式变量体系。
- 复用全局设计变量，不在多个组件复制颜色、间距和层级常量。
- 可点击元素具备键盘操作、可见焦点和正确语义，优先使用原生按钮。
- 表单有可读标签，错误靠近字段，不只通过颜色表达状态。
- 弹窗和抽屉管理焦点，关闭后返回触发元素。
- 响应式布局检查常用桌面宽度与窄屏，避免固定宽度造成横向溢出。

## 拆分与测试

`ProjectSetupView.vue` 与 `AiWorkPlatformView.vue` 保持类型、纯展示逻辑和样式外置；
新增完整交互区域优先提取子组件或 composable，规模要求见 [代码结构规范](代码结构规范.md)。

对行为变更执行受影响的现有测试；回归修复补充能复现问题的用例，关键交互覆盖输入、
事件、空态、失败与权限分支。类型检查和构建不能替代交互验证。纯文案、文档等低影响
修改检查内容与链接，不为重复实现细节新增测试。
