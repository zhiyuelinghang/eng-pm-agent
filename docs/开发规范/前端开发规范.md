# 前端开发规范

## 1. 技术与入口

前端使用 Vue 3、TypeScript、Pinia、Vue Router、Naive UI 和 Vite。验证入口：

```powershell
cd frontend
npm run check
```

项目级开发优先执行：

```powershell
.\test-all.bat --suite structure --suite frontend
```

`npm run check` 必须同时包含 TypeScript/Vue 类型检查和生产构建，不能只验证开发服务器能打开。

## 2. 页面与组件

- 页面组件负责路由级数据装配和流程协调，不承载所有表单、列表、弹窗和消息流实现。
- 能单独命名、复用、测试或形成完整视觉区域的内容拆为子组件。
- 多步骤、有取消/重试/轮询状态的流程优先抽为 composable。
- 组件输入使用 `props`，结果使用 `emit`；不要让子组件直接修改父组件私有状态。
- 模板中的复杂判断和多层映射转为有名称的 computed 或纯函数。

## 3. 类型与状态

- 禁止新增无说明的 `any`。外部响应先定义 API 类型，再在边界处校验或归一化。
- 页面专用类型放在页面同名目录的 `types.ts`，跨页面领域类型放入 `src/types`。
- Pinia 保存跨页面、跨组件或需持久化的状态；临时弹窗和输入状态留在组件/composable。
- 不重复维护可从现有状态计算出的字段，使用 `computed` 保持单一数据源。
- 请求状态至少区分加载、成功、空数据、失败和取消；并发请求应防止旧响应覆盖新状态。

## 4. API 与权限

- API 调用经 `src/api` 客户端封装，认证和错误归一化不散落在组件中。
- 前端权限只控制体验，后端仍是权限最终裁决者。
- 不把服务令牌、Webhook、数据库连接或 AgentScope 管理凭证放入浏览器环境变量。
- 流式响应必须处理断线、用户取消、部分消息、工具确认和最终状态对账。

## 5. 样式与可访问性

- 大页面使用外部 scoped CSS；同一页面的明显视觉领域可以拆成多个样式文件。
- 复用的设计变量放入全局 token，不在多个组件复制颜色、间距和层级常量。
- 可点击的非按钮元素必须具备键盘操作、可见焦点和正确语义；优先使用原生按钮。
- 表单控件有可读标签，错误信息靠近字段，不只通过颜色表达状态。
- 弹窗和抽屉打开后管理焦点，关闭后把焦点返回触发元素。
- 响应式布局至少验证常用桌面宽度和窄屏，不以固定像素宽度制造横向溢出。

## 6. 大页面拆分

`ProjectSetupView.vue` 和 `AiWorkPlatformView.vue` 采用规模棘轮管理。修改这些页面时：

1. 类型放入页面目录 `types.ts`；
2. 树构建、格式化、标签和 API 投影放入纯 presentation 模块；
3. 样式保持外置；
4. 新增完整交互区域时优先创建子组件/composable；
5. 不得提高棘轮来容纳新逻辑。

默认 Vue 文件上限和历史棘轮见 [代码结构规范](代码结构规范.md)。

## 7. 测试

- 纯函数提取后应易于单元测试，避免依赖 DOM 或 store 才能验证格式转换。
- 关键组件覆盖输入、事件、加载、空态、失败和权限状态。
- 修复交互回归时先补能复现问题的测试。
- 类型检查和构建通过不代表交互正确；涉及关键业务链路时应补组件或 E2E 验证。
