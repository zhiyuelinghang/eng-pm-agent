# 变更与评审清单

## 开发前

- [ ] 已确认变更所属领域和正确模块，没有把新职责塞入最近的巨型文件。
- [ ] 已确认权限、数据范围、外部副作用和失败回退要求。
- [ ] Python 任务使用项目内嵌 `python-3.13.14\python.exe`。
- [ ] 没有把构建缓存、运行数据或第三方依赖当作业务源码修改。

## 实现中

- [ ] 路由、业务逻辑、契约、纯转换和外部网关的依赖方向清楚。
- [ ] 新增项目资源访问包含成员/管理员权限校验和跨项目隔离。
- [ ] 新增写操作有输入校验、事务边界、错误映射和必要审计。
- [ ] 前端处理加载、空态、失败、取消和并发响应。
- [ ] 新增大段类型、样式或纯函数已放到对应独立模块。
- [ ] 没有提高结构棘轮、删除断言或跳过测试来掩盖问题。

## 自测

- [ ] 已执行受影响的最小套件并确认失败原因已消失。
- [ ] 已执行 `test-all.bat --suite structure`。
- [ ] 后端变更已执行 `--suite backend`。
- [ ] 前端变更已执行 `--suite frontend`。
- [ ] AgentScope/MCP 变更已执行对应源码测试和发布包冒烟。
- [ ] 交付前已执行 `test-all.bat --keep-going`，确认所有套件结果。

## 代码评审

- [ ] 文件名和模块职责能从名称理解，没有循环依赖或跨层反向导入。
- [ ] API 状态码、错误文案和数据结构稳定，兼容性变化有说明。
- [ ] 日志和响应不泄露密码、令牌、身份证号、路径或附件敏感内容。
- [ ] mock/patch 指向依赖实际使用位置，不因模块拆分产生假通过。
- [ ] 测试覆盖成功、权限拒绝、无效输入和外部失败等关键分支。
- [ ] 文档、脚本和实现保持一致。

## 提交与交付

- [ ] Git 提交标题和更新记录使用中文，说明“改了什么”和“为什么”。
- [ ] 不提交无关用户改动、临时脚本、测试缓存和本地密钥。
- [ ] 数据库变更附带可审阅 SQL/迁移与回滚说明，不依赖应用启动自动迁移。
- [ ] 发布前确认生产包使用构建产物和内嵌运行时，不依赖服务器全局环境。

推荐提交标题示例：

```text
重构：拆分工程资料与智能体会话路由
测试：统一项目级回归与发布包冒烟入口
文档：补充前后端开发和评审规范
```
