# 后端开发规范

## 运行与源码入口

Python 环境统一遵循 [开发规范入口](README.md)，使用项目内嵌解释器。业务后端使用
FastAPI、Pydantic 和 SQLAlchemy；标准部署的 `DATABASE_URL` 必须显式指向 PostgreSQL。
模型调用复用 AgentScope 管理端的配置，不另设一套平台模型凭证。

- 路由按业务领域建立 `APIRouter`，由 `backend/app/main.py` 装配。
- 路由完成输入解析、权限入口、业务调用和响应转换，不堆积跨领域算法。
- 公共鉴权、项目校验和审计使用 `api_common.py`；AgentScope 上下文和消息投影复用
  `agent_api_support.py` 等已有领域模块。
- 新增接口同步明确输入输出契约、权限、错误语义与必要测试。
- 本项目 AgentScope 装配位于 `scripts/agentscope_dev_app.py`；框架与平台改动需分别检查
  对应调用方和测试，不能仅凭业务 API 测试通过判断集成完整。

## 权限与安全

- 项目资源通过当前用户、项目成员关系或明确管理员策略校验后查询和操作。
- 查询包含 `project_id` 或等价可信上下文，禁止只凭全局资源 ID 访问其他项目。
- 管理员能力显式校验，不仅依赖前端隐藏按钮。
- 外部 ID、文件路径、附件、知识库文档 ID 和任务 ID 均视为不可信输入。
- 文件访问先解析并确认目标位于允许目录，防止路径穿越。
- 不向浏览器返回密码哈希、服务令牌、Webhook 或可还原密钥。
- Agent/MCP 只获得受控业务能力，不暴露任意 SQL、任意 HTTP 或宿主命令执行。

401 表示未认证，403 表示无权限，404 表示当前权限范围内资源不存在，422 表示输入
不可接受。不要用统一 500 掩盖可预期业务错误。

## 数据库与事务

- 平台业务访问使用 SQLAlchemy Session 和模型，业务输入不得拼接原始 SQL。
- 完整校验后提交；需原子性的多步写入放在同一事务。
- 数据库异常映射为稳定业务错误，日志保留诊断信息并脱敏。
- Schema 变更提供可审阅迁移和生产 SQL，平台启动不得静默迁移生产表。
- 业务模型与迁移是字段事实来源，具体入口见 [代码结构规范](代码结构规范.md)。
- 生产 SQL 目前需随版本单独交付，不能假定代码压缩包已包含它；执行和备份流程见
  [服务器部署说明](../../服务器部署说明.md)。

数据库交互输入模型位于 `database_interaction_contracts.py`，策略与执行逻辑位于
`database_interactions.py`。直接暴露给智能体的写交互固定要求人工确认，并限制可写
字段、项目范围与角色。仅供 MCP/工作流内部使用的交互，须在限定会话类型和可信上下文
绑定下执行；这类内部授权不能放宽普通对话的写权限。

## 外部服务、类型与日志

- AgentScope、任务引擎、WeKnora 和企业微信通过客户端或网关封装。
- 明确连接/读取超时、错误映射和必要重试；流式长响应不用普通短读取超时。
- 后台任务可停止，数据库会话、HTTP 客户端与异步任务正确关闭。
- 公共函数和复杂结构使用类型标注；边界模型校验后仍需检查业务状态与权限。
- 仅捕获可处理的异常，不无记录吞掉未知异常。
- 日志保留请求、项目和任务等追踪标识，令牌、密码、身份证号及附件内容脱敏。
- 用户可见错误使用稳定中文说明，内部日志保留技术根因。

## 验证

行为变更从受影响的测试开始。业务后端通常执行：

```powershell
.\test-all.bat --suite structure --suite backend
```

涉及 AgentScope、MCP 或未纳入统一入口的测试时追加对应检查；发布验证范围及数据库
测试边界见 [测试规范](测试规范.md)。纯文档修改检查事实、链接和差异，不启动服务或
连接数据库来验证文字。
