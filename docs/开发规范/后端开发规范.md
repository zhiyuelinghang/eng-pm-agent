# 后端开发规范

## 1. 运行环境

后端、脚本和 Pytest 默认使用项目便携解释器：

```powershell
.\python-3.13.14\python.exe
```

不得用系统 `python`、`py` 或 Conda `base` 判断项目依赖状态。项目存在内嵌 Python 时优先
使用内嵌环境；只有依赖确实冲突且任务明确需要时，才检查现有 Conda 环境或申请新环境。

## 2. FastAPI 路由

- 按业务领域建立 `APIRouter`，由 `backend/app/main.py` 统一装配。
- 路由函数只完成输入解析、权限入口、业务调用和响应转换，不堆积跨领域算法。
- 公共响应、鉴权、项目成员校验和审计使用 `api_common.py`。
- AgentScope 消息投影与上下文构建使用 `agent_api_support.py`，不要复制到多个路由模块。
- 新增接口同时定义 Pydantic Schema、权限规则、错误语义和路由测试。

## 3. 权限与安全

- 所有项目资源先通过当前用户和项目成员关系校验，再按资源 ID 查询或操作。
- 管理员能力必须显式校验，不能仅依赖前端隐藏按钮。
- 外部 ID、文件路径、附件、知识库文档 ID 和任务 ID 都视为不可信输入。
- 文件访问先解析并验证目标仍位于允许目录，禁止路径穿越和任意绝对路径。
- 不向浏览器返回密码哈希、服务令牌、Webhook 或可还原密钥。
- Agent/MCP 工具只能获得业务语义能力，不暴露任意 SQL、任意 HTTP 或宿主命令执行。

401 表示未认证，403 表示已认证但无权限，404 表示当前权限范围内资源不存在，422 表示
结构或业务输入不可接受。不要用统一 500 掩盖可预期业务错误。

## 4. 数据库与事务

- 数据库访问通过 SQLAlchemy Session 和模型完成，业务输入不得拼接原始 SQL。
- 写操作在完整校验后提交；需要原子性的多步修改放在同一事务。
- 数据库异常应映射为稳定业务错误，日志保留诊断信息但不泄露密钥和个人敏感数据。
- Schema 变更必须提供可审阅 SQL/迁移方案；平台启动不得静默创建或迁移生产表。
- 项目范围查询必须包含 `project_id` 或等价可信上下文，不允许先按全局 ID 读取后再补权限。

数据库交互白名单的输入模型位于 `database_interaction_contracts.py`；策略目录和执行逻辑位于
`database_interactions.py`。新增写交互必须要求人工确认并限制可写字段、作用域和角色。

## 5. 外部服务与 AgentScope

- AgentScope、任务引擎、WeKnora、企业微信等调用通过客户端或网关模块封装。
- 明确设置连接/读取超时、错误映射和必要的重试；流式长响应不能误用普通短读取超时。
- 单元测试 mock 网关，不连接真实外部服务。
- 服务端密钥只从配置读取，不写入源码、日志、前端或测试快照。
- 后台任务必须可停止并正确关闭数据库会话、HTTP 客户端与异步任务。

## 6. 类型、错误与日志

- 公共函数和复杂局部结构使用类型标注；不以大范围 `Any` 逃避接口设计。
- Pydantic 模型负责边界校验，领域函数仍需验证数据库状态和权限条件。
- 捕获异常时只捕获可处理的具体异常；不得无记录吞掉未知异常。
- 日志包含请求/项目/任务等可追踪标识，但对身份证号、令牌、密码和附件内容脱敏。
- 用户可见错误使用稳定中文说明，内部日志保留技术根因。

## 7. 验证

后端变更至少执行：

```powershell
.\test-all.bat --suite structure --suite backend
```

涉及 AgentScope 或 MCP 时追加对应源码套件和发布包冒烟。交付前仍需执行完整统一验证。
