智能体管理中心
全局操作说明

从模型凭证、智能体创建、能力分配，到项目初始化、平台职责和审计，一份手册走完整个管理流程。无需提前理解 MCP、ReAct 或权限模型。

适用对象：平台管理员、智能体配置人员、业务负责人 适用版本：当前探索版 建议阅读：首次 15 分钟，日常按目录查阅

Quick start

10 分钟完成第一次可用配置

首次配置可按以下 5 步完成基础验证。模型凭证是创建可用智能体前必须完成的基础配置。

1添加凭证配置模型 API，并拉取或手动添加模型。
2创建智能体填写名称、系统提示词，选择固定模型。
3分配能力勾选 MCP、数据库交互、知识库和协同范围。
4创建会话点击 Create Session，发送一条真实任务。
5确认发布需要业务端使用时，再启用并发布为业务智能体。
✓
首次测试建议

建议创建一个暂不发布的测试智能体，首次仅分配一项能力。会话验证成功后再逐项增加能力，便于准确定位配置问题。

Workspace

工作台的四个区域

日常管理主要在对话工作台完成，操作结构为“左侧选择对象、中间测试会话、右侧配置能力”。

① 全局导航对话、审计、平台设置、日程、凭证、知识库、语言与新手引导。
② 智能体与会话切换智能体、创建 Agent、创建/选择会话。
③ 对话区发送任务、上传附件、查看计划时间线、协同过程和结果。
④ 能力侧栏MCP、技能、数据库交互、工具、知识库、协同智能体。
?
功能入口查找

将鼠标悬停在右侧标签上可查看用途说明；左下角“指南/罗盘”按钮可以重新启动内置新手引导。

Roles

平台角色与能力范围

智能体的可见范围由名称、平台角色、发布状态和协同设置共同决定。

平台职责

平台总控智能体

承接普通平台对话并分派任务。只能调用“已启用、允许协同、并明确开放给总控”的智能体。

平台职责

项目初始化智能体

工程配置页的固定入口，负责读取项目资料、制定计划、组织专项智能体并形成待核对草稿。

可发布

业务智能体

面向具体业务任务。只有“已启用 + 已发布”的业务智能体才会进入业务端目录。

内部能力

协同智能体

被其他智能体邀请处理专项任务。必须开启“允许被邀请”，并填写清晰的邀请说明。

系统专家

隐藏智能体

不直接出现在业务端，只作为平台职责或内部协同成员使用，适合专业解析、核验、分析等能力。

安全边界

权限审核员

不参与业务会话，仅审核 Auto 权限模式下“需要确认”的操作；拒绝和危险操作不会被绕过。

Step 1

配置模型凭证

没有可用凭证和模型，智能体无法开始对话。入口位于左侧钥匙图标“凭证”。

1

点击“添加凭证”

选择与服务兼容的凭证类型。自定义服务通常选择 OpenAI 兼容方式。

2

填写连接信息

填写名称、API Key 和 Base URL。名称应准确体现用途，例如“生产模型”或“测试模型”，避免使用“key1”等无法识别用途的名称。

3

建立模型目录

优先使用“自动获取”；服务不支持时再“手动添加”。至少配置一个对话模型，之后才可在智能体中固定使用。

4

测试并保存

保存前先测试模型。若启用 Auto 权限模式，再为系统权限审核员绑定独立审核模型。

!
API Key 安全要求

界面会脱敏显示密钥。完整密钥不得写入智能体提示词、截图、日志或会话消息，只能保存在凭证配置中。

Step 2

创建并配置智能体

在对话页左侧点击“创建 Agent”。左侧目录用于快速切换配置分区；首次创建应先完成身份、模型和平台接入配置。

配置分区功能说明首次配置建议
Agent 身份名称用于列表展示；系统提示词定义职责和边界。名称写业务用途；提示词写清“目标、输入、输出、禁止事项”。
模型配置“跟随会话”允许每次选择模型；“固定模型”保证稳定。业务和平台职责智能体优先固定已验证模型。
平台接入配置决定是否运行、发布、被总控调用和在业务端的排序。先启用但不发布；验证通过后再发布。需要业务端展示时填写清晰说明和分类。
上下文配置控制长会话压缩、保留比例和工具结果截断。保持默认。只有确认上下文过长或关键信息丢失时再调整。
ReAct 配置控制一次任务最多循环多少轮，以及拒绝和中断行为。保持默认。复杂任务失败且日志显示迭代耗尽时再增加。
邀请配置开启后才可被其他智能体协同调用；说明会帮助调用方判断何时邀请。专项智能体开启，并明确写“负责什么、需要什么输入、返回什么”。
调用白名单限制当前智能体可以邀请哪些协同成员。总控可按需设为全部；专业智能体建议选择“指定”。
!
“启用”与“发布”的区别

启用表示智能体可以运行；发布表示智能体可以出现在业务端。智能体应在测试完成后再发布，避免向用户展示未完成配置。

Step 3

给智能体分配能力

右侧标签是当前智能体的能力视图。能力是否可编辑取决于类型：有的按智能体分配，有的是平台固定能力。

可分配

MCP

依赖完整的外部能力包。平台统一安装版本，每个智能体通过勾选决定是否装载。

  • 上传后先查看工具清单和说明
  • 勾选需要的包，再点击“保存分配”
  • 删除包会影响所有使用该版本的智能体
可分配

技能

可复用的工作方法、提示和流程说明，指导智能体以固定步骤完成任务。

  • 通过“添加技能”关联当前智能体
  • 点击条目查看；可编辑项使用统一编辑弹窗
  • 名称用于展示，英文标识用于系统识别
可分配

数据库交互

在表白名单和操作范围内读取或写入业务数据，按智能体勾选最小必要权限。

  • 点击整行查看参数和涉及表
  • “只读”和“写操作”必须明确区分
  • 管理端只查看表白名单，不能随意修改治理规则
全局固定

工具

文件读取、搜索、写入、附件解析等系统基础能力。所有智能体可用，仅展示、不可勾选或修改。

  • 点击条目查看具体参数和用途
  • 附件上传后先经过统一解析流水线
  • 固定能力不需要重复分配
可分配

知识库

为智能体提供可检索资料。先在知识库页面创建并导入文档，再回到智能体选择。

  • 适合制度、规范、产品资料和长期知识
  • 临时会话附件应使用附件解析工具，不作为知识库维护
  • 答案仍需由智能体结合当前任务判断
可分配

协同智能体

决定当前智能体可邀请的其他智能体范围：全部、指定或禁用。

  • 被邀请方必须允许被邀请
  • 业务智能体建议使用“指定”
  • 保存后对该智能体后续会话生效

MCP：上传、查看、勾选、保存

MCP 包是可独立升级的能力。上传必须使用平台适配后的依赖完整包；包内应包含正确的清单、启动入口、工具中文名称/英文标识和参数说明。上传成功不等于已经分配，仍需对当前智能体勾选并保存。

技能：把工作方法交给智能体

数据库交互：只分配必要数据能力

!
数据库交互按最小权限分配

总控、初始化助手和业务智能体需要的数据库交互不同。每个智能体仅分配完成职责所需的最小集合，写操作须逐项确认。

系统工具：固定能力，只看不改

协同智能体：控制可以邀请谁

Database tutorial

数据库交互：从零配置到成功调用

数据库交互不是 SQL 编辑器，而是基于表白名单、字段范围和操作类型创建的可分配数据能力。

数据库交互的四层关系

第 1 层

数据表白名单

平台统一决定哪些表、字段和操作可以开放，以及只能访问当前项目、当前用户还是全局数据。

第 2 层

数据库交互

从白名单中选择主表、查询或写入方式、可选关联表和运行边界，形成一项中文可读的能力。

第 3 层

智能体分配

把已经创建的交互勾选给需要它的智能体。未分配的智能体即使知道技术标识也不能调用。

第 4 层

会话运行校验

调用时平台再次核对会话、用户、项目、智能体、权限和字段范围，然后才执行结构化操作。

i
白名单与数据库交互的区别

白名单是平台级安全边界，在智能体管理端只能查看；数据库交互是基于白名单创建的具体能力，可以新增、编辑、删除并分配给智能体。一个白名单可以创建多项不同交互。

开始前的三个检查

1

选择目标智能体

左侧切换到准备使用数据库能力的智能体，再打开右侧“数据库交互”。只读智能体不会显示新增或编辑能力。

2

点击“查看表白名单”

确认目标表已存在，并检查允许操作、可读字段、可写字段、可筛选字段、数据范围和最低角色。该页面仅用于查看，不能临时扩大权限。

3

明确数据操作

在创建交互前，明确“目标主表、筛选条件、返回或修改字段，以及是否需要关联表字段”。需求范围不明确时，应先完成业务规则梳理。

!
“新增交互”按钮不可用

该状态通常表示平台尚未配置数据表白名单，或当前智能体不可编辑。白名单缺失时，由平台维护人员开放目标表；交互配置不能绕过白名单。

实战示例：查询项目任务并返回负责人姓名

只读查询 主表：项目任务 关联表：平台账号 按当前项目隔离

目标：让智能体查询当前项目的任务，并把任务负责人从内部 ID 转换为可读的姓名和账号。

预期调用：用户问“本周有哪些未完成任务，负责人是谁？”时，智能体调用该交互并获得任务信息与负责人名称。

第 1 步：打开新增弹窗

在“数据库交互”标签点击“新增交互”。弹窗左侧目录可以快速跳到基本信息、数据来源、运行边界、关联表、调用参数和运行设置。

第 2 步：填写基本信息

字段示例判断标准
中文名称查询项目任务与负责人名称应以动作开头，让不懂技术的人一眼知道用途。
英文技术标识query_project_tasks_with_owner仅小写字母、数字和下划线，以字母开头；创建后不能修改。
用途说明查询当前项目任务，并返回负责人姓名、账号、状态和截止时间。说明应包含使用时机、返回内容和不能做什么；模型会用它判断何时调用。

第 3 步：选择数据来源和操作

  • 主表白名单：选择“项目任务 · tasks”。下拉框只会出现平台已经授权的表。
  • 允许操作：选择“查询”。下拉框只会出现该白名单允许的操作。
  • 执行来源/数据范围：确认显示为 tasks 和“当前项目”。这意味着平台会自动隔离项目，不需要模型传入项目 ID。
✓
可信上下文安全规则

项目 ID、用户 ID 和会话 ID 不由模型自由填写。平台根据当前会话识别真实范围，伪造或越权的记录会在执行前被拒绝。

第 4 步：配置运行边界

项目本示例选择含义
调用方式智能体直接调用保存并分配后，这项能力会直接出现在智能体可调用工具中。
允许的会话普通、业务仅在勾选的会话类型中装载。是否允许写入仍受平台实际权限约束。
可信上下文绑定无需额外添加主表白名单已经按当前项目隔离。只有还要按当前会话、用户或执行智能体进一步隔离时才添加。

可信上下文绑定选择规则：

  • 限定记录范围：查询和写入都只能命中当前项目、当前会话、当前用户或当前执行智能体对应的记录。
  • 写入时自动填充：仅用于写操作，平台自动把可信值写入目标字段，调用方无法伪造。
  • 白名单已限定为“当前项目”时，无需重复绑定无关字段。

第 5 步：添加关联表

点击“添加关联表”。系统只会提供与当前查询路径存在真实数据库外键、并且已经加入白名单的表。本示例自动找到：

main.assignee_user_id → users.id

字段本示例说明
关联表白名单平台账号目标表必须已经加入平台白名单。
返回别名users结果字段会以 users.real_name 形式出现；别名不能使用 main。
外键关联条件main.assignee_user_id → users.id只能选择数据库真实存在的外键，不允许手写任意连接条件。
保留方式保留主表全部记录即 LEFT JOIN；负责人缺失时任务仍返回。选择“只保留匹配记录”会过滤无负责人任务。
返回字段username、real_name只勾选智能体真正需要看到的字段。
筛选字段按业务需要勾选勾选后模型才能使用该字段做精确筛选或排序。
!
多表关联只用于查询

新增、修改和删除永远只作用于主表，不能在一项写交互中同时修改多张表。需要多步写入时，应拆成多项交互并由智能体或 MCP 工作流按顺序调用。

第 6 步：理解自动生成的调用参数

保存后，平台会根据主表、字段白名单、操作类型和关联表自动生成参数，不需要手写 JSON Schema。

操作常见参数使用规则
查询keyword、filters、fields、order_by、offset、limit只能使用白名单允许返回、筛选和排序的字段；一次最多返回 200 条。
按 ID 查询record_id 或 record_ids两者不能同时使用；批量 ID 有数量上限。
新增values只能传可写字段；项目、用户、会话等绑定字段由平台补充。
修改record_id、values、可选 expected建议先读后改；expected 可防止覆盖别人刚刚修改的数据。
删除record_id只能删除当前授权范围内的单条记录。

第 7 步：保存、分配、测试

1

保存交互

打开“允许分配和调用”。只读敏感数据可额外要求确认；智能体直接调用的写操作固定需要权限审核，不能关闭。

2

在列表中勾选

新建交互会进入全平台目录，但不会自动分配给当前智能体。找到它，勾选复选框并点击“保存分配”。

3

新建会话测试

发送“列出当前项目未完成任务及负责人姓名”。观察是否调用正确交互、是否只返回当前项目数据。

4

按最小权限修正

如果返回字段过多，编辑交互减少字段；如果智能体无需该能力，取消勾选而不是只在提示词中禁止。

写操作配置规则

安全配置顺序

  • 确认主表白名单允许所需的新增、修改或删除操作。
  • 每项交互只做一个明确动作，例如“更新任务状态”。
  • 只开放该动作所需字段，不开放整张表。
  • 把项目、会话、用户、执行智能体等字段设为可信绑定。
  • 创建配套只读交互，使智能体能够按“先读后写”的顺序执行。

运行时仍会检查

  • 当前会话是否允许写入。
  • 当前用户是否属于项目、是否满足最低角色。
  • 记录是否属于当前项目/用户范围。
  • 外键引用是否存在且没有越权。
  • 记录是否已被其他任务修改。

MCP + Database

让 MCP 与数据库交互协同

MCP 不得获得数据库账号、文件路径或任意 SQL 权限。MCP 访问业务数据时统一通过平台数据库交互网关，并受能力分配、会话范围和白名单约束。

协同方式选择

方式 A：由智能体编排 推荐

适用于常规管理配置和普通 MCP。

用户任务›数据库查询›MCP 分析›可选写回
  • 数据库交互选择“智能体直接调用”。
  • 把 MCP 和数据库交互都分配给同一智能体。
  • 模型能看到每一步，过程清楚、容易调试。
  • MCP 包不需要声明数据库平台能力。

方式 B：MCP 内部调用 开发者

适合大量分页、循环处理或需要封装成单个工具的流程。

用户任务›MCP 工具›平台数据网关›结果
  • 数据库交互选择“MCP / 工作流内部调用”。
  • 该交互不会直接暴露给模型。
  • MCP 包声明受控平台能力，通过注入的接口调用。
  • 适合具备 MCP 开发经验并需要封装复杂流程的维护人员。
?
一项交互对应一种调用方式

“智能体直接调用”和“MCP / 工作流内部调用”不能同时生效。需要同时提供两种入口时，应基于同一白名单创建两项不同技术标识的交互，并分别控制分配。

方式 A 实战：数据分析 MCP 读取任务并生成分析

方式 A 配置简单且调用过程完整可见。以下示例假设平台已上传“数据分析与预测建模”MCP：

1

准备只读交互

创建或复用“查询项目任务与负责人”，调用方式选择“智能体直接调用”，并分配给数据分析智能体。

2

分配数据分析 MCP

切换到 MCP 标签，勾选“数据分析与预测建模”，点击“保存分配”。确认详情中能看到需要的分析工具。

3

可选：准备写回交互

分析结果需要入库时，应单独创建仅开放必要字段的写交互。MCP 和智能体不得绕过交互直接更新数据表。

4

配置智能体调用顺序

在智能体说明中配置“先读取数据，再调用 MCP 分析；只有用户确认且存在已分配写交互时才写回”。该顺序由智能体在运行时执行。

5

新建会话验证闭环

让智能体分析当前项目任务延期风险。时间线应依次显示数据库查询、MCP 调用和可选写回确认，MCP 不直接连接数据库。

智能体协同规则示例

当任务需要分析平台数据时，先调用已分配的只读数据库交互获取必要字段，再把结构化结果交给数据分析 MCP。数据量较大时使用分页或 MCP 内部工作流，避免将整张表复制进提示词。需要写回时必须调用独立写交互并经过权限确认。

方式 B 的适用场景

场景建议原因
几十条以内、步骤需要用户看见方式 A调试简单，数据库查询和 MCP 调用都在会话时间线可见。
需要连续分页读取数千条记录方式 BMCP 可以在内部循环读取，避免把大量数据反复写入模型上下文。
同一 MCP 工具内部要读、计算、再读方式 B封装后单次调用更稳定，也不会产生很长的邀请或工具参数。
业务人员临时组合多个能力方式 A无需改 MCP 包，只需要调整智能体分配与说明。
需要原子性地修改多张表设计专用工作流当前交互写操作只允许单表；多表写入需要受控工作流和回滚策略。

方式 B 的平台配置

  1. 新增数据库交互，选择目标白名单和操作。
  2. “调用方式”选择MCP / 工作流内部调用。
  3. 只勾选真正需要的会话类型，配置可信上下文绑定。
  4. 保存后把该交互分配给实际执行 MCP 的智能体。
  5. 把 MCP 也分配给同一个智能体。

MCP 数据访问边界

MCP 不得接收数据库文件路径、账号、连接字符串或原始 SQL。平台会拒绝未分配交互、错误调用方式、越权项目、未授权字段和未开放的写操作，MCP 不能绕过这些边界。

协同配置验收标准

  • 当前智能体的 MCP 列表和数据库交互列表都显示已选，并且已经保存。
  • 新会话中，方式 A 能分别看到数据库交互和 MCP 调用；方式 B 只看到 MCP 工具，但 MCP 返回中没有 401、403 或 404。
  • 换到另一个项目执行同样任务时，只返回该项目数据。
  • 取消数据库交互分配后，MCP 内部调用应立即被 403 拒绝。
  • 写操作会产生权限确认和审计记录，未确认时不会修改业务数据。

Project initialization

项目初始化：MCP、技能和数据库交互如何配合

项目初始化不是由一个 MCP 包独立完成。它是一条受平台控制的流水线：固定附件解析工具负责读文件，初始化技能负责组织工作，专项智能体通过数据库交互写草稿，核验 MCP 只负责最后核验。

i
初始化能力边界

附件解析由平台固定工具执行，流程组织由初始化编排技能负责，草稿读取与写入通过数据库交互完成，最终检查由核验 MCP 执行。核验 MCP 不属于智能体可分配能力，其当前使用版本在“平台设置”中统一选择。

初始化能力职责划分

环节实现方式负责内容配置位置
附件解析 平台固定工具 附件进入模型前先解析；PDF、图片、DOCX、PPTX、XLSX 优先使用 MinerU，失败后使用本地解析；CSV、TXT、Markdown、XLS 直接本地解析。 在“工具”标签中查看。它是全局固定能力，不能勾选、取消或编辑。
流程编排 初始化技能 先创建执行计划，再创建草稿、读取附件分块、邀请相关专项智能体、检查分区完成状态并提交核验。 主智能体的“技能”标签，分配 orchestrate-project-initialization。
专项整理 专项智能体 + 技能 分别整理工程信息、人员岗位、WBS 进度、风险源和质量指标；专项智能体只处理自己的分区。 主智能体“协同智能体”标签，以及各专项智能体的“技能”标签。
草稿读写 数据库交互 读取附件分块、创建草稿、写入各分区、检查分区状态和提交核验。智能体不直接连接数据库。 每个初始化智能体的“数据库交互”标签，按职责分配最小集合。
最终核验 必需的核验 MCP 读取平台组装好的规范化草稿 JSON，快速执行跨分区规则，返回 ready / invalid 和定位到数据行、字段的问题。 “平台设置 → 项目初始化智能体 → 核验 MCP”，选择当前使用版本。
核对与正式入库 平台固定界面 把问题标签展示到准确的数据行和字段；用户核对并确认后，才把草稿写入正式项目表。 工程管理平台的初始化草稿核对弹窗，无需在管理中心分配。

初始化运行流程

上传附件

专项智能体写分区

1

附件接收与解析

用户上传后应立即看到已接收反馈和解析状态。原附件保留用于下载与审计，解析结果按文件和分块保存为临时数据；附件内容不会整段写入模型提示词。

2

创建执行计划与草稿

附件解析预处理结束后，模型的第一个业务动作必须是 TaskCreate。随后主智能体读取初始化状态和附件分块，创建本轮初始化草稿。

3

分配专项整理任务

主智能体根据资料内容邀请本轮需要的专家。邀请参数传递 draft_id、文件 ID 和分块 ID，不传递大段解析文本；专家通过数据库交互分页读取所需分块。

4

写入专项草稿分区

每位专家使用对应技能理解资料，并通过已分配的数据库交互创建或更新对应分区。专项智能体不能写入其他专家分区，也不能直接写入正式业务表。

5

提交草稿核验

主智能体确认所需分区均已完成后，调用 dobby_finalize_project_initialization_draft(record_id=draft_id)。该调用只提交草稿 ID，不把整份草稿重新交给模型。

6

执行核验 MCP

平台通过数据库交互读取并组装规范化草稿 JSON，然后启动“平台设置”中选定版本的核验 MCP。MCP 返回状态以及问题所在的数据记录 ID、字段、说明和处理建议；平台负责持久化结果。

7

人工核对与正式入库

前端在具体行的“核验”列展示问题标签。用户查看问题与建议、修正或确认后，平台才把草稿原子写入正式项目数据。草稿结构规范不代表业务内容已自动确认，人工确认仍为必需步骤。

初始化团队配置步骤

主智能体配置

  1. 进入“平台设置”，选择 Dobby 项目初始化助手。
  2. 回到该智能体的“技能”标签，确认编排技能已分配。
  3. 在“数据库交互”中只勾选初始化状态、草稿、分区、附件分块、创建草稿和提交核验相关交互。
  4. 在“协同智能体”中允许邀请五位专项智能体。
  5. 普通“MCP”标签不分配核验 MCP，也不分配旧版编排 MCP。

专项智能体配置

  1. 每位专家只分配与其职责对应的一项技能。
  2. 共同分配只读的状态、草稿、分区和附件分块交互。
  3. 写操作只分配本专家对应分区的创建和更新交互。
  4. 专项智能体不需要核验 MCP，也不应直接写正式项目表。
  5. 修改分配后新建初始化任务验证，旧会话可能仍保留旧配置。

核验 MCP 版本管理

1

上传新版本

点击“上传新版本”，上传包含运行时和全部依赖的平台适配 ZIP 包。包名可以保持一致，但 mcp.json 中的版本号必须递增。

2

选择使用版本

上传不会自动切换。打开“使用版本”下拉框选择目标版本，再点击页面底部“保存初始化配置”。之后新触发的核验使用该版本。

3

下载和修改

点击“下载所选版本”可取得当前包作为修改基线。修改规则、提升版本号、重新构建后，再作为新版本上传。

4

删除历史版本

在下拉框选择未使用的历史版本后删除。当前正在使用的版本不能删除，必须先切换并保存其他版本。

核验 MCP 与数据库交互的协作机制

平台受控核验流程 采用

平台负责数据权限与结果持久化，MCP 仅运行核验规则。

数据库交互读取草稿›平台组装 JSON›核验 MCP›平台保存问题
  • MCP 输入已经是规范化的草稿数据。
  • MCP 不读取数据库文件，也不持有数据库账号。
  • MCP 返回问题，不直接向数据库写 SQL。
  • 平台用记录 ID 和字段名把问题保存到准确位置。

MCP 直接访问数据库 不支持

核验 MCP 不具备查找或修改业务数据库的权限。

MCP›数据库账号 / 文件›任意 SQL
  • 无法统一控制项目、用户和字段范围。
  • 规则包可能误写正式数据。
  • 升级和审计时无法区分平台行为与包内行为。
  • 不得把连接字符串、数据库路径或令牌写入包内。

核验 MCP 的输入与输出边界固定，规则可以持续升级：

平台输入：{
  "draft_id": "草稿记录 ID",
  "project": {...},
  "personnel": [...],
  "wbs": [...],
  "risks": [...],
  "quality_requirements": [...]
}

MCP 输出：{
  "status": "ready 或 invalid",
  "issues": [{
    "record_id": "草稿中具体数据的记录 ID",
    "field": "具体字段名",
    "label": "问题中文标题",
    "detail": "问题详细说明",
    "suggestion": "处理建议"
  }]
}

初始化流水线验收

验收通过的表现

  • 上传后先出现接收反馈，再显示附件解析过程。
  • 解析预处理后，聊天时间线立即出现执行计划。
  • 协同卡片只说明专家正在处理什么，不展示大段邀请文本。
  • 专家通过数据库交互读取分块并提交各自分区。
  • 最终核验调用显示平台设置中当前使用的 MCP 版本。
  • 问题出现在准确的数据行和字段，可打开查看说明与建议。
  • 用户确认前，正式项目表不会写入初始化数据。

需要排查的异常表现

  • 执行一半后才创建计划：主智能体编排技能缺失或版本不对。
  • 邀请命令包含整份附件文本：没有传递文件和分块 ID。
  • 主智能体自己生成全部分区：专项智能体或数据库交互分配错误。
  • 模型重新读取整份草稿做最终核验：没有走平台核验 MCP。
  • 上传新核验包后仍执行旧规则：未选择新版本并保存。
  • 核验完成后直接正式入库：跳过了用户草稿确认边界。

核验 MCP 的版本规则

上传新版本不会自动切换。上传后应在下拉框选择目标版本并保存；当前正在使用的版本不能直接删除。需要修改规则时，先下载当前版本作为基线，再上传新版本验证。

首次配置或排查完整流程时，请同时参阅“项目初始化：MCP、技能和数据库交互如何配合”。版本选择仅代表核验能力配置，不代表整条初始化流水线已完成配置。

Audit

查看平台交互审计

审计页只读，用于定位“谁、在哪个项目、哪个会话、调用了什么”。不会修改用户会话。

1

选择平台用户

下拉项显示用户名称和账号，先确定具体使用者。

2

选择项目

项目选择框会在用户选定后启用；一名用户可能属于多个项目。

3

选择会话并检查记录

查看完整消息、工具调用、时间和状态。审计页不提供编辑或重放。

Schedule

查看和管理日程

日程页提供日历与列表两种视图，适合查看智能体产生或关联的计划安排。

Troubleshooting

常见问题快速排查

根据实际现象按顺序检查，每次只调整一项相关配置，以便确认问题原因。

创建智能体后无法对话
  • 检查凭证是否保存且模型测试成功。
  • 检查智能体是否启用、是否绑定了可用模型。
  • 固定模型被删除或停用时，重新选择模型并保存。
业务端看不到智能体
  • 平台角色应为“业务智能体”。
  • 同时打开“允许平台运行”和“发布到平台”。
  • 填写平台展示说明和业务分类后再检查目录。
MCP 上传成功，但智能体不会调用
  • 确认当前智能体已勾选该 MCP，并点击“保存分配”。
  • 打开 MCP 详情，确认工具已被正确发现。
  • 新建会话再测试，避免旧会话仍使用旧配置。
  • 检查包是否为依赖完整的平台适配包。
上传 MCP 出现 Failed to fetch

通常是管理中心后端或 AgentScope 服务未启动，或请求地址不可达。确认服务状态后重新上传；该提示不属于包内容校验错误。

数据库交互列表与其他智能体不同

可分配目录应保持一致，但每个智能体的勾选结果可以不同。目录缺项时，刷新页面并检查平台数据库交互服务；已选数量不同符合按职责实施最小权限分配的规则。

新增数据库交互无法保存
  • 检查中文名称和英文技术标识是否填写。
  • 技术标识只能使用小写字母、数字和下划线。
  • 确认已选择主表白名单和允许操作。
  • 至少保留一种允许的会话类型。
  • 关联表别名不能重复，且必须选择返回或筛选字段。
点击“添加关联表”后提示没有可关联表

主表到目标表之间必须存在数据库真实外键，而且两张表都已加入白名单。仅仅字段名称相同不能建立关联；请让数据库维护人员补充外键或调整数据模型。

数据库写操作不可用
  • 确认该交互属于“写操作”且已分配给当前智能体。
  • 确认目标表和字段在白名单中；写操作不能使用关联表同时修改多表。
  • 检查当前会话是否允许写入以及权限审核结果。
  • 修改或删除必须提供当前范围内的记录 ID。
MCP 内部数据库调用返回 401 / 403 / 404
  • 401：MCP 没有声明 dobby_database_interactions，或没有使用平台注入的专用令牌。
  • 403：交互未分配给执行智能体、调用方式不是 workflow，或会话/项目权限不允许。
  • 404：技术标识错误、交互已停用，或平台会话无法解析。
  • 包内不得写入固定令牌、项目 ID 或用户 ID。
找不到可协同的智能体
  • 被邀请方必须已启用“允许被邀请”。
  • 当前智能体的协同范围不能为“禁用”。
  • 选择“指定”时，确认目标智能体已被勾选并保存。
知识库已经创建，但回答没有引用资料
  • 确认文件解析和索引已完成。
  • 确认知识库已分配给当前智能体并保存。
  • 用资料中有明确答案的问题重新测试。
核验规则更新后仍像旧版本
  • 上传新包后，在平台设置中选择新版本。
  • 点击“保存初始化配置”。
  • 重新发起核验；已经完成的历史核验不会自动重跑。
项目初始化的执行计划出现得很晚
  • 附件解析预处理结束后，主智能体的第一个业务动作应为 TaskCreate。
  • 检查主智能体是否分配 orchestrate-project-initialization 技能。
  • 若技能在代码中已更新但平台仍使用旧内容，重新同步初始化团队后新建任务测试。
邀请专项智能体时命令很长、响应很慢

该现象通常由邀请消息携带附件解析全文引起。邀请参数应只包含草稿 ID、文件 ID 和分块 ID，由专项智能体通过数据库交互分页读取。请检查初始化编排技能和附件分块交互的分配情况。

项目初始化没有触发核验 MCP
  • 确认平台设置中已选择可用的核验 MCP 版本并保存。
  • 确认五个实际需要的草稿分区均已提交完成。
  • 确认主智能体拥有“提交初始化草稿核验”数据库交互，并且最终只提交草稿 ID。
  • 检查 AgentScope 和工程管理平台服务是否都在运行。
保存按钮是灰色

该状态通常表示当前没有变更，或必填项未完成。产生有效修改后若按钮仍为灰色，请检查名称、模型、邀请说明和必选的核验版本。

发布前最后检查

配置检查

  • 凭证和模型测试通过。
  • 系统提示词明确职责、输出和禁止事项。
  • 只分配完成职责所需的 MCP 和数据库交互。
  • 写操作逐项确认，协同范围使用最小集合。
  • 知识库文件已完成索引。

运行检查

  • 至少完成一次真实会话测试。
  • 计划、协同和工具调用过程可见。
  • 结果可核对，敏感信息未泄露。
  • 业务端展示名称和说明清晰。
  • 必要时在审计页确认完整调用记录。
