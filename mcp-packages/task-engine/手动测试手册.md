# 任务引擎手动测试手册

用手动执行的方式，逐条体验任务引擎的能力。每个剧本都给出**可复制的命令**和**预期结果要点**，照着敲、看输出是否符合预期即可。

---

## 一、启动

```bash
cd /Volumes/Media1/Code/Task

# 首次使用，清空数据开始
.venv/bin/python mcp_playground.py --fresh

# 之后可复用数据
.venv/bin/python mcp_playground.py
```

启动后出现交互提示符 `任务引擎 > `。输入 `help` 随时查看命令。

**常用命令速查：**

| 命令 | 作用 |
|---|---|
| `templates` | 列出 7 个内置模板 |
| `gen <需求> --assignee 张三,李四 --confirmer 王工 --site 工点名` | 自然语言生成任务流 |
| `from <模板> [标题] --assignee ... --confirmer ... --site ...` | 按模板创建 |
| `flows` / `tasks` / `schedules` | 列表查询 |
| `dispatch <flow前缀>` | 立即布置 |
| `schedule <flow前缀> --at "时刻" --mode recurring --every N --unit week` | 登记定时 |
| `tick [--now "时刻"]` | 推进引擎 |
| `complete <task前缀> <节点序号>` | 完成节点 |
| `task <task前缀>` | 详情 + 历史 |
| `demo` | 自动跑一遍完整演示 |
| `fresh` | 清空数据 |
| `quit` | 退出 |

**两个小技巧：**

1. **id 可以只输前几位**——`flow_47146aeb6d98` 只要输入 `flow_4714` 就能自动匹配。
2. **节点序号从 1 开始**——界面上第 1 个节点就是 `1`，不是 `0`。

## 二、测试剧本

> 每个剧本开头建议先 `fresh` 清空数据，避免上一步的残留干扰。

### 剧本 0：一键演示（最快体验）

```
demo
```

**预期**：自动跑完「创建 → 布置 → 待办 → 逐节点完成 → 退回重做 → 验收 → 历史」8 个步骤，最后看到 18 条完整历史。

---

### 剧本 1：自然语言生成，自动识别周期

**目的**：验证一句话能变成带周期触发的任务流。

```
fresh
gen 每周五检查基坑监测数据，异常时复核并归档 --assignee 张三,李四 --confirmer 王工 --site 基坑监测点
```

**预期**：
- 触发规则识别为「每 1 周执行一次」（`每周五` 被正确解析）
- 生成 4 个节点，自动选「周期巡检」模板
- 张三、李四轮流分配责任人
- 输出末尾提示「下一步：调用 create_schedule 登记定时触发」

---

### 剧本 2：模板创建 + 完整办理闭环

**目的**：验证从布置到验收的全流程，以及责任人随着流转自动交接。

```
fresh
from 隐患整改 "3号楼临边防护整改" --assignee 张三,李四 --confirmer 王工 --site 3号楼-地下室
dispatch flow_
tasks --assignee u1
```

**预期**：
- `tasks --assignee u1` 看到 1 个任务，当前责任人张三

然后逐个完成（序号从 1 开始，共 5 个节点）：

```
complete task_ 1 --attach 隐患照片.jpg
complete task_ 2
complete task_ 3 --attach 整改后照片.jpg
complete task_ 4
complete task_ 5
```

**预期**：
- 每个 `complete` 后显示「节点已完成 (n/5)」
- 第 5 个完成后显示「全部节点完成，任务进入待验收」
- 期间完成第 1 个后，`tasks --assignee u2` 能看到任务交接给李四

最后验收：

```
accept task_
```

**预期**：显示「已验收通过并闭环」，状态「已完成」。

---

### 剧本 3：责任制三要素强制

**目的**：验证缺责任人 / 确认人 / 工点时，布置被拒绝并说明原因。

```
fresh
from 隐患整改 "缺要素的流程"
dispatch flow_
```

**预期**：拒绝，错误信息列出缺什么（责任人 / 确认人 / 工点）。

再试只给责任人、不给工点和确认人：

```
from 隐患整改 "只有责任人" --assignee 张三
dispatch flow_
```

**预期**：仍然拒绝，但错误信息变少（只缺确认人和工点）。

---

### 剧本 4：定时触发与幂等

**目的**：验证到点自动布置，且重复推进不重复创建。

```
fresh
from 周期巡检 "每周巡检" --assignee 张三 --confirmer 王工 --site 3号楼
schedule flow_ --at "2026-08-21 09:00" --mode recurring --every 1 --unit week
```

**预期**：显示「触发计划已登记」，下次触发 2026-08-21 09:00。

推进引擎到点前、到点、重复：

```
tick --now "2026-08-20 09:00"
tick --now "2026-08-21 09:00"
tick --now "2026-08-21 09:00"
```

**预期**：
- 第一次 `触发 0 个任务`（未到点）
- 第二次 `触发 1 个任务`（到点，自动布置）
- 第三次 `触发 0 个任务`（**幂等**，不重复创建）

查看结果：

```
tasks
schedules
```

**预期**：`tasks` 有 1 个任务；`schedules` 显示计划已触发 1 次、下次 2026-08-28。

---

### 剧本 5：留证约束

**目的**：验证要求留证的节点，不传附件无法完成。

```
fresh
from 隐患整改 "留证测试" --assignee 张三 --confirmer 王工 --site 测试工点
dispatch flow_
complete task_ 1
```

**预期**：拒绝——「节点「发现并记录隐患」要求提交证明材料」（该节点标注 ⚠需留证）。

带上附件再试：

```
complete task_ 1 --attach 现场照片.jpg
```

**预期**：成功，显示「节点已完成 (1/5)」。

> **退回重做同样强制留证**：确认人退回后，被退回的节点若要求留证，必须重新提交材料，旧附件不算数。当前内置模板的末节点都是「归档/关闭」类（不留证），所以通过模板退回演示不到这个场景；它由单元测试 `TestRejectRequiresFreshEvidence` 覆盖，接入 Dobby 后自定义流程会自动生效。

### 剧本 6：转办与受阻

**目的**：验证改派责任人和标记受阻。

```
fresh
from 隐患整改 "协作测试" --assignee 张三 --confirmer 王工 --site 3号楼
dispatch flow_
```

转办第一个节点给李四：

```
forward task_ 1 李四 李四
tasks --assignee u2
```

**预期**：`tasks --assignee u2` 现在能看到任务（转办后李四成为当前责任人）。

标记受阻：

```
block task_ 1 等材料进场
task task_
```

**预期**：任务状态「受阻」，节点显示受阻。

解除并完成：

```
unblock task_ 1
complete task_ 1 --attach 照片.jpg
```

**预期**：解除后状态恢复「进行中」，完成节点正常流转。

---

### 剧本 7：验收权限

**目的**：验证只有确认人能验收。

```
fresh
from 通用流程 "验收测试" --assignee 张三 --confirmer 王工 --site 3号楼
dispatch flow_
complete task_ 1 --attach 资料.pdf
complete task_ 2
complete task_ 3
complete task_ 4
```

现在任务处于「待验收」。用非确认人（张三）验收：

```
accept task_ --actor u1
```

**预期**：拒绝——「只有确认人 王工 可以验收该任务」。

用确认人验收：

```
accept task_ --actor boss
```

**预期**：成功，状态「已完成」。

---

### 剧本 8：逾期判定

**目的**：验证超过截止时间自动标记逾期。

```
fresh
from 通用流程 "逾期测试" --assignee 张三 --confirmer 王工 --site 3号楼
dispatch flow_
tick --now "2030-01-01 09:00"
```

**预期**：`tick` 输出「标记逾期」，任务被标记为「已逾期」。

查看：

```
tasks
task task_
```

**预期**：任务状态「已逾期」，但当前责任人仍是张三，且仍可继续办理（完成节点后恢复正常流转）。

## 三、命令速查（完整）

**生成与模板**
```
gen <需求> [--assignee 张三,李四] [--confirmer 王工] [--site 工点]
from <模板名> [标题] [--assignee ...] [--confirmer ...] [--site ...]
templates
flows
```

**布置与调度**
```
dispatch <flow前缀> [--actor 谁]
schedule <flow前缀> --at "2026-08-21 09:00" [--mode recurring] [--every 1] [--unit week]
schedules
pause <schedule前缀>
cancel-sched <schedule前缀>
```

**推进与查询**
```
tick [--now "2026-08-21 09:00"]
tasks [--assignee u1] [--state running] [--site 前缀] [--open]
task <task前缀>
```

**办理**
```
complete <task前缀> <节点序号> [--attach a.jpg,b.pdf] [--comment 文字] [--actor u1]
forward <task前缀> <节点序号> <新责任人ref> [姓名]
block <task前缀> <节点序号> [原因]
unblock <task前缀> <节点序号>
note <task前缀> <文字>
```

**闭环**
```
accept <task前缀> [--actor 谁]
reject <task前缀> [原因]
cancel <task前缀> [原因]
```

**其他**
```
raw <工具名> [json参数]    直接调用任意 MCP 工具
demo                      一键演示
fresh                     清空数据
help / quit / exit
```

| 隐患整改 | hazard_rectification | 5 | 发现隐患 → 派单整改 → 整改报验 → 安全员复核 → 闭环归档 |

## 五、状态速查

任务状态：待开始 → 进行中 → 待验收 → 已完成；旁支：受阻、已逾期、已取消。

节点状态：未开始 → 进行中 → 已完成；旁支：已跳过、受阻。

**六要素**（每个任务必须回答）：
1. 谁负责 —— 节点责任人（具体人，非岗位）
2. 要做什么 —— 节点名称
3. 截止时间 —— 自动推算
4. 哪个工点 —— 任务工点
5. 交什么材料 —— 节点交付物（可强制留证 ⚠）
6. 谁确认 —— 确认人（仅此人可验收）
