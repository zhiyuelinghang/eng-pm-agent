# 项目初始化核验 MCP

该包由工程平台直接调用，不分配给任何智能体，也不产生模型推理轮次。

- 输入：平台从草稿及五个专项分区组装出的标准 JSON。
- 输出：`ready` / `invalid`，以及带草稿数据 ID、字段名、中文标签、详细说明和处理建议的结构化问题。
- 更新：修改本目录规则，提高 `mcp.json` 与 `server.py` 版本，上传新包并在平台设置中选用该版本。
- 边界：所有初始化资料的业务判定均由 MCP 完成；平台仅负责权限、传输结构、并发与事务写入，不另设资料合格性规则。

本包不访问数据库。数据库读取、草稿组装和核验结果落库均由工程平台完成。

## 2.4.0 / 规则集 2026.09.4

`project_rules.json` 随包保存固定岗位及数值约束，运行时不导入后端校验函数。

- 岗位仅允许现有 15 个固定岗位。空白、自定义岗位及近似称呼均返回 `personnel.unsupported_position` 错误，定位到该人员的 `position_name`，保留上传原值并列出允许岗位。用户须修改原资料后重新上传。
- 补入历史模型已有的 12 项数值约束：合同工期、合同金额、人员序号、风险序号，以及 WBS 的排序、层级、进度、工期、预计工时、已记录工时、预算、实际成本。整数要求、上下限及有限数值检查均在 MCP 内执行；未提供的可选数值不因此被判为必填。
- 已核对历史结构规则：人员重复任职、序号重复，合同/计划/风险日期顺序，WBS 编码、层级、父子与前置关系、循环，质量指标关联与重复等已有对应 MCP 规则。
- 质量内容空白不新增必填限制；一人多岗保留核对提醒。分批选择与快照按既有机制处理。

岗位目录一致性由回归测试检查；后续目录调整须同步发布新 MCP 版本，禁止在初始化前后端另加岗位核验。
