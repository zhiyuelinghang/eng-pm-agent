# Dobby 记忆管理模块 — 迁移接入指南

> **给集成方的手册**：把本仓库的记忆管理模块嵌入你的项目，**替换掉原来的 agentscope**。
> 读完本文你只需要做 6 件事：拷贝目录 → 装依赖 → 建表 → 改配置 → 冒烟 → 替换调用点。
> 涉及"哪里会冲突、哪里会报错"的部分见 §6、§7。

---

## 1. 这个模块是什么

一套**自包含的长期记忆系统**（`utils/` 包，约 35 个 Python 文件），你拿走即可用：

| 能力 | 实现 |
|---|---|
| 长期记忆读写（Mem0 + pgvector） | `MemoryManager.remember / recall / forget` |
| 记忆自动抽取、跨会话检索、多项目隔离 | mem0 `user_id`（项目级）隔离 |
| 上下文组装（7 层 + 5 源融合注入） | `MemoryManager.assemble_context` |
| 上下文压缩（token 预算 + 触发裁剪） | `MemoryManager.compress_if_needed` |
| 记忆生命周期（衰减 / 反思 / 经验沉淀） | `end_session` 自动执行，或独立调 `reflect` / `consolidate_experiences` |
| 夜间维护（decay/verify/curate/classify） | `MemoryManager.run_dreamer`（可 cron） |
| LLM 主动检索工具（function calling） | `memory_tools.TOOL_SCHEMAS` + `execute_tool` |
| 会话持久化（LangGraph PostgresSaver） | `langgraph_utils.build_graph` + `compile_with_checkpointer`（可选层级） |
| 知识库 / 时间线 / 经验库融合 | `fusion.py`（WeKnora / Graphiti / 经验表，均**可选**，缺省优雅降级） |

**agentscope 在模块内只是薄层**，不是核心：只用了它的**消息对象**（`SystemMsg/UserMsg/AssistantMsg`）和 **DeepSeekChatModel 封装**。不需要 agentscope 的项目也可以接入（见 §6-⑤）。

## 4. 嵌入 6 步

### Step 1 — 拷贝 `utils/` 进你的项目

放到你项目的顶层（与你的代码同级）即可，包内全部是**相对导入**，不需要额外配置：

```python
# 你的代码里这样导入
from utils.memory_manager import MemoryManager
```

⚠️ 如果你项目**已有 `utils/` 目录**：整体改名（如 `dobby_mem/`），然后
- 把 `utils/memory_tools.py` 里 **2 处** `from utils.langgraph_utils import get_mem0`（第 166、207 行，函数内导入）改为 `from dobby_mem.langgraph_utils import get_mem0`；
- 把你自己代码里所有 `from utils.xxx import` 改为新包名；
- `utils/` 内其余全部是相对导入（`from . import config`），**无需改动**。

### Step 2 — 装依赖（§3 最小集）

### Step 3 — 初始化数据库（PostgreSQL 16 + pgvector）

```bash
psql -U <user> -d <db> -c "CREATE EXTENSION IF NOT EXISTS vector;"
psql -U <user> -d <db> -f data/init_experience_db.sql     # 经验功能用
psql -U <user> -d <db> -f data/init_graphiti_db.sql       # 时间线功能用
psql -U <user> -d <db> -f data/init_dreamer_db.sql        # 夜间维护用
```

`dobby_memories`（记忆向量表）与 `checkpoints`（会话表）分别由 mem0 / PostgresSaver **自动创建**，不用手动建。

### Step 4 — 配置（环境变量）

```bash
export DEEPSEEK_API_KEY="sk-..."        # LLM（必填）
export EMBEDDING_PROVIDER="local"       # local(本地bge) | dashscope(API)
export DATABASE_URL="postgresql://user:pwd@host:5432/你的库"
export LANGGRAPH_CHECKPOINT_DB="$DATABASE_URL"   # 会话持久化用
```

⚠️ **必改点**：`utils/langgraph_utils.py` 的 `_build_mem0_config()`（约第 577 行）里，pgvector 连接是**硬编码**的：

```python
# 原代码（硬编码）：
config={
    "host": "localhost", "port": 5432,
    "user": "dobby", "password": "dobby",
    "dbname": "dobby_demo",
    "embedding_model_dims": 1024,
    "collection_name": "dobby_memories",
}
# 改成读环境变量（推荐）：
config={
    "host": os.getenv("PGHOST", "localhost"),
    "port": int(os.getenv("PGPORT", "5432")),
    "user": os.getenv("PGUSER", "postgres"),
    "password": os.getenv("PGPASSWORD", ""),
    "dbname": os.getenv("PGDATABASE", "postgres"),
    "embedding_model_dims": 1024,
    "collection_name": os.getenv("MEM0_COLLECTION", "dobby_memories"),
}
```

（整份 `config.py` 的其他参数都可直接改，或仿照上面改成环境变量。`config.py` 是模块级常量，**import 时固化**，改完需重启进程。）

### Step 5 — 冒烟验证

```python
import asyncio, os, selectors, sys
from utils.memory_manager import MemoryManager

async def main():
    mm = MemoryManager(project_id="demo", role_id="dobby_core")
    state = await mm.start_session(session_id="sess_1")
    await mm.remember("3号基坑临边防护栏杆1.05m，不符合JGJ 80-2016要求≥1.2m。",
                      importance=0.8, memory_type="fact")
    hits = await mm.recall("基坑临边防护整改", top_k=5)
    print("命中:", len(hits))
    ctx = await mm.assemble_context(state, "整改进度如何？")
    print("上下文消息数:", len(ctx.messages))
    await mm.end_session(state)

if __name__ == "__main__":
    # Windows 必须用 SelectorEventLoop，否则 psycopg 卡死
    asyncio.run(main(), loop_factory=lambda: asyncio.SelectorEventLoop(selectors.SelectSelector()))
```

### Step 6 — 替换 agentscope 调用点（核心映射）

你原来用 agentscope 的写法 → 现在的写法：

```python
# ── 原来（agentscope）──
from agentscope.agent import Agent, ContextConfig
agent = Agent(name="Dobby",
              system_prompt="你是工程助手",
              model=deepseek_model,                       # DeepSeekChatModel(...)
              context_config=ContextConfig(trigger_ratio=0.8, reserve_ratio=0.1),
              toolkit=Toolkit(tools=[]))
resp = await agent.reply(UserMsg("user", "3号基坑要整改吗？"))
```

```python
# ── 现在（本模块，最简路径）──
from utils.memory_manager import MemoryManager

mm = MemoryManager(project_id="demo", role_id="dobby_core")
state = await mm.start_session(session_id="sess_1")
ctx = await mm.assemble_context(state, "3号基坑要整改吗？", system_prompt="你是工程助手")
# ctx.messages 已含：系统提示 + 记忆/KB/时间线融合注入 + 运行时 + 历史 + 用户消息
# 交给你的 LLM（或 utils.langgraph_utils._call_model(ctx.messages)），得到回复后：
state["messages"] = ctx.messages + [回复消息]
await mm.compress_if_needed(state)     # 等价于原 ContextConfig 自动压缩
```

| agentscope 原来的 | 本模块替代 |
|---|---|
| `Agent(...)` + `agent.reply(...)` | `MemoryManager` + `assemble_context`（自建对话循环）；或完整多角色图：`build_graph(roles)` + `compile_with_checkpointer` + `graph.ainvoke`（见 §5） |
| `ContextConfig(trigger_ratio=0.8)` 自动压缩 | `compress_if_needed(state)`（超预算触发摘要+裁剪） |
| agentscope 消息 `UserMsg/SystemMsg` | 保留使用（薄层）；也可用 dict + `_normalize_user_message()` 归一化 |
| 直接 `new mem0.Memory(...)`（配置漂移） | `get_mem0()` 单例（统一配置，进程内复用） |
| 跨会话记忆检索 | `mm.recall()`（同 `project_id` 自动命中） |

> **完整形态（推荐，多角色+记忆注入+会话恢复）**：直接用 `langgraph_utils` 的图运行时，无需自建循环，参考 `acceptance_tests/demo_05_multi_agent.py` 的调用方式（`build_graph(roles)` → `compile_with_checkpointer` → `ainvoke({"messages": [...], "project_id": ...}, config={"configurable": {"thread_id": ...}})`）。

## 5. 常用 API 速查

| 方法 | 说明 |
|---|---|
| `mm.start_session(session_id=None) -> state` | 新会话（DobbyState） |
| `mm.resume_session(thread_id)` | 恢复历史会话（需 L3 持久化） |
| `mm.end_session(state)` | 收尾：衰减+反思+经验抽取（**每次会话结束建议调用**） |
| `mm.remember(content, importance=0.5, memory_type="fact")` | 写记忆 |
| `mm.recall(query, top_k=5)` | 搜记忆（≥0.75 相似度自动强化） |
| `mm.forget(memory_id)` | 删记忆 |
| `mm.assemble_context(state, user_input, system_prompt=None, mode="auto")` | 7 层上下文组装（模式 auto/minimal/standard/full） |
| `mm.compress_if_needed(state)` | 超预算则压缩，返回是否触发 |
| `mm.reflect()` / `mm.consolidate_experiences()` | 反思 / 经验合并（24h 冷却） |
| `mm.run_dreamer(task_name=None)` | 夜间维护（decay/verify/curate/classify） |
| `execute_tool(name, arguments, user_id, agent_id, state)` | LLM function-calling 分发（6 个工具，schema 见 `memory_tools.TOOL_SCHEMAS`） |
| `get_mem0()` | Mem0 单例（线程安全、懒加载） |

## 6. 合并冲突点与解决（⚠️ 重点）

| # | 冲突点 | 症状 | 解决 |
|---|---|---|---|
| ① | **`utils/` 包名撞车**（你的项目已有 utils） | ImportError / 同名模块互相覆盖 | 改名（如 `dobby_mem/`），只改 2 处内部绝对导入（`memory_tools.py:166/207`）+ 你自己的 import |
| ② | **mem0 连接硬编码**（`_build_mem0_config` 里 host/user/password/dbname 写死） | 连不上你的库 / 连错库 | 改读环境变量（§4 Step 4）——这是**必改点** |
| ③ | **数据库表名冲突**：`dobby_memories`（记忆表）、`checkpoints`/`checkpoint_writes`（会话表）、`experience_extracts`/`experience_registry`、`graphiti_events`、`dreamer_run_log` | 与你的同名表数据混杂 / 类型不兼容报错 | 最简单：模块用**独立 database**；或改 `collection_name`（记忆表）+ LangGraph checkpoint 走独立 schema |
| ④ | **环境变量名冲突**（`DATABASE_URL`、`DEEPSEEK_API_KEY`…通用名） | 值被对方环境覆盖，行为异常 | `config.py` 是 import 时固化的模块常量：先加载你自己的 env（`load_dotenv`）再 import `utils.config`；或改常量名 |
| ⑤ | **agentscope 版本冲突 / 你不想装 agentscope** | 依赖打架 | 模块对 agentscope 只有两处薄依赖，可自行替换：**a)** 消息对象：把 `_make_system` / `_make_user` / `_msg_content` / `_call_model`（`langgraph_utils.py`）里的 `SystemMsg/UserMsg/AssistantMsg` 换成你自己的消息类或 dict（消息协议是 `{"role","content"}` 形状，`_msg_content` 已兼容 dict）；**b)** 模型封装：`_build_model()`（`langgraph_utils.py:178`）是**唯一**模型构造点，换成你自己的 OpenAI 兼容客户端即可。替换后整个模块不再需要 agentscope |
| ⑥ | **嵌入模型/向量维度冲突**（固定 1024 维） | 换模型后建表报 dim 不匹配 | 保持 `EMBEDDING_PROVIDER=local` + bge-large-zh-v1.5（1024 维）；若你的 embedding 维度不同，需改 `config.EMBEDDING_DIMS` 并**删除旧 collection 重建** |
| ⑦ | **torch / sentence-transformers 太重** | 安装慢 / 与你的环境冲突 | 用 `EMBEDDING_PROVIDER=dashscope`（API 嵌入，免本地模型）；或配置已有的 OpenAI 兼容嵌入服务 |
| ⑧ | **`.env` 不会被自动加载** | 配置"看起来对了"但实际没生效 | `config.py` 只读环境变量，不读 `.env` 文件。你自己 `pip install python-dotenv` 并先 `load_dotenv()` 再 import（`app.py` 里有现成写法） |

## 7. 易错点（运行时报错速查）

| 现象 | 原因 | 解决 |
|---|---|---|
| `KeyError: slice(None, 5, None)` / 结果排序乱 | mem0 v2 返回 `{"results": [...]}`，被当 list 切片/排序 | 先解包：`results = results.get("results", [])`（模块内已处理，你自定义代码时注意） |
| `add()` 后搜索永远为空（静默） | **async 上下文直接调 mem0**（同步 API 在事件循环里被吞） | 用线程池：`MemoryManager` 已内置；裸调时包 `ThreadPoolExecutor` |
| `add()` 静默返回空 | `user_id`/`agent_id` 含**冒号 `:`**（mem0ai SQLite history bug） | 用下划线，如 `project_demo` |
| 写入成功但搜不到 | 读写两侧 `user_id`/`agent_id`/`collection_name` 不一致 | 统一：`user_id=project_id`、`agent_id=project_id`、`collection_name` 同一值 |
| Windows 下 asyncio 卡死 | `ProactorEventLoop` 与 psycopg 不兼容 | `asyncio.run(main(), loop_factory=lambda: asyncio.SelectorEventLoop(selectors.SelectSelector()))` |
| 记忆质量极低 / 模型 404 | DeepSeek 旧模型名已下线（`deepseek-chat`） | 设 `DEEPSEEK_MODEL` 为可用模型（如 `deepseek-v4-flash`） |
| 空结果时 LLM 编造事实 | 无检索结果注入 | 用 `assemble_context` 或角色节点（自动注入 `<system-reminder>` 并显式写"暂无相关记录"），不要裸调 LLM |
| HuggingFace SSL 报错 | 在线检查被墙/代理 | `export HF_HUB_OFFLINE=1` |
| 可选组件（Neo4j/WeKnora/LightRAG）连不上导致崩溃 | — | 不会：全部优雅降级返回空；**PostgreSQL 是唯一硬依赖** |
