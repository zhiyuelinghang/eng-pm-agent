# 工程管理智能体 — 服务器开发环境搭建指南

> 目标服务器：CentOS 7.9 / 56核 / 62G内存 / 849G /home / Docker 20.10 + Compose v2.29
> 适用场景：3人协作开发，一周垂直切片

---

## 一、整体思路（给新手看）

```
CentOS 7.9 宿主机（系统老，但硬件强）
│
├── Docker 已装好 ✅
│
└── docker compose up 一键拉起：
    ├── devbox（Ubuntu 22.04 开发容器）← 三人在这里写代码
    │   内含：Python 3.11 / Node 20 / Git / 所有开发工具
    │   端口：3000, 8000, 8001, 8002, 8010, 8088
    │
    ├── ragflow（RAGFlow 检索引擎）
    │   端口：9380（API）, 80（Web UI）
    │
    ├── postgres（数据库：审计/RBAC/用户）
    │   端口：5432
    │
    └── redis（缓存/会话）
        端口：6379
```

**为什么用开发容器？**
- CentOS 7 的 glibc 2.17 太老，Node.js 18+ 跑不了
- 容器里是 Ubuntu 22.04，什么都是新的，不受限制
- 三人 SSH 登录宿主机后，`docker exec` 进同一个容器开发
- 代码放在宿主机 /home 目录（挂载进容器），不怕容器重建丢代码

## 二、操作步骤（照着敲）

### 步骤 1：建项目目录

```bash
# 用 rcbi 账号登录服务器后执行
mkdir -p /home/rcbi/eng-pm-agent
cd /home/rcbi/eng-pm-agent
mkdir -p docker data/ragflow data/postgres
```

### 步骤 2：创建 docker-compose.yml

```bash
cat > docker/docker-compose.yml << 'EOF'
version: "3.8"

services:
  # ============================================================
  # 开发容器：三人在这里面写代码、跑服务
  # ============================================================
  devbox:
    image: ubuntu:22.04
    container_name: devbox
    hostname: devbox
    working_dir: /workspace
    volumes:
      - /home/rcbi/eng-pm-agent:/workspace        # 代码目录挂载
      - devbox-home:/root                          # 保留 shell 历史等
    ports:
      - "3000:3000"    # 前端
      - "8000:8000"    # Gateway + BFF
      - "8001:8001"    # 检索服务
      - "8002:8002"    # Hermes 委派服务
      - "8010:8010"    # AgentScope 编排
      - "8088:8088"    # Hermes API Server
    environment:
      - LANG=C.UTF-8
      - TZ=Asia/Shanghai
    # 保持容器运行
    command: >
      bash -c "
        apt-get update && 
        apt-get install -y curl git python3 python3-pip python3-venv nodejs npm sudo vim tmux htop &&
        curl -fsSL https://deb.nodesource.com/setup_20.x | bash - &&
        apt-get install -y nodejs &&
        pip3 install --upgrade pip &&
        pip3 install fastapi 'uvicorn[standard]' pyjwt pyyaml requests python-multipart httpx &&
        echo '✅ devbox ready' &&
        tail -f /dev/null
      "
    restart: unless-stopped
    networks:
      - agent-net

  # ============================================================
  # PostgreSQL：审计日志 / RBAC / 用户表
  # ============================================================
  postgres:
    image: postgres:15
    container_name: postgres
    environment:
      POSTGRES_USER: agent
      POSTGRES_PASSWORD: agent123
      POSTGRES_DB: agent_platform
    volumes:
      - /home/rcbi/eng-pm-agent/data/postgres:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    restart: unless-stopped
    networks:
      - agent-net

  # ============================================================
  # Redis：会话缓存 / 令牌黑名单
  # ============================================================
  redis:
    image: redis:7-alpine
    container_name: redis
    ports:
      - "6379:6379"
    restart: unless-stopped
    networks:
      - agent-net

networks:
  agent-net:
    driver: bridge

volumes:
  devbox-home:
EOF
```

> ⚠️ RAGFlow 的 docker-compose 比较复杂（自带 Elasticsearch + Milvus），建议按官方文档单独部署，这里先不放进来，避免一次起太多服务。

### 步骤 3：启动

```bash
cd /home/rcbi/eng-pm-agent/docker
docker compose up -d
```

第一次会下载镜像（约 2-3 GB），等 5-10 分钟。

### 步骤 4：验证 devbox 就绪

```bash
# 等容器初始化完成（约 2-3 分钟）
docker logs devbox -f
# 看到 "✅ devbox ready" 就行，Ctrl+C 退出日志

# 进入开发容器
docker exec -it devbox bash

# 在容器内验证
python3 --version    # 应该 3.10+
node --version       # 应该 v20.x
git --version
```

### 步骤 5：三人怎么同时用

```bash
# 每个人 SSH 登录宿主机后，执行这一条就进入开发环境：
docker exec -it devbox bash

# 建议每人用 tmux 开自己的会话（互不干扰）：
docker exec -it devbox tmux new -s p1    # P1 用这个
docker exec -it devbox tmux new -s p2    # P2 用这个
docker exec -it devbox tmux new -s p3    # P3 用这个

# 重新连接已有会话：
docker exec -it devbox tmux attach -t p1
```

## 三、RAGFlow 单独部署（P1 负责）

RAGFlow 官方推荐独立部署，不要和开发容器混在一起：

```bash
# 在宿主机上（不是 devbox 容器里）
cd /home/rcbi
git clone https://github.com/infiniflow/ragflow.git
cd ragflow/docker

# 编辑 .env 设置端口和数据目录
# 然后：
docker compose -f docker-compose.yml up -d
```

RAGFlow 起来后，devbox 容器里通过 `http://host.docker.internal:9380` 或宿主机内网 IP `192.168.4.150:9380` 访问。

```bash

# 克隆仓库（如果用 GitHub）
cd /workspace
```

## 六、日常操作速查

```bash
# 启动全部
cd /home/rcbi/eng-pm-agent/docker && docker compose up -d

# 停止全部
docker compose down

# 重启 devbox（改了 compose 文件后）
docker compose up -d --force-recreate devbox

# 查看日志
docker logs devbox -f
docker logs postgres -f

# 进入开发容器
docker exec -it devbox bash

# 查看资源占用
docker stats
```

## 七、为什么不重装系统（总结）

| 因素 | 重装 Rocky 9 | Docker 开发容器 |
|------|:--:|:--:|
| 风险 | 🔴 远程重装可能变砖 | 🟢 零风险 |
| 时间 | 半天~一天 | 10 分钟 |
| Node.js | ✅ 原生跑 | ✅ 容器内跑 |
| 现有服务影响 | 🔴 全部重来 | 🟢 不影响宿主机 |
| 性能损耗 | 无 | ≈1%（Docker 几乎无开销） |
| 三人协作 | 各自账号 | 同一容器 tmux |

**Docker 容器方案：零风险、10分钟搞定、性能无损耗。**

## 八、注意事项

1. **代码放在 `/home/rcbi/eng-pm-agent/`**（宿主机目录），挂载进容器。容器删了代码不会丢。
2. **三人的 SSH 账号**：如果只有 `rcbi` 一个账号，三人可以都用它登录（开发阶段够用）。正式阶段再建 p1/p2/p3 三个账号。
3. **devbox 容器重建后**：pip 包需要重装。建议把常用包写到 `requirements.txt`，或者用 Dockerfile 固化。
4. **内存分配**：62G 足够——RAGFlow 约占 8-16G，PostgreSQL 1G，devbox 按需，剩余 40G+ 空闲。
