# 三人接口对接卡（贴墙用）

## 一、先懂这三句（心智模型）

1. **每条跨人接缝 = 提供方（建接口的人）+ 调用方（调接口的人）。** 提供方负责把接口建出来，并**第一天就给一个 mock（假接口）**；调用方对着 mock 先开发，不等真接口。
2. **令牌 `common/auth.py` 是三人共用的"货币"。** 所有接口靠它传身份和权限。它一改三人全断 → Day 1 冻结，改它要三人都同意。
3. **P1 的 `/kb/retrieve` 被两个人调（P2 和 P3）。** P1 是"双重提供方"，它的 mock 必须最早出，否则同时堵住两人。

---

## 二、接缝责任矩阵（一共 6 条）

| 接缝 | 是什么 | 提供方(建) | 调用方(调) | 类型 | 谁先给 mock | 联调谁负责 |
|---|---|---|---|---|---|---|
| **A** | 前端 → 网关：`/auth/login`、`/api/chat` | **P2** | P3 | HTTP | P2 | P2+P3 |
| **B** | 编排 → 检索：`/kb/retrieve` | **P1** | P2 | HTTP | P1 | P1+P2 |
| **C** | 编排 → 委派：`/delegate` | **P3** | P2 | HTTP | P3 | P2+P3 |
| **D** | 委派 → 检索：`/kb/retrieve`（**同 B**） | **P1** | P3 | HTTP | P1（同一个） | P1+P3 |
| **E** | 微信 → 入库：`wechat.jsonl` | **P3** | P1 | 离线文件 | P3 给样本 | P3+P1 |
| **F** | 令牌：`common/auth.py` | 共建/P2 维护 | 三人都 import | 共享代码 | Day 1 就有 | 全员 |

> 记住：A 的提供方是 P2（不是 P3），因为前端调的是 P2 的网关。B 和 D 是**同一个接口、两个调用方**。

## 三、每个提供方第一天先交的 mock（直接抄）

mock 的作用：返回写死的假数据，让调用方不被你堵住。**Day 1 推上去，Day 4 再换真的。**

### P1 的 mock —— `kb/mock_retrieve.py`
让 mock 自己也体现权限：总工令牌不返回财务，方便大家早点验证。
```python
# kb/mock_retrieve.py —— 假检索，对着它先开发
import sys, os
from fastapi import FastAPI, Header
from pydantic import BaseModel
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from common.auth import verify_token

app = FastAPI()
class Req(BaseModel):
    query: str
    top_k: int = 6

@app.post("/kb/retrieve")
def retrieve(req: Req, authorization: str = Header(...)):
    p = verify_token(authorization.replace("Bearer ", ""))
    chunks = [{"text": "施工规范要求混凝土养护不少于14天", "source": "规范.pdf",
               "dataset": "ds_specs", "score": 0.9}]
    if "ds_finance" in p["datasets"]:          # 只有经理拿得到
        chunks.append({"text": "项目总成本1.2亿元", "source": "财务.txt",
                       "dataset": "ds_finance", "score": 0.88})
    return {"chunks": chunks}
```
跑：`uvicorn kb.mock_retrieve:app --port 8001`

### P3 的 mock —— `hermes/mock_delegate.py`
```python
# hermes/mock_delegate.py —— 假委派
import sys, os
from fastapi import FastAPI, Header
from pydantic import BaseModel
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from common.auth import verify_token

app = FastAPI()
class Req(BaseModel):
    task: str
    skill: str = "brief"

@app.post("/delegate")
def delegate(req: Req, authorization: str = Header(...)):
    verify_token(authorization.replace("Bearer ", ""))
    return {"result": "【本周简报】1.主体结构完成3层 2.无重大风险", "skill_used": req.skill}
```
跑：`uvicorn hermes.mock_delegate:app --port 8002`

### P2 的 mock —— 编排 `orchestrator/mock_app.py`
```python
# orchestrator/mock_app.py —— 假编排
import sys, os
from fastapi import FastAPI, Header
from pydantic import BaseModel
sys.path.append(os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from common.auth import verify_token

app = FastAPI()
class Chat(BaseModel):
    message: str

@app.post("/chat")
def chat(body: Chat, authorization: str = Header(...)):
    verify_token(authorization.replace("Bearer ", ""))
    return {"reply": "（假回答）收到：" + body.message, "sources": [], "via": "mock"}
```
跑：`uvicorn orchestrator.mock_app:app --port 8010`

> 网关 A 的 mock：P2 直接用真的 `gateway/app.py` 即可，登录发令牌逻辑很简单，没必要 mock。

## 四、怎么"只测一条接缝"（不依赖别人，自己就能验）

先造两个令牌备用：
```bash
python3 -c "import sys;sys.path.append('.');from common.auth import issue_token;print('PM='+issue_token('pm_zhang')['token']);print('CE='+issue_token('ce_li')['token'])"
```

| 测哪条 | 命令 | 期望 |
|---|---|---|
| A | `curl -X POST localhost:8000/auth/login -H "Content-Type: application/json" -d '{"user":"ce_li","password":"123456"}'` | 返回 token |
| B | `curl -X POST localhost:8001/kb/retrieve -H "Authorization: Bearer <CE>" -H "Content-Type: application/json" -d '{"query":"成本"}'` | chunks 里**无**财务 |
| B | 同上换 `<PM>` 令牌 | chunks 里**有**财务 |
| C | `curl -X POST localhost:8002/delegate -H "Authorization: Bearer <CE>" -H "Content-Type: application/json" -d '{"task":"周报","skill":"brief"}'` | 返回 result |
| D | 同 B（委派服务内部调的就是它，B 通了 D 自动通） | —— |

> 这张表就是你们各自"自测达标"的标准：**自己这条接缝按它能过，就算交付。**

## 五、改契约的规矩（避免一个人改崩三个人）

`contracts/` 和 `common/auth.py` 里的东西一旦冻结，要改必须：
1. 开分支，commit 前缀 `[contract]`；
2. PR 里 **@ 所有受这条接缝影响的人**（看上面的责任矩阵）；
3. 受影响的人都 Approve 才能 Merge；
4. 改完在群里喊一声"契约 X 变了，影响 A/B"，让大家拉最新。

字段宁可 Day 1 多想 5 分钟，也别开发到一半改。

## 六、三人按这个节奏走（围绕接缝）

```
Day1  全员：把 common/auth.py + contracts/API.md 定死冻结
      P1 推 mock_retrieve  |  P2 推 gateway真的+mock编排  |  P3 推 mock_delegate
      → 结束时：任何人都能 登录→编排→检索→委派 全链路跑通（虽然都是假数据）

Day2-3 各自"换真"：对着别人的 mock 开发自己的调用逻辑，同时把自己的真接口建出来
      用第四节的命令"只测自己这条接缝"，过了就推

Day4  集成：按"下游先起"的顺序换掉所有 mock（见下），跑端到端
Day5  验收：5 条用例（重点用例4：总工的简报无财务）
```

### 集成启动顺序（下游依赖先起，关键！）
```
1. RAGFlow(P1)        →  2. 检索服务真版(P1, :8001)
3. Hermes API(P3,:8088) → 4. 委派服务真版(P3,:8002)
5. 编排真版(P2,:8010)  →  6. 网关(P2,:8000)  →  打开浏览器
```
为什么这个顺序：每个服务启动时会去连它下游的服务，下游没起会连不上。**从最底层往上点火。**

## 七、接缝出问题时先查这里

| 症状 | 多半是哪条接缝 | 先查 |
|---|---|---|
| 登录就失败 | A | 网关 roles.yaml 路径、密码对不对 |
| 401 令牌无效 | F | 三个服务的 `common/auth.py` 是不是同一份（SECRET 一致）|
| 检索结果为空/报错 | B/D | RAGFlow 起没起、DATASET_IDS 填没填、文档解析完没 |
| 总工能看到财务 ❌ | B/D | 检索服务有没有按 `payload["datasets"]` 过滤 |
| 简报路径不通 | C | 委派服务、Hermes API 起没起；timeout 够不够 |
| 微信查不到内容 | E | P3 的 jsonl 给了没、P1 入库了没 |
| 字段对不上(KeyError) | 任一 HTTP 接缝 | 回去对 `contracts/API.md`，不符的改 |
