Prototype Briefing Guide

工程智管家 MVP 原型演示讲解大纲

这份 HTML 用来辅助下午给用户讲原型：说明当前整套系统做什么、两端如何分工、主流程怎么走、每个页面承担什么作用，以及推荐按什么顺序演示。

原型页面与演示状态已覆盖 范围：运维端 + 工地端 用途：现场讲解大纲 不以真实 API 联调为本次评审口径
01

讲解总口径

先把用户听感定住：它不是再造一个平台，而是现有平台和项目一线之间的智能工作层。

一句话定位

工程智管家 MVP 是面向项目一线的“进度风险提醒与填报减负智能体”。

它不替代公司平台、股份平台、业主平台和检测平台，而是把 WBS、风险源、日报、附件和填报动作串起来，帮助项目部少整理、早提醒、任务到人、草稿可确认、填报可辅助。

价值 1
少填报
从 WBS、风险清单、日报、照片和监测资料中提取可复用信息，减少重复录入。
价值 2
早提醒
根据 WBS 计划、风险等级和提醒规则提前生成风险任务，而不是等平台报警。
价值 3
任务到人
提醒、确认、补材料和填报事项都进入任务中心，并分派到具体责任人。
价值 4
人工确认
日报解析、风险草稿、填报包都允许人工修改和确认，避免 AI 直接替人拍板。
价值 5
协助填平台
用户自行登录目标平台后，系统辅助填写字段和上传附件，最终提交仍由用户本人完成。
价值 6
留痕追溯
提醒、草稿、确认、填报、配置都有日志和来源依据，方便复盘和解释。
本次原型评审口径：看页面、状态、入口、流程和业务故事是否完整；不把真实后端 API、真实文件解析、真实 Playwright 自动化作为本轮缺口。
02

两端与角色

系统分为运维端和工地端，两端的工作重点不同。

运维端

服务对象：实施管理员、系统管理员、项目配置责任人。

主要任务：把项目底座搭起来，包括项目、成员、WBS、风险源、关联关系、日报目录、提醒规则、上报模板、平台字段映射和操作日志。

讲解重点：运维端不是日常一线使用入口，而是前期初始化和规则维护入口。

工地端

服务对象：项目负责人、项目执行人、资料与填报负责人。

主要任务：看首页待办、处理风险任务、确认日报解析、审核风险草稿、启动填报助手。

讲解重点：一线用户不每天维护复杂底图，只处理任务、补材料、确认结果。

角色和页面关系

角色常看页面核心动作
实施管理员项目配置、WBS 导入、风险源管理、WBS-风险关联、规则配置初始化项目底图和提醒规则
项目负责人工地首页、任务中心、风险任务、草稿审核看风险、看逾期、确认关键结果
项目执行人任务中心、风险任务、任务详情处理风险任务、补充材料、提交确认
资料与填报负责人日报解析、草稿审核、填报助手确认日报、审核草稿、启动辅助填报
系统管理员成员配置、操作日志维护人员权限、查看配置和操作记录
03

主业务闭环

讲原型时建议一直围绕这条线，不要散讲页面。

完整闭环

创建项目-> 配置成员-> 导入 WBS-> 导入风险源-> 建立 WBS-风险关联-> 配置提醒和材料规则-> 生成风险任务-> 日报扫描解析-> 人工确认日报-> 生成风险草稿-> 审核生成填报包-> 填报助手辅助录入-> 用户最终提交
第一段
后台初始化
先用运维端把项目、成员、WBS、风险源、关联规则、日报目录、提醒规则、模板和字段映射配置好。
第二段
任务生成与到人
系统根据 WBS 计划时间和风险规则，把提醒转成任务，分派给具体负责人和确认人。
第三段
日报进入人工确认
系统从日报目录识别文件，提取日期、进度、问题、风险和附件信息，用户在日报解析页修正并确认。
第四段
草稿和填报包
已确认日报、WBS、风险源、附件和模板共同生成风险上报草稿，审核后形成填报包。
第五段
网页填报助手
用户自行登录目标平台，系统辅助录入字段、上传附件、保存草稿，并停在最终提交前。
04

运维端页面说明

运维端用于“搭底图、配规则、看日志”。演示时从项目注册/管理进入。
登录页
入口
/login

先选择“系统运维端”或“工地现场端”。运维端登录后进入项目注册/管理。

  • 用于说明系统有两类使用场景。
  • 演示时可先选运维端完成初始化，再切到工地端看一线闭环。
项目注册/管理
P0
/admin/project

管理系统里的项目底座，创建、编辑、停用项目，并进入“项目工作台”。

  • 讲解点：所有 WBS、风险源、任务、日报都归属到当前项目。
  • 演示动作：点击“进入工作台”，进入项目级配置集合。
成员与责任配置
P0
/admin/members

维护项目成员、职位、联系方式、责任标签和每个人负责的风险源。

  • 讲解点：系统不是只按角色提醒，而是任务到具体人。
  • 演示动作：添加或编辑成员，查看成员对应的风险责任。
WBS 导入
P0
/admin/wbs

导入施工进度计划，形成系统判断风险触发时间的工序底图。

  • 讲解点：上传后进入解析预览，能人工调整工序名称、层级和计划时间。
  • 演示动作：点击“选择文件导入”，展示“文件接收 -> 解析字段 -> 人工确认 -> 写入底图”。
风险源管理
P0
/admin/risk-sources

导入和维护风险源，包括风险等级、类型、管控周期、责任人、确认人、控制要求和材料要求。

  • 讲解点：风险源不是简单列表，还包括后续草稿和补材料所需的要求。
  • 演示动作：展示风险源导入预览，编辑材料要求和控制要求。
WBS-风险关联
P0
/admin/wbs-risk-link

把具体 WBS 工序和风险源绑定，配置提前提醒天数和提醒方式。

  • 讲解点：系统能提前提醒，是因为这里建立了“哪个工序触发哪个风险”。
  • 演示动作：新增一条关联规则，说明后续如何生成风险任务。
日报目录配置
P0
/admin/daily-dir

配置 incoming、processing、archive、failed、processed 等目录，以及扫描频率和启用状态。

  • 讲解点：系统不是让用户上传每份日报，而是从微信群监听服务落盘目录扫描。
  • 演示动作：展示文件流转路径和测试扫描。
提醒规则配置
P0
/admin/rules

按风险等级配置提前提醒天数和启用状态。

  • 讲解点：重大风险可以提前 14 天，一般风险可提前 3 天，规则可按项目调整。
  • 演示动作：修改提醒天数，说明任务生成逻辑。
上报模板配置
P1
/admin/templates

维护风险动态上报模板，定义草稿章节、字段、数据来源和缺项规则。

  • 讲解点：AI 草稿不是自由发挥，而是按模板填字段。
  • 演示动作：在字段配置和文书预览之间切换。
平台字段映射
P1
/admin/field-mapping

配置内部草稿字段和外部平台字段的对应关系，同时维护附件类型映射。

  • 讲解点：填报助手知道“系统字段要填到平台哪个字段”，靠这里配置。
  • 演示动作：校验映射，说明失败字段如何转人工处理。
操作日志
P0
/admin/logs

查询系统配置、任务生成、日报解析、草稿确认等操作记录。

  • 讲解点：关键过程留痕，方便追溯“谁改了什么、系统什么时候生成了什么”。
  • 演示动作：按级别或关键词筛选日志。
05

工地端页面说明

工地端用于“看待办、处理任务、确认日报、审核草稿、辅助填报”。
工地首页
P0
/dashboard

一线用户进入系统后的工作台，展示逾期任务、待处理任务、待确认日报、待审核草稿、待填报事项和即将触发风险。

  • 讲解点：首页不放复杂后台配置，只回答“我今天要处理什么”。
  • 演示动作：从统计卡片和快捷入口进入任务、日报、草稿、填报助手。
任务中心
P0
/tasks

所有提醒、确认、补材料和填报事项的统一入口。

  • 讲解点：任务中心按今日任务、逾期任务、待补充材料、待确认日报、待审核草稿、待填报事项筛选。
  • 演示动作：打开任务详情抽屉，展示触发原因、关联 WBS、关联风险源、材料补充、状态流转。
风险任务
P0
/risks

按风险源展示等级、类型、管控期、责任人、确认人、所需材料、关联 WBS、当前状态和触发规则。

  • 讲解点：用户能从风险视角查看风险是否临近、缺哪些材料、有哪些日报和附件。
  • 演示动作：生成草稿，查看历史草稿，进入填报包。
日报解析确认
P0
/daily-reports

展示从日报文件中提取的日期、施工内容、进度、问题、风险、监测、明日计划、匹配 WBS 和附件标记。

  • 讲解点：AI 解析结果不是只读，用户可以改字段、调 WBS、标记附件后再确认入库。
  • 演示动作：切换待确认、历史归档、异常文件；异常文件可重新解析或转人工确认。
草稿审核
P0
/drafts

审核系统生成的风险进展上报草稿，展示正文、字段化信息、来源引用、附件清单和缺项提示。

  • 讲解点：草稿可编辑、可驳回、可审核，通过后生成平台填报包。
  • 演示动作：修改正文，填写审核意见，点击“审核通过并生成填报包”。
填报助手
P1
/filling

预览已确认填报包的待填字段和附件，展示安全声明、登录确认、辅助录入进度、失败字段、草稿保存和最终提交状态。

  • 讲解点：系统不保存密码、不绕验证码、不自动最终提交。
  • 演示动作：打开目标平台，确认已登录，启动辅助填报，标记平台草稿已保存，最后标记用户已提交。
用户与班组
现场入口
/members

工地端可查看项目成员和责任标签，方便一线知道任务和风险责任分工。

  • 讲解点：同一成员可承担多个责任，系统按责任标签分派任务。
  • 演示动作：查看成员负责的风险源。
06

推荐演示路线

如果时间有限，按这条路线讲，最容易让用户理解整套闭环。

15 分钟标准演示

0-2 分钟
开场定位：工程智管家不是新平台，而是帮项目部把 WBS、风险、日报、附件和填报串起来的智能工作层。
2-6 分钟
运维端建底图：项目配置 -> 成员责任 -> WBS 导入预览 -> 风险源导入预览 -> WBS-风险关联 -> 提醒规则。
6-8 分钟
补充自动化配置：日报目录说明文件来源，上报模板说明草稿生成规则，平台字段映射说明填报助手怎么知道填哪里。
8-11 分钟
工地端处理任务：首页看待办 -> 任务中心筛选 -> 任务详情看触发原因、材料和状态流转。
11-13 分钟
日报到草稿：日报解析确认 -> 修改字段和 WBS -> 草稿审核 -> 审核通过生成填报包。
13-15 分钟
填报助手收口：预览字段和附件 -> 用户自行登录 -> 启动辅助填报 -> 保存平台草稿 -> 用户最终提交。
如果只给 5 分钟
讲首页、任务中心、日报确认、草稿审核、填报助手五个页面即可。重点是“任务驱动 + 人工确认 + 辅助填报”。
如果用户关注后台
重点讲项目工作台：WBS、风险源、关联、规则、模板、字段映射。这些说明系统为什么能提前提醒和自动生成草稿。
07

讲解话术

可以直接照着讲，语气按现场调整。

开场话术

“我们这版原型重点不是再做一个大而全的平台，而是在现有平台和项目一线之间加一个智能工作层。系统先把 WBS、风险源、日报目录、提醒规则、模板和字段映射配置好；一线人员日常主要看任务、确认日报、审核草稿和启动填报助手。”

解释为什么需要后台配置

“系统要提前提醒，前提是知道哪个 WBS 工序会触发哪个风险源；系统要生成草稿，前提是知道风险源要求哪些材料、模板需要哪些字段；系统要辅助填平台，前提是知道内部字段和平台字段怎么对应。所以后台配置是为了让一线少维护。”

解释人工确认边界

“日报解析、草稿生成、网页填报都不是直接自动提交。系统负责整理、提取、生成和辅助，关键节点都要人工确认。特别是外部平台账号、密码、验证码只在目标平台输入，系统不保存密码，不绕验证码，也不自动最终提交。”

收尾话术

“这条闭环跑通以后，项目部每天不用从多个文件和平台里反复复制粘贴，而是围绕任务中心处理：哪些风险快到了、哪些材料缺了、哪些日报要确认、哪些草稿要审核、哪些填报包要处理，都能在一个工作台里看到。”

08

用户常问问题

提前准备几个回答，避免现场被问散。
用户可能问建议回答
AI 解析日报错了怎么办？日报解析确认页可以人工修改日期、施工内容、进度、问题、风险内容和匹配 WBS，确认后才入库。
风险提醒怎么来的？后台先把 WBS 和风险源建立关联，再按风险等级配置提前提醒天数，系统根据计划开始时间生成任务。
每个风险要哪些材料在哪里配？风险源管理页维护材料要求，上报模板页维护缺项规则，任务和草稿里会显示缺哪些材料。
草稿是按什么格式生成？上报模板配置页定义章节、字段和来源，草稿生成后还要人工审核确认。
填报助手会不会替用户提交？不会。用户自行登录目标平台，系统只辅助录入和上传附件，保存草稿后停在最终提交前。
如果字段填不上怎么办？平台字段映射页维护字段对应关系；填报助手页会显示失败字段和失败原因，转人工处理。
现在是完整上线版本吗？当前是原型演示版本，重点验证流程、页面和业务闭环；真实 API、文件解析和平台自动化会在后续开发联调阶段落地。
讲解提醒：用户如果问“现在能不能真实解析文件、真实填平台”，回答要稳：当前演示的是原型闭环，真实解析和真实平台自动化属于后续联调与验收工作，不混在本次原型评审里判断。
