# 工程智管家 MVP 用户需求规格说明书

> 文档状态：开发前期基线
> 文档目的：将用户需求转化为可开发、可测试、可验收的需求规格。

---

## 1. 用户目标

项目部希望系统解决以下核心问题：

| 用户目标 | 说明 |
|---|---|
| 少填报 | 尽量从 WBS、风险清单、日报、照片、监测资料中提取信息，减少重复录入 |
| 早提醒 | 在风险源进入管控期前提前提醒，不等平台报警后再处理 |
| 任务到人 | 提醒和待办直接分派到具体责任人，而不是只按抽象角色推送 |
| 少维护 | 一线用户不每天维护复杂 WBS 和风险清单，只处理任务和确认结果 |
| 自动整理 | 自动读取微信群日报文件，提取进度、照片、问题和风险内容 |
| 人工确认 | 智能生成内容必须允许人工修改和确认 |
| 协助填平台 | 用户登录平台后，系统辅助填写字段和上传附件，但不自动提交 |

---

## 2. 用户角色

| 角色 | 主要诉求 | 主要操作 |
|---|---|---|
| 项目负责人 | 快速了解风险、逾期任务和待确认事项 | 查看总览、确认关键草稿、追踪逾期 |
| 项目执行人 | 快速处理现场任务并补充资料 | 查看任务、补充照片、确认进度、处理风险提醒 |
| 资料与填报负责人 | 减少整理材料和填平台工作量 | 审核日报解析、修改草稿、启动填报助手 |
| 实施管理员 | 初始化项目数据和规则 | 导入 WBS、导入风险源、配置关联、配置模板 |
| 系统管理员 | 维护用户、权限、日志和运行状态 | 配置账号、查看日志、处理异常 |

## 3. 核心业务场景

### 3.1 后台初始化 WBS 计划和风险源

用户目标：项目不希望一线人员每天维护复杂计划，但系统必须知道哪些工序会触发哪些风险。

需求：

- 系统支持导入 WBS 进度计划。
- 系统支持导入风险源清单。
- 系统支持建立 WBS 工序与风险源关联。
- 系统支持配置提醒规则和材料要求。
- 一线工地端用户不需要看到复杂初始化过程。

验收：

- 能导入真实 WBS 文件。
- 能导入真实风险源清单。
- 能人工建立并保存关联关系。
- 能展示关联依据、负责人、确认人和提前提醒天数。

### 3.2 根据 WBS 工序提前触发风险提醒

用户目标：项目人员希望在风险源进入前一周或两周收到提醒，提前准备材料和措施。

需求：

- 系统根据 WBS 工序计划开始时间、风险等级和提醒规则生成风险预警任务。
- 提醒必须转化为任务，而不是只发消息。
- 任务必须分派到具体责任人。
- 任务必须展示触发原因和所需材料。

验收：

- 系统能在计划开始前指定天数生成任务。
- 同一触发点不能重复生成多条无意义任务。
- 用户能查看、处理、补充材料、提交确认。

### 3.3 从微信群日报文件获取实际进展

用户目标：项目人员已经在微信群里发送日报文件，希望系统自动读取，不再人工查找和整理。

需求：

- 系统支持配置日报文件目录。
- 系统定时扫描目录并识别新增文件。
- 系统能判断文件是否已处理。
- 系统能记录处理成功、失败和异常原因。
- 系统能提取日报日期、施工内容、当前进度、照片、问题和风险相关内容。

验收：

- 新文件能被发现并处理。
- 同一文件不会重复处理。
- 解析结果能进入人工确认页面。
- 解析失败能进入异常记录。

### 3.4 用日报实际进展校验 WBS 工序状态

用户目标：WBS 反映计划，日报反映实际，系统应结合两者判断风险是否临近或已经发生。

需求：

- 系统将日报进展与 WBS 工序匹配。
- 匹配依据包括工序关键词、计划时间和历史进展。
- 匹配结果应区分高置信度、低置信度、无法匹配。
- 低置信度和无法匹配结果必须生成确认任务。

验收：

- 用户能看到日报内容匹配到哪个 WBS 工序。
- 用户能修改匹配结果。
- 确认后的实际进展能用于风险草稿生成。

### 3.5 生成风险进展上报草稿

用户目标：项目人员希望系统根据风险源、WBS、日报、照片和监测资料自动生成风险进展上报草稿。

需求：

- 系统支持为指定风险源生成上报草稿。
- 草稿应包含项目名称、风险名称、风险等级、关联工序、当前进展、监测情况、控制措施、现场照片说明、问题、后续措施、附件清单。
- 草稿应标明数据来源。
- 草稿应标明缺少材料。
- 草稿必须允许人工修改。
- 草稿确认后才能生成平台填报包。

验收：

- 草稿内容可读、可改、可确认。
- 缺项能被清楚标出。
- 确认前不能进入正式填报流程。

### 3.6 网页平台辅助录入

用户目标：用户自己输入账号密码登录平台后，系统帮助填写表单和上传附件。

需求：

- 系统打开目标平台地址。
- 用户自行输入账号、密码和验证码。
- 登录成功后，填报助手根据已确认填报包自动填写字段和上传附件。
- 自动录入前，用户能预览待填内容。
- 自动录入后，用户能检查页面内容。
- 系统保存草稿后停留在提交前。
- 最终提交由用户本人完成。

验收：

- 系统不保存平台账号密码。
- 系统不绕过验证码。
- 系统不自动最终提交。
- 字段或附件失败时能提示失败原因。

## 5. 非功能需求

| 类别 | 需求 |
|---|---|
| 安全 | 不保存平台密码，不绕过验证码，不自动最终提交 |
| 可追溯 | 解析、提醒、草稿、填报、确认都要留日志 |
| 可解释 | 风险提醒和草稿必须标明来源与触发原因 |
| 可确认 | 智能生成内容必须经过人工确认 |
| 可恢复 | 文件处理、草稿生成、填报失败后应可重试 |
| 可配置 | 提醒规则、日报目录、模板、字段映射可配置 |
| 易用性 | 工地端以任务中心为主，减少复杂菜单 |

## 6. 优先级定义

| 优先级 | 定义 |
|---|---|
| P0 | MVP 必须实现，不实现则主闭环无法验收 |
| P1 | 优先实现，用于提升自动化程度和使用体验 |
| P2 | 后续扩展，不进入 MVP 验收强约束 |

---

## 7. 需求验收边界

MVP 不以“全部自动化”为验收目标，而以“可确认、可追溯、可辅助、可减负”为验收目标。

任何自动解析、自动匹配、自动草稿和自动填报结果，都必须允许人工检查和修改。系统不得直接替用户做最终提交。
