## 1. 文档包定位

本目录用于沉淀工程智管家 MVP 开发前必须明确的系统设计资料，面向业务方、项目部、产品设计、架构设计、后端开发、前端开发和研发负责人。

本套文档不是汇报材料，也不是概念方案，而是进入开发前的基线资料。它要回答以下问题：

- 系统为什么做，解决哪些业务问题。
- MVP 做到什么边界，哪些暂不做。
- 用户、角色、任务和业务流程如何定义。
- 系统架构如何分层，外部系统如何协作。
- 初步数据库对象有哪些，核心字段是什么。
- 前后端接口按哪些业务模块拆分。
- 页面和交互如何组织。
- 开发任务如何拆解，里程碑如何安排。

## 5. 当前基线结论

工程智管家 MVP 的最小闭环为：

```text
WBS 风险底图
  -> 微信日报实际进展
  -> 风险预警任务
  -> 任务到人
  -> 风险进展草稿
  -> 人工审核确认
  -> 网页辅助填报
  -> 操作留痕追溯
```

开发应先跑通这条闭环，再扩展更多平台、更多项目、更多智能分析能力。

> 架构基线补充：系统按 A/B 双层落地——前端采用独立 Web 工程，推荐 Vue 3 + TypeScript + Vite + Element Plus；A 类确定性业务流用 FastAPI + PostgreSQL 直接实现；B 类智能工作流（日报解析、风险草稿生成、自然语言录入预留）用 LangGraph 受控编排，取其状态机、人在环暂停确认与断点续跑能力，大模型只在节点内做“文本到结构化”的填空，不自主决定流程。耗时解析与工作流统一经 Celery 执行（Beat 定时 + Worker 队列）；Hermes 保留为 LangGraph 按需调用的复杂子任务工具，不作为流程编排者。技术栈选用 PostgreSQL、Redis、Celery、MinIO。详见 `03_系统架构设计.md` 第 1.1、10 节与 `04_初步数据库设计.md` 第 1.1 节。
