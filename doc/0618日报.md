一、工程智管家前端整体架构重构

1、重新梳理工程智管家前端产品方向，明确当前版本不再沿用原 V1、V2 的传统后台页面结构，而是改为围绕人员协同、智能对话、任务跟踪和工程资料流转展开的智能工作平台。
2、将系统主菜单收敛为工作首页、智能协同、任务管理、项目状态、工程资料五个核心入口，移除原有分散的后台配置、工地端页面和 V1、V2 旧入口。
3、调整前端路由结构，将旧的 dashboard、risks、daily-reports、drafts、filling、admin 等路径统一重定向到新的五个核心页面，避免用户继续进入废弃页面。
4、统一顶部栏和左侧菜单的展示方式，顶部保留当前项目、搜索、通知等全局上下文，页面内部不再重复展示“当前项目”等冗余信息。
5、调整全局主题色、字体、按钮圆角和页面背景，使整体视觉从传统管理后台转向更现代的智能化工作台风格。

二、工作首页待处理工作队列重设计

1、重新定位工作首页，不再作为传统项目概览看板，而是作为当前登录人每天处理工作的主入口，优先展示需要当前人决策、上传资料、参与协同或跟进的事项。
2、将首页主体改为“待处理工作 / 快捷协同”双标签结构，默认进入待处理工作，用户可切换到快捷协同直接发起轻量对话。
3、优化待处理工作队列展示方式，支持按页面高度自适应分页，避免列表过长或页面底部留白过多，同时增加左右翻页按钮进行切换。
4、梳理首页筛选分类，将原“对话生成工作”调整为“需我协同”，筛选项统一为“全部、需我决策、需我上传资料、需我协同”，更符合使用者视角。
5、调整工作卡片信息结构，突出事项排序、处理原因、责任人、截止时间、标签和操作入口，减少无意义说明性文案。
6、移除左下角“今日待办”卡片，避免与首页主体待处理工作重复展示。

三、工作首页右侧协同信息面板优化

1、将首页右侧区域调整为待协同对象、建议处理顺序、协同动态三个信息面板，用于辅助当前人判断当天需要配合的人、优先处理顺序和系统同步动态。
2、将“今日协作人”“需要协作对象”等名称多次调整后最终确定为“待协同对象”，强调该区域展示的是当前任务中需要与当前人协作的对象，而不是所有参与人或用户本人。
3、修正待协同对象中出现当前用户本人的问题，改为只展示当前任务中需要与当前人配合的其他人员。
4、调整右侧面板高度和自适应布局，使右侧区域在页面高度内更完整地填充，不再出现局部悬空或视觉不对称的问题。
5、优化协同动态更新时间位置，将更新时间从容器外部调整到容器内部的合适位置，避免底部信息看起来像脱离面板。

四、快捷协同能力设计与首页内聊天支持

1、将快捷协同从简单跳转入口调整为首页内的轻量聊天能力，用户可直接在首页输入项目问题、资料需求或协同任务。
2、明确快捷协同与智能协同的关系：快捷协同没有完整会话列表和右侧监控面板，但对话内容会同步到智能协同中，后续可以在智能协同继续跟进。
3、调整快捷协同会话标题生成逻辑，将用户发送的第一句话作为会话标题，而不是使用“首页快捷”等固定标题。
4、在快捷协同未发送消息时增加居中的宽提示气泡，说明可用于查询资料缺口、拆解处理动作、发起多人协同和跟踪闭环结果。
5、反复压缩和调整提示文案，去掉过多教学式、标注式描述，使首页更像正式系统而不是功能说明页。

五、智能协同页面三栏布局重构

1、参考设计图重做智能协同页面，将页面重构为左侧会话列表、中间聊天主区域、右侧实时信息面板的三栏结构。
2、左侧会话列表支持置顶会话、今天、更早分组展示，并在会话卡片中展示标题、具体时间、摘要、参与人数和工作数量。
3、中间聊天区域重新设计标题、会话时间、消息气泡、输入区和会话生成工作展示，解决原页面标题过大、主次反转和内容拥挤的问题。
4、右侧实时信息面板展示当前会话已生成任务、参与人、资料缺项和处理动作，使对话过程中产生的工作能够被持续跟踪。
5、优化会话标题过长时的显示方式，超出容器后采用省略号处理，避免撑破布局。
6、将会话时间从“昨天”“周一”等相对时间改为具体日期时间，提升工程业务场景下的可追溯性。

六、智能协同聊天气泡与会话生成工作优化

1、优化用户消息和智能体消息气泡样式，调整头像、角色标识和气泡对齐方式，修复“我”字位置突兀的问题。
2、将原先独立统计式的“参与人、任务、完成度”信息移除，改为在聊天过程中直接体现由对话生成的工作，避免聊天界面出现无意义统计块。
3、将“已生成工作”从双列卡片改为一行一个的任务列表，每条展示工作标题、类型、责任人、截止时间、进度、状态和跟踪按钮。
4、修复会话生成工作卡片被旧样式撑高的问题，调整为稳定的单列紧凑布局，避免聊天区域出现异常长卡片。
5、右侧“已生成任务”与聊天中的“已生成工作”保持同步，用于从会话维度查看任务进展和责任人状态。

七、智能建议查看交互优化

1、取消聊天输入区下方固定展示的“调整优先级、补齐背景、拆解下一步、需要他人协助”等快捷项，避免用户误以为这些是固定功能按钮。
2、改为根据当前会话上下文动态提供建议，建议内容参考当前会话中的任务、资料缺项、参与人和逾期状态，点击后生成 2-4 条建议。
3、建议默认不展示，用户点击后才展开，避免占用聊天底部空间。
4、点击建议后只将建议内容填入输入框，不自动发送，防止误触发对话和任务生成。
5、将按钮名称从“生成建议”调整为“查看建议”，因为该功能更接近查看当前可用建议，而不是重新生成一个新对象。
6、将“查看建议”按钮与上传附件、提及人员、插入时间三个输入辅助按钮放在同一行，左侧为输入工具，右侧为查看建议，建议列表在工具栏上方展开。
7、补充 hover、active 和 focus-visible 状态，修复按钮点击后出现突兀焦点边框的问题，同时保留键盘可访问性。

八、任务管理、项目状态、工程资料页面统一调整

1、统一任务管理、项目状态、工程资料页面的页面标题、标签、按钮、卡片和列表样式，避免只有工作首页和智能协同完成新风格，其它页面仍停留在旧样式。
2、减少页面顶部重复标题和菜单名堆叠的问题，避免顶部栏已有当前菜单时页面内部再次强行塞入同名大标题。
3、优化任务管理页面筛选和任务列表展示方式，改善标题、筛选按钮、任务卡片挤在一起的问题。
4、工程资料页面去掉无意义统计堆叠，围绕资料流、缺项、日报、填报包和附件状态组织信息。
5、修正页面中的中英文混用问题，将 reviewing、pending 等状态文案改为中文表达，同时保留 WBS 等工程专业术语。
6、清理明显“AI 话术”和演示说明式文案，使界面表达更接近真实业务系统。

九、本地启动脚本和开发服务配置

1、将前端 Vite 开发服务端口从常见的 5173 调整为随机五位数端口 38429，降低端口冲突和默认模板感。
2、新增 start-frontend.bat 启动脚本，用于 Windows 环境下直接启动前端项目并自动打开本地页面。
3、修复 bat 脚本中文乱码问题，在脚本中加入 chcp 65001 设置，确保中文路径和提示信息正常显示。
4、启动脚本中增加 package.json 和 npm.cmd 检查，当前端目录或 Node 环境缺失时给出明确提示。
5、本地访问地址统一为 http://127.0.0.1:38429/。

十、构建验证与浏览器检查

1、多次执行 npm run build，确认前端 TypeScript 类型检查和 Vite 构建均可通过。
2、使用浏览器检查工作首页和智能协同页面，确认页面无横向溢出，三栏布局、右侧面板、聊天区域和输入区展示正常。
3、验证智能协同中会话生成工作由双列卡片改为单列列表后高度稳定，任务项展示不再异常拉伸。
4、验证“查看建议”默认不展示建议列表，点击后可展示 2-4 条建议，点击建议后可正确填入输入框且不会自动发送。
5、验证首页筛选项“需我协同”可正常显示，并同步替换原“对话生成工作”标签。
